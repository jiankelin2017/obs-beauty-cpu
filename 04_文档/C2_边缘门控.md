# C2 · Sobel 边缘门控（从 MIT 开源仓库落地）

> 2026-10-28 · 结论已实测，可复现

## 0. 结论

**加了边缘门控后，边缘处的磨皮量降到 83.6%，皮肤处 100.0% 不变，而总耗时反而降了 2%。**

| 指标 | 值 |
|---|---|
| 高梯度区（眉毛、眼睑、鼻翼）磨皮量 | 1.14（k=0 时 1.37）→ **83.6%** |
| 低梯度区（皮肤平坦处）磨皮量 | 0.98 → **100.0%（一点没变）** |
| 1080p 30fps 均摊 | **7.11 ms**（加门控前 7.25 ms） |
| k=0 时输出 | 与加门控前**逐字节相同**（三档分辨率哈希一致） |

## 1. 为什么要它

双边滤波靠「颜色差大 → 权重小」隐式保护边缘。这对**高频纹理**有效，
但对**同色系的硬边**（黑眉毛压在皮肤上、眼镜框边缘、发际线）保护不足 ——
它会把边缘磨成渐变，观感上就是「五官糊了」。

显式 Sobel 梯度门控把「真边缘」和「皮肤瑕疵」分开：前者梯度大，后者梯度小。

算法与思路来自 `wuxiwuhen/obs-beauty-filter`（**MIT**，已归档到
`09_开源参考/MIT_wuxiwuhen_beauty_filter.effect.txt`）：

```
atten = mask × (1 - edge) × strength
out   = low + high × (1 - atten)
```

我们只取其中的 `edge`，套用在自己已有的「掩码 + 线性混合」结构上：

```cpp
k = (ti · mask) >> 8;              // 原来的磨皮权重
k = (k · (256 - edge)) >> 8;       // edge=0 时与原值逐位相同
```

这样 `edge=0`（平坦皮肤）时行为与改造前**完全一致**，可以用哈希验证。

## 2. 三个踩过的坑（这是本文档的主要价值）

### 2.1 直接搬 ×10 灵敏度会让整体少磨一大截

原公式 `edge = saturate(|∇luma| × 10)`，作者用的是 luma 归一化到 0..1 的口径。
我按同样的比例搬到 0..255 的整数域，实测结果：

| k | 高梯度区磨皮量 | 低梯度区磨皮量 |
|---|---|---|
| 0 | 100% | **100%** |
| 10 | 96.8% | **86.2%** ← 皮肤也被门控了 |
| 40 | 94.4% | **94.4%** ← 等于基本不磨了 |

**低梯度区（皮肤）也被降了 14%，这就不叫门控了，叫整体减弱。**

### 2.2 原因：Sobel 标的是「边缘线」，不是「区域」

实测这张图的梯度分布（归一化 0..1）：

| 区域 | 中位数 | 90 分位 |
|---|---|---|
| 脸颊平坦处 | 0.020 | 0.082 |
| **眉毛横带** | **0.017** | 0.111 |

**眉毛横带的梯度中位数比脸颊还低** —— 因为那个矩形区域里大部分像素是眉间的皮肤，
只有眉毛本体是高梯度。所以「眉毛区域」整体看梯度很低，但「眉毛线条」梯度很高。

正确做法是**死区 + 斜坡**，不是线性放大：

```cpp
static const int kEdgeLo = 102;    // 低于此完全不门控
static const int kEdgeHi = 306;    // 高于此完全门控
```

改完之后低梯度区稳定在 100.0%，一点不动。

### 2.3 用 |Laplacian| 评价「边缘有没有被保护」会得到相反结论

第一版指标用「细节保留率」（mean |Laplacian| 比值），结果 k 越大读数越低，
看起来像「门控让画面更糊了」。真相是：

**磨皮在强边缘处产生振铃，把二阶导撑大了。** 全磨（k=0）时边缘区的
Laplacian 保留率是 **101.18%** —— 比原图还高。去掉振铃后读数回落到 100% 以下，
反而显得「磨得更多」。

换成直接测**磨皮幅度**（输出与原图的 RGB 平均绝对差）才得到正确结论：

| k | 高梯度区磨皮量 | 相对 k=0 | 低梯度区磨皮量 | 相对 k=0 |
|---|---|---|---|---|
| 0 | 1.37 | 100.0% | 0.98 | 100.0% |
| 5 | 1.31 | 95.3% | 0.98 | 100.0% |
| **10** | **1.14** | **83.6%** | **0.98** | **100.0%** |
| 20 | 0.87 | 63.3% | 0.98 | 100.0% |
| 40 | 0.67 | 48.9% | 0.98 | 100.0% |

> 教训：**换指标之前先确认这个指标不会因为被测量的手段本身而失真。**

## 3. 性能：加门控反而更快了

第一版实现 1080p 从 4.88 → 7.96 ms（+3.08 ms），太贵。两处优化后归零：

| 优化 | 做法 | 效果 |
|---|---|---|
| 亮度改用 G 通道 | 完整 luma 要 3 次乘加 × 8 邻居 = 24 次/像素；G 通道直接读 | 省 2/3 算术 |
| 混合改多线程 | `blendWithMask` 原本单线程遍历 200 万像素 | 2~3 ms → 接近 0 |

结果：

| 版本 | 1080p 纯磨皮帧 | 30fps 均摊 |
|---|---|---|
| opt4（无门控） | 4.88 ms | 7.25 ms |
| opt5（门控 + 单线程混合） | 7.96 ms | 10.34 ms |
| **opt6（门控 + G 通道 + 多线程混合）** | **4.60 ms** | **7.11 ms** |

阈值按 G 通道尺度重标（G 0..255，Sobel 系数和 4 → gx 上界 ±1020），
与原 luma 口径的 0.10 / 0.30 归一化等价。

## 4. 一条验证过、明确不可行的路

**用椭圆 mask 替代「肤色 ∩ 人脸框」—— 画质不达标，已放弃。**

动机来自 wtnl-zhi（明确写「不是像素级皮肤分割」）和 lumina：椭圆只要几个 float 参数，
当 uniform 传给 shader 就不需要下载整帧。系数也抄到了：
`radius_x = 脸宽 × 0.57`、`radius_y = 脸高 × 0.55`。

实测（`ellipse_vs_skin.py`，对现有掩码）：

| 场景 | 椭圆覆盖 | 现有掩码 | IoU | 精确率 | 召回率 |
|---|---|---|---|---|---|
| face_src | 11.91% | 6.91% | **0.562** | **0.568** | 0.980 |
| crop_a | 7.64% | 0.58% | 0.062 | 0.063 | 0.839 |
| crop_c | 22.00% | 2.01% | 0.075 | 0.076 | 0.830 |

召回率 0.98（几乎不漏），但精确率只有 0.57 —— **椭圆比实际皮肤胖了近一倍，
多出来的全是眼睛、眉毛、头发**。这会让五官变糊，属于降低画质。

wtnl-zhi 之所以能用椭圆，是因为它还叠了「保护眼睛、嘴部」的二次扣除，
而且他们的定位本来就是「快速近似」而非「精准分割」。我们现在的掩码 IoU 0.844，
退回 0.56 是明确的倒退。

**结论：椭圆只在「决定整体改走 GPU」时才值得重新评估**（那时换来的是去掉全帧往返，
性质不同）。纯 CPU 路线上没有收益。

## 6. 事实 vs 推测

**实测**：上表所有数字、三档 SHA256 一致性、梯度分布分位数、椭圆 IoU。

**未验证**：
- 观感层面「边缘保护到什么程度最合适」—— k=10 是按指标选的，
  真实人脸上是否还该更激进（k=15~20）需要肉眼看
- 只在 `face_src` 一张上做了分区统计，其它场景的梯度分布可能不同
- 眼镜框、刘海这两类「真边缘多」的场景没有专门素材
