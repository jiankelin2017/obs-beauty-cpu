> 【朝向口径更正 · 2026-10-30】
> 1. **两种格式方向相反**：抓取脚本里 `sizeOf()`（日志用）按 `r+"x"+rr` = 宽×高 记录；`readFBO`/`readTex`（bin 文件名用）按 `h+"x"+w` = 高×宽 记录。这是早期误读的根源。
> 2. **两次抓取朝向不同**：首测（pid 21084，见 `sb_capture5_raw.txt` 第 55 行 evidence JSON：`source_path:"gl_sb_capture4.js"`）日志 `540x960`、源 `1080x1920` = 竖屏——该判定已由抓取脚本 `gl_sb_capture4.js` 的 `sizeOf()`（第 25-38 行，`glGetTexLevelParameteriv` 查 `GL_TEXTURE_WIDTH(0x1000)`/`GL_TEXTURE_HEIGHT(0x1001)`、输出 `r+"x"+rr` = **宽×高**）**脚本级坐实，非推断**；本次像素回读（pid 5360）bin 文件名 `360x640`、`720x1280` = 高×宽（来自 `gl_texture_dump.js` v1 的 `readFBO/readTex`，`h+"x"+w`），即横屏 `640×360`、`1280×720`（相邻行相关系数 + 肉眼还原双重确认）。两种格式方向相反，是早期误读根源。
> 3. **核各向异性随缓冲朝向变化**：方向表按横屏参考 `1136×640` 固定生成（`sx=3/1136`、`sy=3/640`、`sy/sx=1.775`），像素步长 = UV 步长 × 缓冲维度，各向异性比 = `1.775×(H/W)`。竖屏缓冲 540×960 → `sx·540=1.426` / `sy·960=4.500` → **3.16× 竖椭圆**（首测值，计算无误）；横屏缓冲 640×360 → `sx·640=1.690` / `sy·360=1.6875` → **0.998 正圆**（本次值，字节流实证）。`beauty.exe` PID 5360 抓回的 bin 与 OBS 日志（base 1920×1080、摄像头 1280×720）均为横屏，圆核匹配、竖屏 bug 不触发；若实际做竖屏直播，垂直半径需按 `ry = rx×1.775×H/W` 校正（本次 bin 与"当前工程 360×640"口径不符，竖屏实测数据待补，不断言）。

> 【第三方 IPC 参数通道 · 2026-10-30 02:30 只读实测】
> 1. **参数通道不是管道，是共享内存**：`\\.\pipe\BEAUTY_BRIDGE_PIPE<pid>`（1024 B 定长帧）只跑文本控制帧 `module version=%s` / `Init Result = %s`；参数在 2 MB 命名共享内存节 `BEAUTY_SETTING_<uuid>` 里，另有 `DATA_PIPE_<uuid>`（2 MB）存授权/登录态/渲染状态。`OpenFileMappingW(FILE_MAP_READ)` 可直接只读打开两节，无需注入。
> 2. **格式性质 = 零拷贝共享对象图，不是序列化字节流**【实测】：块内以**绝对指针**互链，规范基址 `BEAUTY_SETTING` = `0x1dc5db30000`、`DATA_PIPE` = `0x1dc63f00000`（本进程映射基址不同，故必须按"基址+偏移"解释）。无 protobuf / JSON / msgpack / FlatBuffers 特征。记录框架：`[u64 长度 0x70/0x81/0x90…][name ASCIIZ 按 8 字节对齐][u64 类型标记=1][u64 值][0x38 描述符{0x90,1,0x1990,下一记录偏移,2,字段尺寸,0x10,0x10}]`；值只有 **u64 整数**与**内联 ASCIIZ 字符串**两种，**全块无浮点**（double/float 100.0、55.0 均 0 命中）。
> 3. **参数 schema 共 64 项，无 `blur_type`**【实测，2 MB 全块 0 命中】：相机组 11（含 `skin_dect_en`）、磨皮/滤镜组 18（`heavy_blur`、`balance_smooth`、`blur_level`、`color_level_type`、`color_level`、`clarity`、`delspot_level`、`red_level`、`sharpen`…）、脸型五官组 21、美妆美体组 14。**`skin_detect` 亦 0 命中**（只有 `skin_dect_en`），`blur_times`/`face_shape`/`filter_level` 同样 0 命中。这些名字只存在于 beauty.exe 的 `.rdata` 参数名表（内存扫描 26 命中）→ **"SDK 可设置项" ≠ "产品实际下发项"**。

| UI 壳 | `obs-cam-beauty_qt6.dll`（在 obs64 内，3.79 MB） | 只导出标准 `obs_module_*` 壳函数；持有高层 UI 参数键；经 `BEAUTY_BRIDGE_PIPE` IPC 通信 | 仅 9 个导出；串搜索见 `BEAUTY_BRIDGE_PIPE`、`BEAUTY_SETTING_`、`blur_level`/`cheek_thinning`/`eye_enlarging` |

| 资源 | `common/assets/{graphics,items,model}/*.bundle` | 加密的美颜资源（含 GLSL） | 解密后堆内存即 bundle 明文 |

**数据流**

```
UI 滑块 (obs-cam-beauty_qt6.dll)
   ↓ IPC：BEAUTY_BRIDGE_PIPE（命名管道，高层键 → 引擎键）
引擎宿主 beauty.exe + CNamaSDK.dll
   ↓ fuItemSetParamd(itemHandle, key, value)（每帧重发）
AI 人脸检测 (fuai.dll) ──→ 关键点 ──→ 掩膜 tex_mask
   ↓
```

# 二、磨皮两级管线

## 2.1 档位映射【实测，精确成立】

```
面板 t (0–100)
  └─ OBS 层恒等透传，不做 ÷100
  └─ SDK 内部 ÷100 → blur_amount ∈ [0,1]
  └─ blur_intensity = 0.75 × blur_amount
```

`blur_amount_s_clear_blur_mix < 0.001` 时直接返回原图。

## 2.2 第一级：边缘感知预模糊【源码】

```glsl
void main() {
  lowp vec4 origin_color = texture2D(tex_origin, st);
  lowp vec4 mask_color   = texture2D(tex_mask, st);
  lowp vec4 ret_color    = origin_color;
  if (mask_color.a > 0.001) {                           // 仅在皮肤区域处理
    lowp vec4 blur_color = texture2D(tex_pre_blur, st); // 预模糊图（低频）
    blur_color.a = origin_color.a;
    // dis = 模糊图与原图的色彩差，乘以 30 作为边缘强度度量
    float dis = distance(vec3(0.0),
                    max(blur_color.rgb - origin_color.rgb, 0.0)) * 30.0;
    float factor = 1.0;
    factor = step(0.5, dis);                            // dis<0.5（平坦皮肤）：不磨
    factor = (1.0 - smoothstep(5.0, 6.0, dis)) * factor; // dis>6（五官强边缘）：不磨
    if (dis > 0.5 && dis < 5.0) {                       // 仅中频区（毛孔/细纹）磨平
      ret_color = shader_main_s_pre_enlighten(
          origin_color, factor * blur_intensity * mask_color.a * 0.25);
    }
  }
  gl_FragColor = ret_color;
}
```

**`dis` 带通表**（`dis = |blur − origin| × 30`）

| `dis` 区间 | 含义 | 处理 |
|---|---|---|
| < 0.5 | 平坦皮肤 | **不磨**（防塑料感 / 噪点放大） |
| 0.5 ~ 6.0 | 中频（毛孔 / 细纹） | **磨** |
| > 6.0 | 五官强边缘 | **不磨**（保边） |

> ⚠️ **别把这一级实现成"全图预模糊 + LUT"**。LUT 确实在 `pre_enlighten` 里面，但它的**入口被 `dis` 带通门控包着，且混合系数带 `0.25`**。丢掉门控会导致平坦区被磨（出塑料感）、强边缘被糊。

## 2.3 预提亮（被 2.2 调用，3D-LUT）【源码】

```glsl
lowp vec4 shader_main_s_pre_enlighten(lowp vec4 C, lowp float blend_factor) {
  lowp vec4 textureColor = C;
  float blueColor = textureColor.b * (dim_s_pre_enlighten - 1.0);
  float r_raw = 1.0 / raw_s_pre_enlighten;
  float r_col = 1.0 / col_s_pre_enlighten;
  vec2 quad1;
  quad1.y = floor(floor(blueColor) / raw_s_pre_enlighten);
  quad1.x = floor(blueColor) - (quad1.y * col_s_pre_enlighten);
  vec2 quad2;
  quad2.y = floor(ceil(blueColor) / raw_s_pre_enlighten);
  quad2.x = ceil(blueColor) - (quad2.y * col_s_pre_enlighten);
  vec2 texPos1;
  texPos1.x = (quad1.x * r_col) + 0.5/(col_s_pre_enlighten * dim_s_pre_enlighten)
            + ((r_col - 1.0/(col_s_pre_enlighten * dim_s_pre_enlighten)) * textureColor.r);
  texPos1.y = (quad1.y * r_raw) + 0.5/(raw_s_pre_enlighten * dim_s_pre_enlighten)
            + ((r_raw - 1.0/(raw_s_pre_enlighten * dim_s_pre_enlighten)) * textureColor.g);
  vec2 texPos2;
  texPos2.x = (quad2.x * r_col) + 0.5/(col_s_pre_enlighten * dim_s_pre_enlighten)
            + ((r_col - 1.0/(col_s_pre_enlighten * dim_s_pre_enlighten)) * textureColor.r);
  texPos2.y = (quad2.y * r_raw) + 0.5/(raw_s_pre_enlighten * dim_s_pre_enlighten)
            + ((r_raw - 1.0/(raw_s_pre_enlighten * dim_s_pre_enlighten)) * textureColor.g);
  lowp vec4 newColor1 = texture2D(tex_enlighten, texPos1);
  lowp vec4 newColor2 = texture2D(tex_enlighten, texPos2);
  lowp vec4 newColor = mix(newColor1, newColor2, fract(blueColor));
  return newColor = vec4(
             mix(textureColor, vec4(newColor.rgb, textureColor.w), blend_factor).rgb,
             C.a);
}
```

**LUT 网格**：`dim = 64, raw = 8, col = 8` → 一张 **512×512** 纹理，64³ 三维查找表摊平。`blueColor = b × 63`，`quad.y = floor(floor(blueColor)/8)`，`quad.x = floor(blueColor) − quad.y×8`。
**LUT 内容未取到**，只影响颜色/通透感，**不影响磨皮几何**。

## 2.4 第二级：双表面模糊（磨皮主体）【源码】

```glsl
vec4 shader_main_s_surfaceblur_mix(vec2 st, vec4 C) {
  if (blur_amount_s_clear_blur_mix < 0.001) {
    return C;                                            // 强度≈0 直接返回原图
  } else {
    lowp vec3 blur1 = texture2D(tex_surfaceblur1, st).rgb; // 表面模糊层1（低频）
    lowp vec3 blur2 = texture2D(tex_surfaceblur2, st).rgb; // 表面模糊层2（低频）
    lowp vec4 mask  = texture2D(tex_mask, st);
    lowp float eye_mask = 0.0;
    if (mask.g > 0.0 && mask.r <= 0.1 && mask.b <= 0.1) { // 绿色通道=眼睛/五官
      eye_mask = mask.g;
    }
    lowp float skin_mask = mask.a;                         // alpha=皮肤区域

    lowp float intensity = blur_amount_s_clear_blur_mix;

#ifdef USE_SKIN_DETECT                                   // 可选：肤色检测
    if (skin_detect_s_clear_blur_mix > 0.5) {
      lowp float r = C.r, g = C.g, b = C.b;
      if (r > 0.371 && g > 0.156 && b > 0.078 && r > b && r > g &&
          abs(r - g) > 0.059 &&
          (max(max(r,g),b) - min(min(r,g),b) > 0.059)) {
        // 判定为皮肤：保持强度
      } else {
        intensity = nonskin_blur_scale_s_clear_blur_mix * intensity; // 非皮肤：衰减
      }
    }
#endif

    intensity = mix(intensity * 1.4286, 1.0, step(0.7, intensity));
    lowp float evenfactor = mix(0.3, intensity - 0.3, step(0.6, intensity));
    lowp vec4 result_color = C;
    lowp vec3 diff = (C.rgb - blur1) * 0.5 + 0.5;          // 高频（细节）层
    lowp vec3 even = clamp(2.0 * diff + blur2 - 1.0, vec3(0.0), vec3(1.0));
    even = mix(C.rgb, even, skin_mask);                    // ← ① 仅在皮肤内混合
    even = mix(even, blur2, skin_mask * evenfactor);       // ← ② 拉向 blur2
    lowp vec3 res = mix(C.rgb, even, intensity);
    result_color = vec4(mix(C.rgb, res, (1.0 - eye_mask)), C.a); // 眼睛完全不模糊

#ifdef USE_SHARPEN                                        // 可选：高通锐化补偿
    vec4 st_offset1 =
        vec4(widthOffset_s_clear_blur_mix, heightOffset_s_clear_blur_mix,
             -widthOffset_s_clear_blur_mix, -heightOffset_s_clear_blur_mix) * 0.5
        + vec4(st, st);
    vec4 st_offset2 =
        vec4(-widthOffset_s_clear_blur_mix, heightOffset_s_clear_blur_mix,
             widthOffset_s_clear_blur_mix, -heightOffset_s_clear_blur_mix) * 0.5
        + vec4(st, st);
    lowp float sum = texture2D(tex, st_offset1.xy).g;
    sum += texture2D(tex, st_offset1.zw).g;
    sum += texture2D(tex, st_offset2.xy).g;
    sum += texture2D(tex, st_offset2.zw).g;
    sum = 0.25 * sum;
    lowp float highPass = C.g - sum + 0.5;
    lowp float flag = step(0.5, highPass);
    lowp vec3 hv = (2.0 * highPass + result_color.rgb - 1.0);
    lowp vec3 color = mix(max(vec3(0.0), hv), min(vec3(1.0), hv), flag);
    result_color.rgb = mix(result_color.rgb, color.rgb, sharpen_s_clear_blur_mix);
#endif
    result_color.a = C.a;
    return result_color;
  }
}
```

> **① 和 ② 的顺序是确定的**，不要怀疑：`even = mix(C, even, skin)` 在前，`even = mix(even, blur2, skin·evenfactor)` 在后。
> 旧交接文档曾把这条列为"位置待确认的阻塞项"，是**抄漏了 ① 这一行**导致的误判。

## 2.5 频率分解公式（核心思想）【源码】

| 层 | 公式 | 含义 |
|---|---|---|
| 低频（模糊图） | `blur1` / `blur2` | 肤色是否均匀 |
| 高频（细节） | `diff = (C.rgb − blur1) × 0.5 + 0.5` | 毛孔 / 细纹 / 质感 |
| 合成 | `even = clamp(2·diff + blur2 − 1, 0, 1)` | 低频底 + 高频叠回 → **磨皮但保留质感** |

代数上 `clamp(2·diff + blur2 − 1) = clamp(C − blur1 + blur2)`。

## 2.6 强度重映射与 evenfactor【源码】

```glsl
intensity  = mix(intensity * 1.4286, 1.0, step(0.7, intensity));
lowp float evenfactor = mix(0.3, intensity - 0.3, step(0.6, intensity));
```

注意第二行的 `intensity` 是**第一行重映射之后**的值。

| 原始 `I` | `I₁` | `evenfactor` |
|---|---|---|
| `I < 0.42` | `1.4286·I < 0.6` | **0.3**（常数） |
| `0.42 ≤ I < 0.7` | `[0.6, 1.0)` | **1.4286·I − 0.3** |
| `I ≥ 0.7` | `1.0` | **0.7**（常数） |

**关键推论**：`I ≥ 0.7` 之后 `I₁` 和 `evenfactor` 都不再变化 → **第二级在 70 档以上完全饱和**。75→100 的差异**全部来自第一级预模糊**（`blur_intensity` 0.5625 → 0.75）。

# 三、表面模糊核（prog 67）

## 3.1 同一核串行两趟，不是两种模糊【实测】

| | blur1 | blur2 |
|---|---|---|
| 趟次 | pass 1 | pass 2 |
| 输入 | 原图 | **blur1 本身** |
| `yFactor` | 40 | 20 |
| 色差容限 | 0.1581 | 0.2236 |
| 输出 | 540×960 | 540×960 |

## 3.2 权重数学式

```
Δgk = Ck.g − C0.g
wk  = 1 − min(Δgk² · yFactor, 1)        ∈ [0,1]
out = (Σ wk·Ck + C0) / (Σ wk + 1)
```

**必须照抄的四个细节**

1. **空间权重恒为 1** —— 盒式核，**不是高斯**
2. **值域权重是二次抛物线截断** —— 不是指数，不是 L1
3. **只测绿通道** —— 不是亮度，不是 HSV 的 V
4. **25 tap** —— 8 方向 × 3 环（`lens = 1, 2, 5`，比例 1:2:5）+ 1 个中心点

> ⚠️ **来源存疑**：`07_历史文档\master_analysis.md §3.5` 明确写 `clear_blur` / `blur_h_fs` / `blur_v_fs` 的**逐行 GLSL 源码体在已解密堆文本中未干净捕获**（仅拿到文件名清单），那节是「参数级结论 + 算法重建」。上表的数字若来自动态反推而非逐字源码，实现时需留拟合余量。**这条待澄清。**

## 3.3 采样几何【实测】

UV 空间半轴固定：`sx = 0.002640845`、`sy = 0.0046875`（比值 **1.775**）。

像素步长随处理分辨率变化：

| 输入 | 处理分辨率 | 环1 | 环2 | 环3 | 形状 |
|---|---|---|---|---|---|
| 1920×1080（横屏） | 960×540 | 2.53 / 2.53 | 5.07 / 5.07 | 12.67 / 12.67 | **圆** |
| 1080×1920（竖屏） | 540×960 | 1.43 / 4.50 | 2.85 / 9.00 | 7.13 / 22.50 | **椭圆 3.16:1** |

**结论**：核按 `1136×640` 参考分辨率生成，**没有随画幅自适应**。横屏下是圆核，竖屏下竖向拉长 3.16 倍。
上采样回 1080p 后，竖屏最大环步长为 **14.26 / 45.0 px**。

## 3.4 生成链与固定参数【实测】

- 先由 `blur_h_fs.glsl`（横）+ `blur_v_fs.glsl`（纵）做分离模糊打底；
- 再由 `clear_blur.glsl`（表面模糊）现场生成两级产物：
  - `tex_surfaceblur1`（轻）→ 用于提取高频 `diff = (C − blur1) × 0.5 + 0.5`
  - `tex_surfaceblur2`（重）→ 作为低频底参与合成

| 参数 | 值 | 含义 |
|---|---|---|
| `blur_size` | **4.0** | 模糊半径（采样窗口） |
| `blur_times` | **2** | 迭代次数（同窗口重复平均 2 遍） |

> `blur_size = 4.0` 属 `tex_pre_blur` 链路，与 25-tap 核**无关**【推断】。

# 四、`blur_type`：三档算法【实测】

磨皮**不是一条管线**，而是三种算法可选。**注意：第三方面板上并没有这个下拉框**（那是我们自己插件 `obs-beauty.cpp:577` 加的），产品**从不下发** `blur_type`，只用 bundle 内建默认。

| `blur_type` | 算法 | 细节能量（越小越平滑） | 保留率（磨皮=50） | |
|---|---|---|---|---|
| **1** | **双边滤波** | **2.358（最强）** | 72.0% | ❌ **不是产品默认**（三路证据）：产品从不下发 `blur_type`，生效档 = bundle 裸默认 = **bt2**。此档只是 SDK 回退路径的代码默认（`nama_engine.h:156`），**生产默认的 CoreEngine 根本不读 `blur_type`** |
| 0 | 高斯 | 2.719（中等） | 84.6% | |
| 2 | 弱磨皮 | 3.762（较弱） | 94.5% | ✅ **= 产品实际生效档**（bundle 裸默认，离线逐字节 md5 `2e0943ab620f20cf` + 动态零下发双重坐实） |
| 3 | — | 4.180（≈没磨） | — | 已从列表移除 |
| 4 | — | 与高斯**逐字节相同** | — | 已从列表移除 |
| — | 完全不磨 | 4.184 | 100% | 基准 |

**它极可能是第一级 `tex_pre_blur` 的生成算法选择器**【推断，证据强】：
`dis = |blur − origin| × 30`，而 `factor = step(0.5, dis)`。若 `blur_type=3` 让 pre_blur 等于原图 → `dis = 0` → `factor = 0` → **整级不磨**。这与"3 ≈ 等于没磨"完全吻合。

**旁证**：`goldens_legacy/flat/blur100_bt1/out.raw` 被当作平滑核真值扫参，结果**前 10 名全是双边滤波**，`d=9 σc=40` 曲线 RMSE **1.16 个百分点**，引导滤波最好只有 2.20。`bt1` 就是 `blur_type=1`。

> 面板默认是双边，所以**真机对拍时 SDK 跑的是「双边预模糊 + 表面模糊」**，任何只实现第二级的方案都少一条腿。

# 五、掩码与保护

## 5.1 `tex_mask` 通道约定【源码】

| 通道 | 含义 | 作用 |
|---|---|---|
| `.a` (alpha) | **皮肤区域掩码** | 磨皮仅在皮肤内生效（`skin_mask`） |
| `.g` (green) | **眼睛 / 五官区域** | 磨皮时被保护（`eye_mask`，`mix(C, res, 1−eye_mask)` → 眼睛完全不模糊） |
| `.r` (red) | 非肤检测 | `mask.r <= 0.1 && mask.b <= 0.1` 用于判定眼区 |
| `.b` (blue) | 皮肤（美白用） | 美白模块使用 |

## 5.2 肤色判定硬阈值【源码】

```
r > 0.371 && g > 0.156 && b > 0.078
&& r > b && r > g
&& |r − g| > 0.059
&& (max(r,g,b) − min(r,g,b)) > 0.059
```

满足 → 判定为皮肤，保持磨皮强度；否则 `intensity *= nonskin_blur_scale`。

**`nonskin_blur_scale = 0`** → 非肤区域**一点都不磨**，输出原图，没有渐变带。

## 5.3 眼保护：只有 eye，没有 mouth【源码】

```
out = C + (res − C) · (1 − eye)
```

**SDK 没有嘴巴保护** —— 嘴唇被当皮肤磨。任何实现里多加的"嘴巴椭圆"都是**多做的**，会与 SDK 产生系统性偏差（实测 100 档唇区残差 +25.5）。

## 5.4 管线中间产物

**① 掩码**：`tex_mask`（多通道，见 5.1）、`tex_skin`、`tex_eye_mask`、`tex_mouthoccu` / `tex_face_occu_blur`、`tex_segmentation` / `tex_bg` / `tex_background` / `tex_back_blur`（背景虚化）

**② 关键点**（AI 人脸追踪输出，传形变着色器）
- 轮廓：`p_nose`、`p_chin`、`p_chinleft`、`p_chinright`、`p_chinleft_u`、`p_chinright_u`
- 变换/索引：`p_origin`、`p_rot`、`p_flip`、`p_inv`、`p_faceright`、`p_5`、`p_6`、`p_8`、`p_C`、`p_T`、`p_f`、`p_type`

**③ 保护掩码**：`eye_mask`（由 `.g`，完全不磨）、`skin_mask`（由 `.a`，限域）、非肤衰减（`USE_SKIN_DETECT` + `nonskin_blur_scale`）

**④ 高低频层**
- 低频（拿去磨平）：`tex_surfaceblur1`/`blur1`、`tex_surfaceblur2`/`blur2`、`tex_pre_blur`
- 高频（要保留）：`diff = (C − blur1) × 0.5 + 0.5`
- 合成：`even = clamp(2·diff + blur2 − 1, 0, 1)`
- 基准：`tex_origin`

# 六、参数全表

| 参数名 | 含义 | 控制阶段 | 备注 |
|---|---|---|---|
| `blur_intensity` | 磨皮强度 | 第一级边缘感知模糊 | 与 `mask.a`、`0.25` 系数共同决定混合量；`= 0.75 × blur_amount` |
| `blur_amount_s_clear_blur_mix` | 表面模糊混合量 | 第二级（**主驱动**） | `< 0.001` 时直接返回原图 |
| `blur_type` | **磨皮算法选择** | 第一级预模糊生成 | 1=双边（默认）/ 0=高斯 / 2=弱磨皮；3、4 已废弃 |
| `blur_level` | 磨皮混合系数 | 另一条 pass | `clamp(blur_level, 0, 1)`，线性 `mix` |
| `blur_fs` / `blur_h_fs` / `blur_v_fs` | 模糊滤波器尺寸（含横/纵） | 模糊核生成 | 控制模糊半径 |

## 六·补.1 三项都是纯颜色变换（箱内 σ 判据）

按输入灰阶分箱统计输出，「箱内 σ」= 同一输入值映射到输出的离散度。
σ ≪ 1 灰阶 ⇒ 与空间位置、邻域无关 ⇒ 是逐像素颜色变换。

| 参数 | 档位 | 箱内 σ（掩码内） | 样式（输入 → 输出） |
|---|---|---|---|
| `clarity` | 0.25 / 0.5 / 0.75 / 1.0 | **0.08 / 0.15 / 0.21 / 0.27** | S 形对比：96→95/94/93/92、160→162/165/167/170、200→203/205/208/210 |
| `color_level` | 0.25 / 0.5 / 0.75 / 1.0 | 0.36 / 0.65 / 0.95 / 1.24 | 提亮：96→99/102/105/108、160→164/167/171/174、200→203/205/208/210 |
| `red_level` | 1.0 | 0.73 | **只压 G**：32→−4、96→−5、160→−3、224→0；R 不动，B +1~2 |

**结论（与旧记录的差异）**：
- 「清晰」在 SDK 里**不是**局部对比/中频增益，是 S 形对比曲线 + 轻微暖调。
  与 `01` 旧记录里"sharpen_*/color_level_* [0,1]"的取值范围一致。
- 「红润」不是加红，是**压绿**（提高 R−G 差值）。`red_level` 实测 3 帧均值：
  ΔR−G = +0.98/+2.18/+3.50/+4.75（0.25/0.5/0.75/1.0），Δ亮度 = −0.59/−1.19/−1.78/−2.35。
- 「美白」在 1.0 档的肤色区 Δ亮度 **+13.3**（整帧覆盖 92%，其内部 `skin_mask`
  覆盖范围远大于人脸），不是"只提脸"。

## 六·补.3 五官三项的**细结构**真值（2026-10-30 深夜实测，8 帧）

上表是「支撑集」层面的真值。下面是**逐行剖面**测出来的细结构 —— 这是把
我们自己的模型从 30 分推到 80 分的关键依据。

### 3.1 去法令纹：响应有**两个瓣**

沿「眼正下方竖线」扫描（`_naso_line.py`，m00 眼R 侧，dy = 眼下方多少脸高）：

| dy | 参照 Δ | 只做「上瓣」时我方 Δ |
|---|---|---|
| 0.13 | 11.7 | 23.9 |
| 0.15 | 18.3 | 60.0（封顶，过冲） |
| **0.17** | **48.0（峰）** | 60.0（封顶） |
| 0.19 | 5.2 | 14.0 |
| 0.23 | 6.7 | 3.8 |
| 0.25 | 8.0 | 0 |
| **0.31** | **12.0（次瓣峰）** | 0 |
| 0.45 | 0.7 | 0 |

**上瓣** = 真正的褶皱线：窄（5~8 px）、强（峰 48~52，恒定封顶），
位置恒在「眼正下方 0.16~0.20 脸高」。
**下瓣** = 褶皱朝嘴角延伸的那一段：宽、弱（3~12 灰阶），
范围 dy 0.25~0.45，**与亮度无关**（那儿并不暗）。

⇒ 上瓣可用「暗度驱动」（Δ ∝ 邻域最大亮度 − 当前亮度）表达；
**下瓣必须用常量增益**（和五官立体同一套原语）。

### 3.2 参照 Δ 的方差集中在极小的支撑集上

`_naso_spec.py`，m00 脸框掩码内 291,780 像素：

| 分位 | p50 | p75 | p95 | p99 | p99.5 | p99.9 | max |
|---|---|---|---|---|---|---|---|
| Δ | 0.00 | 0.00 | 1.89 | 6.20 | 8.47 | 36.0 | 51.0 |

| top 占比 | 0.1% | 0.5% | 1% | 2% | 5% |
|---|---|---|---|---|---|
| 方差贡献 | **52.5%** | 78.2% | 84.3% | 90.8% | 96.8% |

⇒ 292 个像素（0.1%）就占了一半方差 —— 参照的响应确实是**窄线尖峰主导**，
不是宽场。这否定了「宽场提亮」路线的正确性。

### 3.3 去黑眼圈：响应是**斜向窄脊**，且两侧强度差很大

`_pouch_map.py`：m00 眼R 的响应从 (x=0.66, y=0.43) 斜向右下到
(x=0.74, y=0.50)，宽约 12 px、长约 62 px、方向约 **41°**（水平方向偏下），
**不是**水平椭圆带。

两侧强度差（`_pouch_prof.py`）：

| 帧 | 眼R 侧峰 | 眼L 侧峰 |
|---|---|---|
| m00 | 12.8 | 2.6 |
| m03 | 17.7 | 2.4 |

⇒ 用 **yaw 透视缩短修正**（`rx *= 1 − yawK·yaw·side`）能表达大部分；
额外加「分侧增益」参数反而**无益**（扫参验证：gainL/gainR 偏离 1.0 一律降分）。

### 3.4 **引擎自身的两个缺陷**（不是参照的问题）

**① 皮肤软掩码在褶皱处是假阴性**

皮肤掩码是 YCbCr 肤色椭圆，褶皱越深越暗就越「不像肤色」→ 掩码越低。
实测 `corr(皮肤掩码, 参照Δ) = **−0.66**`（法令纹区域）——
引擎恰好在**最该提亮的那条线上**把效果掐掉。

修法：限制因子从「乘皮肤掩码」改成 **`max(皮肤掩码, 区域权重)`**
——只有区域核心旁路肤色判断，区域外仍由肤色把关，不会溢到头发/背景。

**② 负增益的像素写回整体偏移一档**（`beauty_region.cpp`）

```cpp
// 旧（错）：(int) 是截断不是 floor，负增益被多算一档
const int nv = (int)(p[c] + acc + (acc >= 0.0f ? 0.5f : -0.5f));
// 修：lroundf 对正负都对
const int nv = (int)lroundf((float)p[c] + acc);
```

acc = −0.4 时旧代码实际减 1（而不是 0.4）——**所有压暗类效果多暗一档**。
修完后模拟器与引擎逐像素 corr 0.9949 → **0.9999**，五官立体 +4.4 分。

### 3.5 两项局部效果的 corr 上界（为什么到不了 70）

评分口径：`40·min(chg/chg_sdk, chg_sdk/chg) + 35·corr + 25·max(0, 1−rmse/(2·max(chg,chg_sdk)))`。

局部效果的 `chg_sdk` 只有 0.17（黑眼圈）/ 0.33（法令纹），
所以第三项的分母 `2·max(chg,chg_sdk)` 只有 0.34 / 0.66，
而真实 rmse 是 0.72~2.4 —— **第三项（25 分）结构性不可达**。
**要拿 70 分，corr 必须 ≥ 0.86。**

用 oracle 分解测出的模型类上限（8 帧，`_pouch_decomp.py` / `_naso_decomp2.py`）：

| 项 | 当前 | 位置全对（oracle 形状） | 幅度全对（oracle 幅度） |
|---|---|---|---|
| 去黑眼圈 | 0.722 | 0.787 | 0.818 |
| 去法令纹 | 0.763 | 0.811 | 0.869 |

⇒ **「椭圆 + 常量增益」这一模型类最多到 corr 0.79~0.82**，
换句话说 **用 5 个关键点（双眼/鼻/嘴）无法复刻 3D 网格驱动的响应**。
要再往上走只有两条路：
① 引入人脸网格（做位移场/逐像素对齐）
② 把幅度改成内容自适应（混合模型，实测 +0.9，引擎需新增原语）

# 十二、一句话收口

磨皮是「**双级边缘感知 + 频率分解 + 掩膜限域**」：第一级只磨中频（`dis∈(0.5,6.0)`）保五官边缘，第二级用 `even = 2·diff + blur2 − 1` 把毛孔细节加回低频底、做到「磨平不丢质感」，并用 `mask.a` 限皮肤、`mask.g` 保眼睛。滑块是裸 0–100 直送 SDK，÷100 由 SDK 内部完成；表面模糊是同一核串行两趟（`yFactor` 40→20），核按 1136×640 生成、不随画幅自适应。第一级预模糊的算法由 `blur_type` 选择——**但产品实测从不下发这个参数**（2026-10-30 三路证据结案），生效档 = bundle 裸默认 **bt2**，见 §0.3b/§0.3c。

# 十三、档位强度曲线的真值（2026-10-30 03:40，实测）

**口径**：8 帧真机原始帧（1920×1080，脸宽 529 px）、加密 bundle + `blur_type=-1`、离线同进程、掩码内平均 |Δ|（官方 `change_in`）；flat/tex 用**本项目基准口径**「5×5 局部标准差」（`flat: σ<2` 占脸 56.6%、`tex: σ>6` 占 12.1%）。

|---|---|---|---|---|
| 0 | 0.000 | 0.000 | 0.000 | — |
| 25 | **0.010** | 0.006 | 0.013 | 0.51 |
| 50 | **0.403** | 0.422 | 0.333 | **1.27** |
| 75 | **1.121** | 1.188 | 0.863 | **1.38** |
| 100 | **1.901** | **2.026** | **1.459** | **1.39** |

**曲线形状是凸的**：归一化后 25/50/75/100 = 0.005 / 0.212 / 0.590 / 1.0。也就是说：

- **25 档几乎不动**（满档的 0.5%）。用户截图里"SDK 低档看不出变化"不是截图失真，是真值。
- **50 档只有满档的 21%**，75 档 59%，最后 25 档贡献 41% —— 高档才是主要工作区。
- **平坦区比纹理区磨得更狠，且档位越高越明显**（比 0.51 → 1.27 → 1.38 → 1.39）。这就是"越平越磨、越有结构越保守"。

# 十四、磨皮选择性的真值（2026-10-30 04:10，实测）

> 本节只讲「产品在**不同结构强度**的区域各磨多少」，也就是它那句「越平越磨、越有结构越保守」
> 的量化形式。量纲统一为**掩码内平均 |Δ|（灰阶）**，分类器为 **5×5 局部标准差**。

## 14.1 三档结构强度下的改动量

8 帧真机原始帧（1920×1080，脸宽 529 px）、加密 bundle、`blur_type=-1`、同帧离线、档位 100：

| 区域 | 判据（5×5 σ） | 面积占掩码 | 产品改动量 |
|---|---|---|---|
| 平坦 | σ < 2 | 56.6% | **2.026** |
| 中间 | 2 ≤ σ ≤ 6 | 31.3% | **≈1.85**（由整体 1.901 反解） |
| 纹理 | σ > 6 | 12.1% | **1.459** |
| 整体 | 掩码内全部 | 100% | **1.901** |

**分布是单调递减的**：平坦 2.026 → 中间 1.85 → 纹理 1.459。平坦/纹理比 **1.39**。

关键点：产品**并非"只磨平坦区、不碰纹理"** —— 纹理区仍被磨掉 1.459（相当于平坦区的 72%）。
它是"梯度式收敛"，不是"开关式保护"。这一点很重要，因为按"保护纹理"去设计会把纹理区
压到 1.2 以下，反而偏得更多（我方实测过，见 14.3）。

## 14.2 这个比值与我们参数的关系（可验证的机理结论）

我方门控是 `gw = 1/(1+(a/T)²)`，最终改动量 ≈ `|even − c| · gw · I`，其中
`even = C − B1 + B2` 经 `e` 向 `B2` 混合。实测三者对分布的作用**完全分离**：

| 旋钮 | 总量 | flat/tex 比 | 结论 |
|---|---|---|---|
| `I`（强度） | 等比放大 | **不变** | 改不了分布 |
| `e`（evenfactor） | 等比放大 | **略降**（0.70→1.00 时 1.43→1.34） | 改不了分布，反而削弱 |
| `T`（门控阈值） | 单调减 | **单调增**（T=5.0→1.88、6.5→1.43、8.3→1.10） | **唯一能改分布的旋钮** |

→ 所以「把比从 1.09 提到 1.39」在数学上只有一条路：**降 T 提比，再用 e 把掉的总量补回来**。
这也解释了为什么 v3.1.18 只调 I/e 时比值一直卡在 1.09。

## 14.3 门控陡度指数（gwp）是一条死路

试过把门控写成 `gw = 1/(1+(a/T)^p)`，p>2 时低振幅更贴 1、高振幅掉更快（T=8.3、e=0.70）：

| p | 总量 | 平坦 | 纹理 | flat/tex | RMSE |
|---|---|---|---|---|---|
| 2.0（原式） | 1.917 | 1.777 | 1.621 | 1.10 | **1.608** |
| 2.5 | 1.895 | 1.823 | 1.266 | 1.44 | 1.615 |
| 3.0 | 1.879 | 1.853 | 1.021 | 1.81 | 1.643 |

比值对了，**RMSE 反而变差**；而且 p 与低 T 叠加会过冲（T=6.5 + p=2.2 时比 1.58、
纹理 1.199，低于产品的 1.459）。说明产品那条曲线在 `(a/T)²` 这个形状上已经是最优，
**不需要额外的陡度自由度**。
