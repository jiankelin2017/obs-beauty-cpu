# C4 · 高低频分离磨皮（替代「滤波结果线性混合」）

> 2026-10-28 · 用户要求：磨皮要用我们自己的核，但必须是「磨皮 + 高通（高低频）」，
> 否则脸部很模糊。

## 0. 为什么换

旧的实现是：

```
dst = src·(1-t) + blur·t   ≡   src - (src-blur)·t
```

这个式子把**所有频段一起削弱 t 倍** —— 包括低频（脸型、光影、骨骼起伏）。
t 一大，脸就"糊"了，不是"磨"了。

高低频分离把两件事拆开：

```
low   = 保边模糊(src)          低频：结构，从头到尾不动
high  = src - low              高频：毛孔、痘印 + 五官边缘
atten = strength · (1 - smoothstep(magLo, magHi, |high|))
                                                 ↑ 只压低幅度（瑕疵），
                                                   高幅度（眉耳边）不动
out   = src - high · atten
```

**低频不动 = 脸不塌**，这是这套方法的核心。

## 1. 三个实现选择（都踩过坑）

### 1.1 低频为什么不用大半径高斯

第一版按经典频率分离用可分离高斯（σ=3, 19-tap）。两个问题：

1. **太贵**：1080p 要 **34.22 ms**，直接超 33 ms 预算。
2. **不保边**：高斯各向同性，把边缘也糊进低频，于是 `(src-low)` 在边缘处出现大差值，
   幅度门控只能救回一部分 —— 实测大幅度区只保住 92.1%。

### 1.2 改用「双边迭代」做低频

```
low = bilateral(r=2) 迭代 N 次
```

- **保边**：双边在边缘处几乎不平均，`(src-low)` 在边缘本来就接近 0，门控不用救。
- **便宜**：r=2 已经做过 ROI + 多线程优化，迭代 2~3 次远低于 19-tap 高斯。

数据对比（1080p、磨皮 100 档、`face_src`）：

| 低频提取方式 | 1080p 均摊 | 磨皮量 | 低频保留 | 中幅度保留 | 大幅度保留 |
|---|---|---|---|---|---|
| 高斯 σ=3 | 34.22 ms | 2.443 | 99.1% | 92.3% | 95.8% |
| 高斯 σ=6 | — | 3.026 | **97.1%** | 84.5% | **92.1%** |
| 双边 iters=2 | **14.94 ms** | 1.493 | 99.6% | 96.4% | 98.5% |
| 双边 iters=3 | 19.48 ms | 1.790 | 99.5% | 95.1% | 98.0% |
| （旧）双边 r=2 + 线性混合 | 8.67 ms | 1.053 | 99.8% | 97.8% | 99.1% |

**结论：双边迭代完胜高斯** —— 磨皮量比高斯低，但低频和大幅度保护都更好，成本还只有一半。

### 1.3 颗粒回填（grain）

双边迭代有个副作用：**平坦区被压成"平台"，平台之间出现新台阶**（阶梯效应）。
实测表现是「小幅度高频」不但没降，反而从 105% 涨到 **110.9%** —— 磨皮在造新纹理。

按 lumina 的 `smoothGrain` 扣回 4 邻域尺度的最细颗粒：

```
high -= (src - around4) × grain
```

| grain | 磨皮量 | 小幅度 | 大幅度 |
|---|---|---|---|
| 0 | 1.790 | 110.9% | 98.0% |
| 0.3 | 1.767 | 110.5% | 98.2% |
| **0.5（默认）** | **1.655** | **108.3%** | **98.5%** |
| 0.8 | 1.615 | 107.9% | 98.7% |

方向正确但只缓解了 3 个百分点。**阶梯效应没有根治**（见 §4）。

## 2. 现在的默认参数

| 参数 | 值 | 含义 |
|---|---|---|
| `freqMode` | 1 | 高低频（0 = 退回旧的线性混合，做 A/B） |
| `radius` | 2 | 每次迭代的双边半径 |
| `freqIters` | **2** | 迭代次数（低频尺度 = radius × iters） |
| `sigmaSpace` / `sigmaColor` | 7 / 40 | 沿用 S2 标定值 |
| `magLo` / `magHi` | 6 / 30 | 幅度门控区间（0..255 尺度） |
| `freqGrain` | 0.5 | 颗粒回填量 |

选 2 次迭代而不是 3 次：1080p 从 19.48 降到 **14.94 ms**，而低频保留只差 0.1 个百分点
（99.6% vs 99.5%）。33 ms 预算下还要留出 OBS 层 stagesurface 往返的余量。

## 3. 两个必须记住的坑

### 3.1 迭代会向外扩散，ROI 必须逐轮外扩

第 1 轮写完 `low` 后，第 2 轮读的是 `low` 的邻域 —— ROI 边界那圈像素在第 1 轮里
**没被写过**（是残留数据）。直接导致 ROI 内边界出现 `maxdiff=7` 的偏差。

修法：迭代 N 轮就用 `roi 外扩 N×radius` 的范围跑，最后只在原始 roi 内合成。

### 3.2 「ROI 开/关」必须跑同一种算法，否则等价性测试失效

改完算法后 `verify_roi.py` 报 FAIL。排查发现：ROI 关闭时走的是**旧的双边全帧路径**，
不是高低频 —— 对比的是两种算法，当然不同。

修法：没掩码 / 关 ROI 时也走高低频（只是范围放到全图）。修完三档 **maxdiff=0**。

> 教训：等价性测试只在「同一个算法、只改一个变量」时才有意义。

## 7. 架构不变量：做完开源那 5 项之后，还是不是「高低频」方案

> 起因：2026-10-28 12:50 用户提问 —— 按 1~5 项改完，磨皮逻辑是否还保持「脸部磨皮 + 高通显细节」。

### 7.1 答案：是，主干一个字都不改

当前链路（`beauty_core.cpp` 第 466~526 行 + `beauty_freq.cpp` 的 `freqComposite`）：

```
低  = lowpass(源)                     ← 双边迭代，全分辨率
高  = 源 − 低                          ← 全分辨率
高' = 高 × gate(|高|)                  ← 只压小幅度（magLo..magHi）
    − (源 − 4邻域均值) × grain         ← 颗粒回填，保住 1px 层
sm  = 源 − 高'                        ← 全强度磨皮结果（fp.strength 固定 100）
dst = 源·(1−k) + sm·k                 ← k = 面板 t × 肤色掩码 × (1−edge) × (1−protect)
dst = 美白/红润(dst)
```

那 5 项**全部只动「低」怎么算、以及在哪一级分辨率算**；`高 = 源 − 低` 和
「只压小幅度、大幅度原样留」这两条不动。所以它仍然是频率分离（高通显细节），
不会退化成「整体柔化」——后者是 wuxiwuhen 那种「4 pass 模糊 + 正常混合」的做法，
差别就在**有没有幅度门控**。

### 7.2 一条红线：分离与合成必须留在全分辨率

第 2 项（磨皮降到 1/2）**只能降「低」的计算分辨率**，不能把整个分离+合成一起下沉。

原因：`高` 的最高频率 = 全分辨率奈奎斯特频率。一旦在半分辨率上算 `高`，
1px 级的毛孔纹理会直接落在奈奎斯特频率之外、从 `高` 里消失 —— 而「显细节」恰恰
靠 `高` 保留这一层（`grain` 回填的也是 1px 层）。脸会立刻变成塑料。

lumina 的做法正是这个边界：`kSkinBlurShader` 在 1/2 跑，`kComposeShader` 在全分辨率跑。

### 7.3 三处会「悄悄变味」，必须重标

| 项 | 语义变化 | 要重标什么 |
|---|---|---|
| 1 · diff 减法 | 缓变的大幅过渡不再被判成边缘 → 低在缓变区照常平均 → `高` 在缓变区趋近 0。「高通层只含真细节」 | 面板 `t` 曲线（缓变区会磨得更多，同档位变强） |
| 3 · uint8→float | `低`/`高` 现在都有 ±0.5 量化噪声，4 次迭代还会逐轮把结果压回整数（平台）。改 float 后 `|高|` 分布整体变小 | `magLo`（现在 6，可能要下调）；`grain` |
| 4 · 引导滤波降到 1/4 | 低的边缘位置有约 2px 偏移（1/4 分辨率），`高` 在边缘两侧会留一圈错位余量 | 看是否需要收 `magLo` 或加 1px 羽化 |

第 5 项（检测异步）是纯时序：只影响「掩码晚几帧到位」，与算法无关。

### 7.4 关于 106% 那个数

`freqComposite` 的注释里已经写了实测「小幅度高频 105% → 113%」。目前**还分不清**
这里面多少是双边迭代的平台效应、多少是 `低` 存成 uint8 的逐轮量化。
第 3 项（float 化）做完才能把两者分开 —— 这也是为什么第 1、3 项要一起做再测，
分开做会得到互相污染的数据。

**事实 vs 推测**：7.1 的链路与常量来自源码实读（`fp.strength=100`、`magLo=6`、
`freqIters=2`、`grain=0.5`）；7.2 的边界来自 lumina 源码的 pass 划分。
7.3 表里「会磨得更多 / 分布变小 / 约 2px 偏移」是**推断，未实测**。

### 7.5 实测修正（2026-10-28 13:00）

§7.3 表里「1 · diff 减法」和「3 · uint8→float」两行，**已经做出来实测，结论相反**：

| 改动 | 实测结果 |
|---|---|
| diff 减法（`(tap-center)-(refTap-refCenter)`） | 小幅度 106.0%→105.4%，大幅度 99.1%→98.8%，脸颊台阶 59.4%→66.8%，成本 +40% |
| uint8 → float 缓冲 | 小幅度 106.0%→105.0%，成本 +8~15% |

连带两点：

- **§7.4 那句「106% 里分不清多少是平台效应、多少是量化」现在有答案了：都不是量化。**
  换成 float 后数字几乎不动。而且这个指标本身不可靠（分母极小 + 中尺度错配），
  已改用「脸颊台阶像素占比」：原图 73.3% → 旧路线 59.4% → 参照路线 66.8%。
- **`高 = 源 − 低` 主干没变**（§7.1 仍然成立），变的只是 `低` 的算法；但既然
  四条指标里两条更差两条持平，默认就不切过去。默认仍是 `lowPath=0`。
