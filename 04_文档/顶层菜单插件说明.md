# obs-beauty-ui —— 顶层菜单插件说明

在 OBS 菜单栏加一个**顶层菜单「美颜(&A)」**（位置与第三方「插件中心(C)」相同，都在最右侧），
菜单项「参数面板...」会弹出一个独立窗口，窗口内容**由滤镜自身的属性定义自动生成**。

## 它和「插件中心」是同一套机制（本机实测证据）

| 环节 | 证据 |
|---|---|
| 「插件中心」的真身 | `%APPDATA%\obsplus\store\64bit\store_qt6.dll`（2.9 MB） |
| 它的依赖 | `Qt6Widgets.dll` / `Qt6Gui.dll` / `Qt6Core.dll` + `obs-frontend-api.dll`（dumpbin /dependents） |
| 它调的前端函数 | `obs_frontend_get_main_window`（dumpbin /imports） |
| 它怎么加菜单 | 文件内含 `?addMenu@QMenuBar@@…` 与 `?menuBar@QMainWindow@@…` 符号引用 |

即：**拿主窗口指针 → `menuBar()->addMenu()`**。本插件走的就是这条路，只是把 `obsplus.dll`（纯后台服务，不含任何 Qt 代码）换成了我们自己的代码。

## 安装

已安装到 OBS 的**全局插件目录**（无需管理员权限，与 obsplus 同级）：

```
C:\ProgramData\obs-studio\plugins\obs-beauty-ui\bin\64bit\obs-beauty-ui.dll
C:\ProgramData\obs-studio\plugins\obs-beauty-ui\data\locale\en-US.ini
```

> ⚠️ **目录名必须与 DLL 文件名完全一致。** OBS 扫描 ProgramData 插件时，
> 是按 `<插件目录名>/bin/64bit/<插件目录名>.dll` 去找文件的（见 `obs-module.c`
> 的 `parse_binary_from_directory()`）。名字对不上会**静默跳过、一行日志都不写**，
> 现象和"插件压根没装"完全一样。本插件最初装在 `nama-beauty-ui\` 目录下、
> DLL 却叫 `obs-beauty-ui.dll`，就是这个原因导致重启后菜单不出现。

重新安装只需覆盖这个文件，然后**重启 OBS**。

## 使用

1. 重启 OBS。
2. 菜单栏最右侧出现「**美颜(&A)**」→ 点「**参数面板...**」。
3. 面板顶部下拉框选择作用对象（显示为 `源名 → 滤镜名`），下面的滑块/下拉/勾选框即为该滤镜的全部参数。
4. 改动**即时生效**；「恢复默认」调用滤镜自己的默认值；「刷新」重新扫描滤镜实例。

面板不硬编码任何参数，而是遍历滤镜的 `obs_properties` 动态建控件，
所以滤镜那边增删参数、改标签、改范围，面板自动跟随，不需要维护两份表。

## 构建

```
build-ui.bat
```

依赖：
- **Qt 6.8.3 msvc2022_64**（装在 `C:\Qt`，与 OBS 32.1.1 内置的 Qt 版本一致）
- `obs-sdk\obs.lib`、`obs-sdk\obs-frontend-api.lib`
- MSVC（本机 VS 18 / 14.51 可用）

### 三个必须知道的坑

1. **必须加 `/permissive-`**。本机 MSVC 14.51（VS 18）默认不是一致性模式，Qt 6.8.3 头文件会直接
   `static_assert` 失败（`error C2338: On MSVC you must pass the /permissive- option`），
   紧接着报一堆 `C2666` 重载歧义和 `C2139` 不完整类型的**连带错误**。
   这些连带错误看着像 Qt 与编译器不兼容，其实加 `/permissive-` 后全部消失。
2. **`QAction` 在 Qt6 属于 `QtGui`**，不是 `QtWidgets`。写 `#include <QtWidgets/QAction>` 会报找不到头文件。
3. **`obs-frontend-api.h` 安装包不提供**。本插件只用到 `obs_frontend_get_main_window()` 一个函数，
   直接在源码里按 ABI 声明即可；导入库用 `lib.exe /def` 从 `obs-frontend-api.dll` 的导出表生成
   （`obs-sdk/obs-frontend-api.def` → `.lib`，共 96 个导出）。

另外：菜单创建**不能**在 `obs_module_load()` 里直接做——那时主窗口可能还没建好。
本插件用 `QTimer` 每 250 ms 轮询，直到 `menuBar()` 可用为止（也避免了硬编码 `obs_frontend_event` 枚举值）。

| 文件 | 作用 |

## 已知限制

- 面板对少数控件类型（颜色、路径、字体、可编辑列表、按钮）显示为占位文字。
  滤镜属性页里的「恢复默认 / 保存到 preset.json / 从 preset.json 读取」三个按钮属于
  `OBS_PROPERTY_BUTTON`，libobs 没有提供外部触发接口，面板里用「恢复默认」按钮替代（走
  `obs_get_source_defaults`），preset 的存取仍在滤镜属性页里操作。
- 面板按 `源名 + 滤镜名` 定位实例，多摄像头互不干扰；但底层 SDK 的全局状态问题仍属滤镜端。
