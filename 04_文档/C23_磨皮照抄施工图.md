## 0. 判据：什么算"抄成了"

拟合的病不是精度不够，是**换了条件就崩**：

- 阶段 3 的五条"硬结论"（`r1≈r2` 同尺度、`thr=0` 纯盒式、`e` 线性 0.45→0.60、半径线性 2→14、脸宽归一化）全部是扫参产物，被阶段 4 逐条推翻。
- `S2` 用双边把档位曲线压到 RMSE 1.16 个百分点，但**像素级 RMSE 3.977 / MAD 3.125** —— 曲线对了，结构没对。

所以验收判据不是"曲线重合"，而是：

| 层级 | 判据 | 现状 |
|---|---|---|
| 结构 | 两级都有、第二级是 25 tap 表面模糊串行两趟、核 UV 半轴固定 | **缺第一级、第二级是盒式** |
| 行为 | 档位曲线 **+** 像素级残差同时达标 | 只有曲线达标 |
| 可迁移 | 换分辨率/换脸宽不重新调参 | 现在靠 `scale = fw/532` 硬归一化，是拟合痕迹 |

## 1. 目标管线全景

```
                    ┌─ tex_mask (a=skin, g=eyes)
                    │
src ──┬─ [L1] 边缘感知预模糊 ──► out1 ── [L2] 表面模糊混合 ──► out2 ──► 美白/红润/细节回填
      │        ↑ tex_pre_blur                    ↑ blur1 / blur2
      │        （blur_type 选算法）               （25 tap 串行两趟，半分辨率）
      │
      └─ 全分辨率 ─────────────────────────────► 全程全分辨率，只有 blur1/blur2 是半分辨率
```

三条必须同时成立的约束：

1. **两级串联，不是二选一。** 只做第二级 = 少一条腿（`01` §4 末尾）。
2. **L1 的混合系数带 `0.25`**，最大贡献只有 `0.75 × 1.0 × 1.0 × 0.25 = 0.1875`。
3. **L2 在 `t ≥ 0.7` 完全饱和** → 75→100 档的差别**全部**来自 L1（`blur_intensity` 0.5625 → 0.75，即 L1 混合系数 0.1406 → 0.1875，**+33%**）。这是"为什么必须补第一级"的定量答案。

## 2. 第一级：边缘感知预模糊

### 2.1 逐行伪代码

```cpp
// 输入：src（全分辨率 RGBA）、mask（.a = skin）、preBlur（全分辨率，由 blur_type 生成）
// 输出：out1
for each pixel (x, y):
    C      = src[x,y]                       // 0..1
    m      = mask[x,y].a
    out    = C
    if (m > 0.001) {                        // 【源码】仅在皮肤区域处理
        B  = preBlur[x,y]                   // 低通图
        // dis = 模糊图与原图的"正向"色差 × 30
        vec3 d = max(B.rgb - C.rgb, 0)      // 【源码】注意是 max(...,0)，只算变亮方向
        float dis = length(d) * 30.0
        float factor = step(0.5, dis)                       // dis<0.5 平坦皮肤：不磨
        factor *= (1.0 - smoothstep(5.0, 6.0, dis))         // dis>6 强边缘：不磨
        if (dis > 0.5 && dis < 5.0) {                       // 仅中频（毛孔/细纹）
            out = preEnlighten(C, factor * blurIntensity * m * 0.25)
        }
    }
```

**四个不能省的细节**

| 细节 | 值 | 证据 | 省掉的后果 |
|---|---|---|---|
| `max(B−C, 0)` 的**单向** | 只取变亮方向 | 【源码】 | 用 `abs()` 会让暗侧也进门控，磨掉阴影细节 |
| `× 30` 的放大 | 30 | 【源码】 | 不放大则 `dis` 永远进不了 (0.5, 6.0) |
| `step(0.5, ·)` 下限 | 0.5 | 【源码】 | 平坦区被磨 → 塑料感 + 噪点放大 |
| `smoothstep(5,6,·)` 上限 | 5→6 | 【源码】 | 五官边缘被糊 |
| `× 0.25` | 0.25 | 【源码】 | L1 贡献放大 4 倍，画面发灰 |
| `blur_intensity = 0.75·t` | 0.75 | 【实测】 | 档位曲线整体偏移 |

### 2.2 `preEnlighten` = 3D-LUT 预提亮

结构【源码】，LUT 内容**未取到**（`01` §2.3）。网格 `dim=64, raw=8, col=8` → 512×512 摊平纹理。

> **施工策略**：L1 的**几何部分**（`dis` 门控 + 混合系数）可以先照抄，LUT 用恒等表（identity）跑通链路；LUT 内容作为独立的颜色项后补，**不阻塞结构**。这与"磨皮几何"是解耦的。

### 2.3 `tex_pre_blur` 由 `blur_type` 选算法

`01` §4 只有"极可能"的推断，但 3.1.14 之前已拿到**强旁证**：`bt0` 的梯度十分位曲线呈 **U 形**（中段保留率 59.4% 最低、两端 71.7%/77.8% 回升），正是 `dis` 带通门控的指纹 —— 说明 `blur_type` 改的确实是 `pre_blur`，进而改了 `dis` 的分布。

| 档 | 族 | 施工优先级 |
|---|---|---|
| **1（默认）** | 双边族（依赖比 1.647、MTF 高频平台 0.73） | **先做这个** |
| 0 | 线性低通 + `dis` 带通门控 | 后做 |
| 2 | 极弱近线性 | 最后做 |

**双边参数未定**【推断】：`S2` 扫出 `d=9 σc=40 σs=13.5` 能复现档位曲线，但那是**曲线拟合**，不是参数真值。施工时先落地，并把参数标成 `【拟合】`，等 0a′ 与合成图实验再定。

## 3. 第二级：表面模糊主体

### 3.1 核：25 tap，串行两趟

```cpp
// 在**半分辨率**（960×540）上跑，输出 blur1 / blur2
// C0 = 中心像素（归一化 0..1），Δg 只测绿通道
vec3 surfaceBlur25(vec2 uv, vec3 C0, float yFactor, sampler2D tex) {
    vec3  sum  = C0;            // 中心点权重恒为 1
    float wsum = 1.0;
    for (int d = 0; d < 8; ++d) {              // 8 个方向，45° 间隔
        vec2 dir = vec2(cos(d * PI/4), sin(d * PI/4));
        for (int j = 0; j < 3; ++j) {          // 3 个环：lens = 1, 2, 5
            float r  = RING[j];                // 1, 2, 5
            vec2 off = dir * vec2(sx, sy) * r; // ← UV 半轴**固定**，不随画幅变
            vec3 Ck  = texture(tex, uv + off).rgb;
            float dg = Ck.g - C0.g;            // 只测绿通道
            float w  = 1.0 - min(dg*dg*yFactor, 1.0);   // 二次抛物线截断
            sum  += w * Ck;
            wsum += w;
        }
    }
    return sum / wsum;
}
// pass1: yFactor=40  （容限 Δg=0.1581），输入=原图
// pass2: yFactor=20  （容限 Δg=0.2236），输入=pass1 输出
```

**四个必须照抄的细节**（`01` §3.2）

| # | 细节 | 若做错 |
|---|---|---|
| 1 | **空间权重恒为 1** —— 盒式，不是高斯 | 换成高斯会让高频衰减曲线变形，MTF 高频段对不上 |
| 2 | **值域权重是二次抛物线截断** `1−min(Δg²·y,1)` | 换指数/L1 会改变容限的物理含义 |
| 3 | **只测绿通道** | 换成亮度会让人脸肤色差异参与门控 |
| 4 | **中心点权重恒为 1**（不参与门控） | 加门控会让核在强边缘处退化 |

> ⚠️ **来源存疑（必须写进代码注释）**：`master_analysis §3.5` 记录 `clear_blur` / `blur_h_fs` / `blur_v_fs` 的**逐行 GLSL 体在已解密堆文本中未干净捕获**（只拿到文件名清单）。所以这一节的 25 tap / `yFactor` 40-20 / 容限 0.1581-0.2236 **可能是【重建】而非【源码】**。
> **纪律**：实现时在函数头标注 `【重建·待证】`，等 0a″ 合成图实验（阶跃边/脉冲阵列）验证后再改成 `【源码】`。**不许假装是抄来的。**

### 3.2 采样几何：UV 半轴固定

`sx = 0.002640845`、`sy = 0.0046875`（比值 1.775），**按 1136×640 参考分辨率生成，不随画幅自适应**【实测】。

验证（与 `01` §3.3 的表逐格对齐）：

| 输入 | 处理分辨率 | 环1 | 环2 | 环3 |
|---|---|---|---|---|
| 1920×1080 | 960×540 | 0.002640845×960 = **2.535** / 0.0046875×540 = **2.531** | 5.07 | 12.67 |
| 1080×1920 | 540×960 | 1.426 / **4.500** | 2.85 / 9.00 | 7.13 / 22.50 |

**推论**：横屏是**圆核**，竖屏是 **3.16:1 椭圆核**。这条如果抄错（比如按画幅归一化），横屏看起来"没问题"、竖屏直播直接翻车 —— 而现有 11 张金标图**全是 640×394**（宽高比 1.62，接近参考的 1.775），**椭圆问题显现不出来**。

### 3.3 合成式（逐行照抄）

```glsl
diff = (C.rgb - blur1) * 0.5 + 0.5;                  // 高频层
even = clamp(2.0 * diff + blur2 - 1.0, 0.0, 1.0);    // ≡ clamp(C - blur1 + blur2)
even = mix(C.rgb, even, skin_mask);                  // ①
even = mix(even, blur2, skin_mask * evenfactor);     // ②
res  = mix(C.rgb, even, intensity);
out  = mix(C.rgb, res, 1.0 - eye_mask);              // 眼睛完全不磨
```

**① 和 ② 的顺序是确定的**，`01` §2.4 已给出逐字源码，不要怀疑。

## 6. 施工顺序与验收点

### 6.0 前置：两份金标，决定后面会不会白写

`#5`（25 tap 核）是**唯一一处"结构本身可能不是抄来的"**。在动它之前必须先拿到：

| 金标 | 怎么拿 | 解决什么 |
|---|---|---|
| **合成图**：水平/垂直阶跃边、单像素脉冲阵列、不同周期棋盘 | 给 SDK 喂合成图（GL 上下文，直播结束后） | ① 直接读出**脉冲响应** → 反解 25 tap 的环半径与权重；② 定 UV 半轴比值（现在噪声底 ±0.10，判不了 1.093） |
| **预模糊单独产物** | hook `glTexImage2D` dump `tex_pre_blur`，或改 shader 直接输出它 | 直接看 bt1 的双边参数，不用从最终输出反推 |

> **为什么必须前置**：如果合成图反解出来的核不是"8 向 × 环 {1,2,5} + 中心"，`#5` 就得推翻重写。而 `#5` 是第 2 批里工作量最大的一项。**先花半天验证，比写完再推翻便宜。**

### 6.1 工单顺序

```
第 2 批-0  合成图 + 预模糊 dump + 0a′        定对象、定核、定几何
           ↓ 验收：脉冲响应能拟合出环半径；bt1 的 σs/σc 有直接读数
第 2 批-A  #5 + #6 + #7   第二级换成 25 tap + 半分辨率 + 固定半轴
           ↓ 验收：100 档 像素级 RMSE 从 3.977 降到 < 2.0；MTF 高频段与 bt1 差 < 0.10
第 2 批-B  #8            补第一级（LUT 恒等）
           ↓ 验收：75→100 档的增量出现（现在第二级饱和，这段完全没有）
第 2 批-C  #9            预模糊按 blur_type 分档
           ↓ 验收：bt0/bt1/bt2 三档的梯度十分位曲线形状同时对上（U 形 / 上升 / 平坦）
第 2 批-D  #10           LUT 真实内容
```

**若合成图拿不到**（比如 hook 失败）：`#5` 仍可写，但必须在函数头标 `【重建·待证】`，并且**不许**宣称"照抄完成"。这种情况下第 2 批-A 的验收只能看曲线与 MTF，不能看脉冲响应。

**每步都必须跑的两组回归**（`00_先读我.md` §5.2）：

1. 8 场景 × 5 档对拍
2. `verify_roi` 两套哈希 —— **legacy 必须逐字节不变**（`maxdiff=0`，EMA 默认必须为 1.0）

## 8. 反拟合纪律（写进代码注释，不是写在这里就算）

1. **每个常数必须带证据标签。** 形如 `// 【源码】01§2.2`、`// 【拟合】S2 RMSE 1.16`、`// 【重建·待证】master_analysis §3.5`。
2. **拟合出来的参数不许冒充真值。** 凡是扫参得到的（`d=9 σc=40`、`r=2/it=2`、`fw/532`），注释里必须出现"拟合"二字。
3. **改参数必须说明改的是"抄错了"还是"拟合偏了"。** 前者修 bug，后者要重跑曲线。
4. **不许为了让某个金标对上而加归一化/缩放项。** `scale = fw/532` 就是这类东西，第 2 批删掉。

## 9. 第 2 批-A 实测结果（3.1.15）

### 9.1 §6.0 前置验证的产出

合成图实验做了一半，结论要按证据等级分开记：

| 目标 | 结果 | 证据 |
|---|---|---|
| 核尺度是否随画幅缩放 | **是**，σx ∝ W^0.98（四画幅 1.95/3.85/7.72/11.20 px） | 【实测】`synth_grating.py` + `grating_fit.py` |
| UV 半轴各向异性 | 640×394 实测 σx/σy=0.951，固定 UV 预测 0.915，一致 | 【实测】 |
| **环半径 {1,2,5}** | **没测出来** —— 互相关区域受「活跃区是细网」限制，只有 4,460 px，展宽部分每抽头 0.006 与噪声同量级 | 仍【重建·待证】 |
| `tex_pre_blur` 单独产物 | 未做（需要 hook `glTexImage2D`） | 仍缺 |

**方法学教训（两条，都写进 `00_先读我.md`）**：

1. **脉冲/阶跃探针原理上无效。** 值域权重 `wk = 1 − min(Δg²·yFactor, 1)` 天生拒绝孤立离群点：A=9 的单像素脉冲响应只有 0.3 灰阶（uint8 全舍入为 0），强阶跃边缘 `wk≈0` 根本不磨。有效探针只能是低幅光栅（A=16、P=20px → `wk=0.984`）。
2. **被混合权重压缩过的量不能直接当尺度判据。** `|H_eff|` 高频端在 0.5 附近饱和，动态范围只剩 1.0→0.5；只看幅值会得出「核像素固定」的错误结论。必须拟合到 σ 再比。

### 9.2 实现与标定

3.1.15 落了 `surface3Rgb25()`（`beauty_smooth.cpp`），默认**关闭**（`g_cfg.s3Tap25=0`，`BEAUTY_S3_TAP25=1` 打开）。legacy 与旧 surface3 输出逐字节不变（`verify_roi` 三套哈希 `ac7c2af4`/`c7015036`/`9b039485` 全 PASS）。

**`yFactor` 40/20 → 110/55，是标定不是拟合。** 用光栅法量自研引擎的核宽：

| 实现 | σx | σy | 高频平台 a |
|---|---|---|---|
| **SDK bt1** | **3.85** | **4.23** | 0.497 |
| 自研盒式（tap25=0） | 2.77 | 2.79 | 0.076 |
| 自研 25 tap，yF 40/20 | 4.67 | 5.08 | 0.349 |
| 自研 25 tap，yF 80/40 | 4.10 | 4.27 | 0.394 |
| **自研 25 tap，yF 110/55** | **3.54** | **3.52** | 0.454 |

40/20 让核宽了 21%（过磨主因），按 σ 对 log2(yFactor) 插值到 3.85 得 ≈109，取 110。**没有按 RMSE 挑值**：160/80 的 RMSE 只再低 0.056（噪声内），但幅度掉到 2.46 明显欠磨，按 RMSE 挑就是拿金标拟合。

### 9.3 验收状态

2. **25 tap 的环半径 {1,2,5} 与「8 方向 × 3 环」这个结构，从「【重建·待证】」降级为「疑似错误」**——它的频响有旁瓣，SDK 没有。
3. 下一步不是继续加级，而是**用 SDK 的实测频响曲线反推 B1/B2 的空间形状**（目标函数是保留率曲线，不是 RMSE，不违反 §8 反拟合纪律）。候选：

   - 换平滑核（盒式/高斯）但保留值域权重
4. 性能警示：25 tap 在 1080p 离线 48.43ms，相对 legacy 是 4.0×。真机 720p 上预计总时长约 40ms，**超 33.3 预算**。核结构定稿后必须做性能。

## 11. 振幅-频率响应（真机帧光栅法，2026-10-29 19:20）

### 11.1 为什么要这一步

§10.5 证明了线性模型不够：双高斯拟合能把谱形状压到 MAE 0.0194，但作用到图上改动量只有 0.915，SDK 是 2.704。**线性移不变滤波器在结构上就复现不了边缘自适应行为**——平均谱看起来像弱平滑，实际改动集中在部分像素上。

所以必须测「增益随振幅怎么变」。工具：`06_离线验证/real_grating.py`

### 11.4 两个结构性缺陷（量化）

**缺陷 1：核太窄，凹陷位置错了一倍。**
- SDK 主凹陷在 **24 px**，我们主凹陷在 **12 px**
- 在 24 px 处：SDK 0.201，我们 **0.412** —— 皮肤纹理的主导尺度上，我们只磨了 SDK 的一半
- 在 8–12 px：我们磨得比 SDK 多

**缺陷 2：振幅依赖太弱，所以边缘磨过头。**
- SDK：P=8 处 A=2→A=16，增益 0.289→0.579（**翻倍**，强纹理自动放过）
- 我们：同一处 0.396→0.415（**几乎不变**，强弱一视同仁）
- 结果就是 §10.3 看到的：SDK 只磨颗粒，我们把眼镜框、眉骨、下颌全磨了

### 11.5 根因：B1 与 B2 只在值域容差上不同，不在空间尺度上

§3.3 的合成式 `even = C − blur1 + blur2` 是一个**带通**：去掉的频段由 B1、B2 的差异决定。

- 我们的 B1/B2 用**同一个** 25 tap 核（半径都是 1/2/5），只有 `yFactor` 不同（110 vs 55）→ 两者的空间尺度一样，差异只来自值域门控 → 带通中心落在短周期（12 px）
- SDK 的带通中心在 24 px，且 §10 的双高斯拟合给出 **σ₁≈2.25 / σ₂≈7.25 px（差 3.2 倍）** → 它的 B1/B2 是**不同空间尺度**的模糊，不只是容差不同

**结论：`blur1` 与 `blur2` 必须是两个不同尺度的模糊，不能是同一个核的两个容差档。** 这是 C23 §3.3 需要修正的地方（原文按「同核两档 yFactor」实现）。

### 11.6 下一步设计（待验证）

```
B1 = 窄模糊  σ ≈ 2.3 px（1080p）→ UV 半轴约 0.0012
B2 = 宽模糊  σ ≈ 7.3 px（1080p）→ UV 半轴约 0.0038
out = C + w(Δg) · (B2 − B1)
```
其中 `w(Δg)` 必须是**振幅相关**的：弱纹理（A 小）w 接近 1，强纹理（A 大）w 迅速降下来。这正好对应 SDK 的 A=2→A=16 增益翻倍。

验收：用 `real_grating.py` 的同一张表对比，要求
- 主凹陷位置落在 24 px
- A=2 时 P=24 的增益 ≈ 0.20
- A=16 时 P=8 的增益 ≈ 0.58

**这三条是结构判据，不是 RMSE。** 全部对上之后再跑 `real_frame_eval.py` 看像素 RMSE。

## 12. 双尺度带通落地（2026-10-29 17:40，core 0.10）

### 12.1 定型的结构

```
B1  = 窄模糊    3 次盒式，半分辨率宽 5 px（全分辨率 10 px）
B2  = 宽模糊    3 次盒式，半分辨率宽 9 px（全分辨率 18 px）
D   = B2 − B1                                    带通
even= C + (1−e)·D + e·(B2 − C)   ≡ §3.3 的 (1−e)C − (1−e)B1 + B2
a   = blur(|C.g − B2.g|)        振幅代理（只测绿通道，同 §3.1 ③）
w   = 1 / (1 + (a/T)²)          Wiener 式收缩，T = 14 灰阶
out = C + w·(even − C)
```

代码：`beauty_smooth.cpp` 的 `surface3RgbBand()`，开关 `BEAUTY_S3_BAND=1`，
默认**关**（`g_cfg.s3Band=0`）。25 tap 路径原样保留，可用
`BEAUTY_S3_BAND=0 BEAUTY_S3_TAP25=1` 做 A/B。

**为什么用盒式而不是高斯**：3 次盒式 ≈ 高斯，实测 RMSE 1.353（真高斯）vs
1.336（3 次盒式）—— 差在噪声内。但盒式是 O(1)/像素的滑动窗，比高斯省一个数量级。
**为什么 3 次不是 2 次**：2 次盒式改动量掉到 2.32（3 次 2.53），过磨不足，且实测
不比 3 次快，不做。

**为什么半分辨率**：实测 RMSE 1.336（全分辨率）vs 1.362（半分辨率），可忽略；
耗时差 4 倍。

### 12.2 T 的标定（不是扫 RMSE）

§11.4 量出 SDK 的振幅依赖是**与频率无关的标量**：A 从 2 涨到 16，各周期的
「改动量」都缩到 0.58 倍（P=8: 0.592、P=24: 0.571、P=64: 0.576）。这正好对应
`1/(1+(A/T)²)` 这个形状，用四个振幅档拟合得 T ≈ 19（作用在光栅振幅上）。

落到实现里 `a` 是 `|C−B2|` 而不是光栅振幅，两者差一个 `(1−H2)` 因子，换算后
原型里 T=12。**真实管线里 T 要取 14**，因为 skin 掩码羽化 + 眼周保护把改动量
压掉约 5%：

| T | 内缩 6px RMSE | 改动量 | 空间相关 |
|---|---|---|---|
| 8 | 1.771 | 1.979 | 0.877 |
| 10 | 1.618 | 2.279 | 0.885 |
| 11 | 1.586 | 2.410 | 0.886 |
| 12 | **1.582** | 2.529 | 0.885 |
| **14** | 1.636 | **2.740** | 0.881 |

**按改动量对齐取 14**（2.740 vs SDK 2.704，差 1.3%），不是按 RMSE 取 12。
T=12 的 RMSE 更低 0.054，但那是「少磨一点、误差小一点」的假赢——§10.5 已经
证明过这条路（α=0.70 时 RMSE 2.495 但改动量只有 2.106）。

### 12.3 三个振幅代理的对照（为什么选 `|C−B2|`）

| 代理 | 定义 | P=8 处 A=2→A=16 的振幅依赖 | 结论 |
|---|---|---|---|
| `d` | `|B2−B1|` | **1.0x** | 高频处两者都≈0，相减也≈0，门控失效 |
| `c1` | `|C−B1|` | 强，但 P=64 几乎不响应 | 频率依赖过头 |
| **`c2`** | `|C−B2|` | **1.3~2.0x**，全频段一致 | 采用 |

振幅平面再平滑一次（3 次盒式宽 5）——不平滑的话 `|C−B2|` 本身带噪，
门控会逐像素抖，出现「麻点」。

### 12.4 落地后的实测（真机帧 1920×1080，SDK 金标）

| surface3 盒式 | 6.000 | 3.977 | 0.629 | — |

边缘像素占皮肤 22%，原来扛 58% 的残差平方，现在只扛 25%。**「描轮廓线」的
问题解决了**（对比图 `goldens/real/d_cam_surface3_band14_chg_*.png`：SDK 与
我们都是弥漫斑点，不再有眼镜框/眉毛的轮廓）。

改动图里唯一还剩的差别是**眼周**：SDK 在眼睑上仍有改动，我们是黑的。原因是
`kps=1`（只检出一个关键点），眼周保护掩码退化成一个大椭圆。实测把 `EYEK`
从 100 降到 0，RMSE 1.582 → 1.411、改动量 2.496 → 2.607，更接近 SDK。
**这是独立问题，本轮没动默认值**（改它会同时影响 legacy 路径）。

### 12.5 结构判据：2 过 1 不过

用 `real_grating.py` 同一把尺子（掩码内缩 8px，316,608 px）：

| 周期 px | A=2 | A=4 | A=8 | A=16 |
|---|---|---|---|---|
| 8 | 0.477 | 0.440 | 0.494 | **0.615** |
| 12 | 0.430 | 0.468 | 0.481 | 0.612 |
| 16 | 0.416 | 0.434 | 0.504 | 0.611 |
| **24** | **0.382** | 0.413 | 0.456 | 0.587 |
| 32 | 0.446 | 0.476 | 0.515 | 0.610 |
| 48 | 0.598 | 0.651 | 0.670 | 0.699 |
| 64 | 0.700 | 0.765 | 0.793 | 0.807 |

与 SDK 表 MAE **0.066**（25 tap 是 0.139 的 LTI 版、0.072 的门控版）。

| 判据 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 1 主凹陷位置 | 24 px | **24 px** | ✅ |
| 2 A=2 · P=24 增益 | 0.201 | **0.382** | ❌ 偏保守 |
| 3 A=16 · P=8 增益 | 0.579 | **0.615** | ✅（差 0.036） |
| 附 振幅依赖 P=8 | 2.00x | 1.29x | ❌ |

**判据 2 不过的含义要说清楚**：我们对**噪声级（±2 灰阶）弱纹理**没有 SDK 那么狠，
保留约 62% 而不是 80%。试过硬门控（幂次 3/4/6/8），RMSE 全部变差
（1.53 / 1.70 / 1.92 / 2.03），因为硬过渡在真实纹理的振幅分布上切出一圈振铃。
**软门控 + 略保守，是像素指标下的最优；判据 2 是「光栅探针」的偏好，不是人眼
的偏好。** 这一条留作已知偏差，不硬凑。

### 12.6 性能

| 画幅 | band | 25 tap | 变化 |
|---|---|---|---|
| 640×394 | 4.70 | 6.68 | −30% |
| 1280×720（真机） | **10.33** | 17.82 | **−42%** |
| 1920×1080 | 21.28 | 31.62 | −33% |

盒式被调用 18 次/帧，**每次单独起线程的话光创建就吃掉 3~4 ms**（1080p 上占 20%）。
所以 `bandBoxH/V` 一次并行区域处理 3 个通道，线程创建次数降到 1/3。小画幅
（半分辨率 < 150k 像素）直接单线程。

**还能再快的地方（未做）**：模糊目前跑整帧，而掩码只占 20%。按掩码 bbox 外扩
`passes×(r2+ra)` 裁剪理论上还能省 3~4 倍，但要改坐标映射，且必须保证
`verify_roi` 仍然 `maxdiff=0`。留作下一轮。
