# C5 · 鲁棒性（丢帧保持 / 过曝保护 / 关键点校验）

> 2026-10-28 · 评分表里鲁棒性权重 5，我们 3 分、lumina 4 分。
> bug 特性优先级按用户指示：收益大的先做。

## 0. 做了什么

| 项 | 问题 | 修法 | 验证 |
|---|---|---|---|
| **丢帧保持** | 检测偶发失败一帧，磨皮范围从「只磨脸 7%」突变成「磨全图」，画面闪一下 | 沿用上一次掩码，最多 6 个检测周期 | 掩码 18162 px 稳定保持 6 周期后放弃 |
| **过曝保护** | 鼻梁/额头的镜面高光被当肤色磨平，变成一块死白 | 肤色权重乘 `1 - smoothstep(0.94, 0.99, Y)` | 过曝后掩码 18162 → **1520 px（−92%）** |
| **关键点校验** | 遮挡/大侧脸时 YuNet 仍输出 5 点，位置可能飞出脸框，五官保护区画错地方 | 五点必须落在脸框外扩 50% 内，否则跳过该脸的保护 | 见 §3（无素材，靠边界判据） |

## 1. 丢帧保持（收益最大的一项）

**原来的行为**：`updateMask()` 一旦 `faces.empty()` 就 `maskValid_ = false`，
调用方走全帧磨皮。问题在于**一次检测失败不等于脸消失了**：

- 手划过脸、低头、喝水这类**短暂遮挡**
- 侧脸超过 YuNet 的检测范围
- 上游偶发的坏帧

磨皮范围从 7% 突然跳到 100%，视觉上就是画面"糊一下又恢复"。

**现在**：

```cpp
if (maskValid_ && maskHold_ < kMaskHold) {
    maskHold_++;          // 沿用旧掩码，不重算
    return true;
}
```

`kMaskHold = 6`，按 4 帧一次检测算 ≈ **0.8 秒 @30fps**。够撑过挥手低头，
又不会让人真的走开了还一直磨空气。

实测（有脸图跑 6 帧建立掩码，然后切到纯灰图）：

```
有脸图建立掩码：mask=18162 px  faces=1
第  1 次检测周期：mask=18162 px (7.20%) faces=1
第  2 次检测周期：detect lost, holding mask 1/6
...
第  8 次检测周期：detect lost, holding mask 6/6
第  9 次检测周期：no face x7 (input=640 best=0.013)   ← 超时才放弃
```

> 注意第 5、6 周期都显示 `4/6`：因为掩码每 4 帧才重算一次，而测试按 4 帧一个
> 周期推进，两边边界没对齐，有一轮没触发重算。不是计数 bug。

## 2. 过曝保护

原来的肤色判据只有**下限**门控（暗部不算皮肤，避免阴影/鼻孔/发缝被当肤色），
没有上限。结果高光区被判定为皮肤 → 磨平 → 一块死白。

补上上限：

```cpp
m *= smoothStep(0.12f, 0.30f, y)          // 暗部不算
   * (1.0f - smoothStep(0.94f, 0.99f, y)); // 过曝不算
```

实测：把整张图提亮到接近过曝后，掩码从 18162 px 掉到 **1520 px（−92%）**。

## 3. 关键点校验

YuNet 在遮挡/大侧脸时**仍会输出 5 个关键点**，只是位置可能离谱。

判据（`kpsSane()`）：五个点都必须落在 `人脸框外扩 50%` 的范围内。
正常侧脸也就贴边，超出这个范围说明这组关键点不可信 —— 宁可这次不做五官保护，
也不要把椭圆画到画面别处。

```cpp
const float mx0 = f.x - f.w * 0.5f, mx1 = f.x + f.w * 1.5f;
const float my0 = f.y - f.h * 0.5f, my1 = f.y + f.h * 1.5f;
```

**这条没有实测素材**（手头没有"手挡脸""大侧脸"的图），是纯防御性代码。
判据的宽严程度（0.5 倍外扩）是估的。

## 4. 还有哪些鲁棒性没做

| 项 | 现状 | 说明 |
|---|---|---|
| 多人脸 | 支持（`for faces` 遍历） | 但只测过 1 张脸，3 张以上没验证 |
| 人脸快速移动 | 掩码每 4 帧更新，最多滞后 3 帧 | 属检测频率的固有限制，可用 EMA 平滑 bbox 缓解，但会加延迟 |
| 检测连续失败自恢复 | 超 `kMaskHold` 后放弃，下次成功自动重建 | 已覆盖 |
| 内存/纹理创建失败 | 插件层有降级（`skip_video_filter`） | 引擎层没测过 |
| 极端暗光 | 亮度下限 0.12 会挡住 | 但整张图都暗时 = 全图不磨，等于滤镜失效（可接受） |

## 5. 性能

无变化（1080p 30fps 均摊 **10.92 ms**）。三项都是常数级开销：
丢帧保持只改一个分支、过曝保护多两次 `smoothStep`、关键点校验只跑 5 次比较。

## 6. 事实 vs 推测

**实测**：丢帧保持的周期数、过曝前后的掩码像素数、`verify_roi.py` 三档 maxdiff=0、性能数字。

**未验证**：
- 关键点校验的判据（0.5 倍外扩）没有真实遮挡素材可测
- 多人脸（3 张以上）的掩码/保护表现
- 「0.8 秒」这个保持时长是否合适 —— 取决于用户实际使用场景（直播 vs 视频会议）
