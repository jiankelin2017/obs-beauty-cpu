### 1.1 性能现状逐项判定（两层口径）

> 本节只做状态判定，不记变更、不列耗时数字。当前版数字表格已按第 5 批裁定清零，
> 历史轴的耗时、加速比与哈希不进当前版，仓库内不再提供逐字出处。
> 判定依据按「逐字源码 > 动态实测 > 推断」的可信度顺序取用。

**一句话结论**：代码层优化已落地（继承自历史轴，**不是**当前轴验收）；引擎层 A/B 与画质 golden A/B 已于 2026-11-06 在本轴重跑；真机端到端、少核机器、多人脸仍未验证。三者不可混为一谈。

## 3. 升版本操作清单（可执行）

1. 改 `01_源码\beauty_params.h` 的 `BEAUTY_BUILD_STR`（唯一出处），按规则递增：普通升级第四位 +1，大版本第一位 +1 其余归零。
2. **不要再手工同步版本号**：`06_安装包\build_setup.ps1` 从 `BEAUTY_BUILD_STR` 读取 `$Ver` 并派生 `$FilterVer` / `$PanelVer` / `$CoreVer`；`e2e_test.ps1` 的 `$Setup` 与 `obs-beauty.nsi` 的 `PKGVER` 均自动跟随（缺 `/D` 时 `!ifndef` 分支直接 `!error`，没有兜底默认值）。依据见 `docs/guides/guide-build-installer.md` §2 与该脚本第 45–54 行。
3. 用 `BEAUTY_OUTDIR` 编两件 DLL 到新产物目录，再用 `BEAUTY_BUILD_OUT` 打包。
4. 跑版本串自检（脚本内自动）、核对版本资源四段、跑 `e2e_test.ps1`。
5. 更新本文件「当前有效结论」表与根 `README.md` §0，`docs/INDEX.md` 的「适用版本 / 最后核对」列。
6. `python 05_验证\check_upload.py --staged` 过闸门后再提交。
