## 2. 关键变更记录（只留影响使用的里程碑）

### `1.0.0.0` — 2026-11-06 · CPU 线立轴（当前版）

| 变更 | 对读者的影响 |
|---|---|
| 版本重置为四段 `1.0.0.0`，与 GPU 版 `3.0.1` 明确分离 | 版本号不可互比；所有脚本/文档/日志口径换轴。**不是** `3.1.41`，也不是回退 |
| `BEAUTY_BUILD_STR` 定为唯一出处；`CoreEngine::version()` 并入单轴 | 升版本只需改 `beauty_params.h` 并按链路同步；不再有 `core 1.4.x` |
| UI 新增 `BEAUTY_UI_CPU_EDITION` 编译宏（默认 `0`，仅 `build-ui_320.bat` 定义 `=1`） | CPU 版菜单/标题/角标/关于/日志带明显 CPU 标识；GPU 版共用同一 UI 源码时行为零变化 |
| `obs_module_description()` 与 `init OK` 日志加 CPU 标识 | 日志里现在是 `init OK (CPU v…)`，按旧样例 `init OK (v3.1.39…)` 去找会找不到 |
| 构建脚本新增 `BEAUTY_OUTDIR` / 打包脚本新增 `BEAUTY_BUILD_OUT` | 可输出到独立目录，**不覆盖** `build_output\` 的历史定稿 DLL；不设变量时行为与原来一致 |
| NSIS 新增 `EDITION "CPU 版"`，产物名 / Name / Caption / BrandingText / DisplayName 同步 | 安装包名变为 `OBS美颜_CPU_v1.0.0.0.exe`；控制面板显示带 CPU 版 |
| `VIProductVersion` / `FileVersion` 直接取 `${PKGVER}`，不再拼 `.0` | 版本资源正确为四段；沿用旧写法会变五段 `1.0.0.0.0` |
| `e2e_test.ps1` 指向新安装包名 | 回归测试对象换成 CPU 包（**但两轮 40 项断言尚未对新包复跑**） |

验证（2026-11-06 实测）：滤镜与 UI（含不带宏的对照版）均编译通过；CPU 宏字符串只出现在 `=1` 版；
定稿 DLL 的 MD5 编译前后完全一致；打包自检全绿；安装包 `ProductVersion` / `FileVersion` = `1.0.0.0`（四段）。

### `3.1.40` — 2026-11-01 · 无脸帧直接透传（历史轴，**按用户要求未装机**）

| 变更 | 对读者的影响 |

该行为已随源码进入 CPU `1.0.0.0`，但**未在 CPU 版本轴上重新跑 A/B**（待人工确认）。

## 3. 升版本操作清单（可执行）

1. 改 `01_源码\beauty_params.h` 的 `BEAUTY_BUILD_STR`（唯一出处），按规则递增：普通升级第四位 +1，大版本第一位 +1 其余归零。
2. 同步 `06_安装包\build_setup.ps1` 顶部四个 `$*Ver`、`06_安装包\e2e_test.ps1` 的 `$Setup` 文件名、`06_安装包\obs-beauty.nsi` 的 `!ifndef` 兜底默认值。
3. 用 `BEAUTY_OUTDIR` 编两件 DLL 到新产物目录，再用 `BEAUTY_BUILD_OUT` 打包。
4. 跑版本串自检（脚本内自动）、核对版本资源四段、跑 `e2e_test.ps1`。
5. 更新本文件「当前有效结论」表与根 `README.md` §0，`docs/INDEX.md` 的「适用版本 / 最后核对」列。
6. `python 05_验证\check_upload.py --staged` 过闸门后再提交。
