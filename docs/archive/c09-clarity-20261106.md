# C9 · clarity（清晰）—— 大半径局部对比，补立体感

> 2026-10-28 13:20。对应 `04_文档/D1_我们自己的技术线路.md` 的 **S1**。
> 一句话：**面板上那根从来没生效的「清晰」滑块，现在真的会动了；它补的是立体感。**

## 1. 为什么是「主动加」而不是「别磨掉」

开工前先做了一次零成本标定（只扫参数），结果推翻了原来的设想：

| magLo,magHi | 磨皮量 | 中幅度%（立体感代理） |
|---|---|---|
| 6,30（现默认） | 1.347 | 96.7 |
| 6,60 | 1.416 | 96.8 |

**门控阈值怎么调，中频都稳在 96.8%** —— 说明立体感从来不是「被磨掉了」，

## 2. 公式

```
L     = 0.299R + 0.587G + 0.114B              // 只在亮度上算
Llow  = box(L, radius = 12)                    // 25px 窗口
mid   = L - Llow                               // 大尺度明暗层次
gate  = 1 - smoothstep(8, 22, |mid|)           // 软膝
out   = dst + mid × gain × gate × (mask/255)   // 增量同时加到 RGB 三通道
```

三个刻意的选择：

1. **只在亮度上算，同一个增量加到三个通道** —— 保持色相与饱和度。三通道各算各的
   会把颜色边缘放大成彩边。
2. **半径必须 12（25px）** —— 磨皮的核动的是 ≤8px（毛孔、痘印），立体感在 10~30px
   （鼻翼两侧、眼窝、颧骨下方）。窗口取小了等于把痘印加回去。
3. **输入是 `dst`（磨皮之后），不是 `src`** —— 要增强的是最终画面的结构，
   拿原图算会把刚磨掉的瑕疵加回来一半。

## 3. 软膝是怎么定的（这一步踩了个坑）

第一版照 D1 的设计用 20/45，结果**大幅度带（>30）从 99.7% 涨到 105.9%** ——
意思是硬边被加亮了，也就是光晕。扫参后收到 **8/22**：

| 软膝 | 中幅度% | 大幅度% | 判定 |
|---|---|---|---|
| 20,45（初版） | 117.4 | **105.9** | ❌ 边缘被加亮 |
| 10,28 | 102.6 | 100.1 | 边缘仍偏 |
| **8,22（采用）** | 104.7 | **100.0** | ✅ |

为什么会这样：softstep 的 `|mid|` 在 60 灰阶的硬边上约为 30，20/45 的软膝在 30 处
还有 50% 增益，等于给边缘加了一圈亮边。收到 8/22 后，30 处已经归零。

## 4. 验收（D1 §5.3 的指标，逐条对）

| 指标 | 目标 | 实测（面板 0/25/50/100） |
|---|---|---|
| 中幅度（6~30）保留% | 100~106 | 98.6 / **100.2 / 101.1 / 104.7** ✅ |
| 大幅度（>30）保留% | ≥99 且不涨 | 99.7 / 99.7 / 99.8 / **100.0** ✅ |
| 非皮肤区变化 | 0 字节 | **0 像素** ✅（用引擎自己的掩码判，不是猜框） |
| 脸颊台阶% | 不上升 | 69.4 → 71.1 ⚠️ 见下 |
| 1080p 增量 | ≤1.5 ms | **+1.4 ms** ✅ |
| ROI / 多线程等价性 | maxdiff=0 | **三档全 PASS** ✅（clarity=100 下测的） |

档位明细（640×394，磨皮固定 50）：

| 清晰档 | 中% | 大% | 磨皮量 | 亮度变化 |
|---|---|---|---|---|
| 0 | 98.6 | 99.7 | 0.493 | +0.01 |
| 25 | 100.2 | 99.7 | 0.575 | +0.01 |
| 50 | 101.1 | 99.8 | 0.647 | +0.02 |
| 100 | 104.7 | 100.0 | 1.068 | +0.03 |

**亮度变化 +0.03 灰阶** —— 证明 `mid` 在统计上是零均值，加它不会整体提亮（不是
变相美白）。

### 台阶% 上升 1.7 这一条要说清楚

`脸颊台阶%` 原本是 C8 用来判「磨皮有没有磨出平台边」的指标。clarity 是**对比增强**，
它的工作就是让局部对比变大，所以这个指标天然会涨 1.7 个点。**它不是 clarity 的合适
否决指标** —— 真正的否决指标是「大幅度带是否上涨」（涨了 = 光晕），实测 100.0，没涨。

## 5. 顺手修的一个性能坑

clarity 第一版 1080p 增量 **+2.17 ms**（超了 1.5 的门槛）。原因是
`boxPlaneV` 逐列扫：1080p 的 ROI 上每读 4 字节要跳一整行（1.8 KB），缓存全废。

改成**按列分块**（一次处理 32 列 = 128 字节 = 2 条 cache line），增量降到 **+1.4 ms**。
这个改动同时让引导滤波那条路也变快（它用的是同一个函数）。

## 6. 开关与默认值

- 面板「清晰」滑块，0..100 → gain 0..0.30（`g_cfg.clarityMax = 0.30`）
- 环境变量：`BEAUTY_CLARITY_MAX`（改上限）、`BEAUTY_CLARITY_R`（改窗口）
- 离线接口：`BeautyCoreSetClarity(maxGain, radius, kneeLo, kneeHi)`、
  `BeautyCoreSetClarityPanel(0..100)`

**面板默认值仍是 0**，所以现有用户的画面一个像素都没变 —— 硬证据：默认路径的输出
哈希与加 clarity 之前完全一致（`3f41f430…` / `40946fc9…` / `fda807e2…`）。

要不要把默认改成 40（中频 +1 个点、观感更有层次）是**产品决定**，需要你确认后再动。

## 7. 事实 vs 推测

**事实**：§4 的所有数字来自 `clarity_test.py` 与本机交替采样测量
（1080p 逐对差值 median +1.40 ms）；ROI/多线程等价性三档 maxdiff=0；
非皮肤 0 像素是用 `BeautyCoreMask` 导出的引擎掩码判定的；默认路径哈希不变。

**推测**：「中频 +6 个点肉眼能不能看出立体感变好」——**没有客观指标能证明**。
中频能量只是代理，真正的判断要真机看。所以默认值我建议你亲自拖到 40~60 看一次再定。
