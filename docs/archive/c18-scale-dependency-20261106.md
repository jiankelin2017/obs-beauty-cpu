# C18 分辨率 / 脸大小依赖：假说部分证实

日期：2026-10-29
脚本：`06_离线验证/scale_test.py`
上游：C17（离线说我们"削过头"）与真机 4 张（说我们"削不够"）结论相反

## 1. 为什么要做这个实验

| | 素材 | 脸宽 | 结论 |
|---|---|---|---|
| 离线 C17 | `face_src` 640×394 | **111px** | 我们**削过头**（额头细 −17.6） |
| 真机 4 张 | 1920×1080 | **≈550px（5 倍）** | 我们**削不够**（50 档 +23.3%、100 档 +15.8%） |

假说：我们的核是**绝对像素尺度**（`boxRadius=2`、σ≈2px，与分辨率无关的常量），
在更大的脸 / 更高分辨率上相对尺度只有 1/5，自然削不动；SDK 大概率按脸大小自适应。

实验：把同一张 `face_src` 用 LANCZOS 放大到 k 倍，再对拍 core 与 SDK。
同一输入喂两边，插值带来的高频变化在两边相同，**差值可比**。

## 2. 结果

细 / 阴影 = 四区域（额头/鼻翼/脸颊/眼区）平均保留率 %，差 = core − SDK
（负 = 我们削过头，正 = 我们削不够）。

| k | 脸宽 | 档 | 细 core/SDK/差 | 阴 core/SDK/差 |
|---|---|---|---|---|
| 1 | 111px | 50 | 76.6 / 75.5 / **+1.1** | 99.5 / 99.1 / **+0.4** |
| 1 | 111px | 100 | 51.5 / 60.7 / **−9.2** | 98.9 / 96.4 / **+2.5** |
| 2 | 222px | 50 | 81.1 / 77.7 / **+3.5** | 99.0 / 96.7 / **+2.3** |
| 2 | 222px | 100 | 53.3 / 66.8 / **−13.5** | 97.6 / 87.6 / **+10.0** |
| 5 | 556px | 50 | 97.8 / 95.3 / **+2.6** | 99.4 / 92.5 / **+6.9** |
| 5 | 556px | 100 | 90.1 / 88.7 / **+1.4** | 98.0 / 76.2 / **+21.8** |

真机实测的脸颊阴影分组差 **+10%**。

## 3. 读法：只有阴影频带可信

**阴影频带随脸宽单调扩大，假说在这一频带上成立**：

```
脸宽 111px → 222px → 556px      d阴 = +2.5 → +10.0 → +21.8   （单调）
```

真机的 +10% 落在 k=2 附近（k=5 是 +21.8）。考虑到真机是 JPEG、有摄像头噪声、
且脸颊单区域与四区域平均口径不同，这个量级差异在预期内。

**细频带的 k=5 数字不可用**：LANCZOS 放大让相邻像素高度相关，
细频带（|Y − box1|）的能量本身趋近 0，两边保留率都跑到 90%+，指标失去分辨力。
所以"k=5 细差 +1.4"不能当作"细纹理已对齐"的证据。

**50 档的方向在 k=2 就与真机一致**（core 保留更多，+3.5），100 档的翻转
（k=1 −9.2 → k=5 +1.4）受上面这条口径失效影响，不足以单独下结论。

## 4. 结论

1. **分辨率 / 脸大小依赖确实存在**，证据是阴影频带的单调扩大。
   我们的核不随脸大小缩放，脸越大，削不动的大尺度明暗越多。
2. 这一条比 C17 的 `magHi 60→40` 重要得多：后者像素级只有 0.022 灰阶（肉眼不可见），
   前者在真机上是 +10% 的阴影差距。
3. 落地方向：**核尺度随脸框宽度自适应**（σ ∝ 脸宽），而不是继续调固定值。
   固定值换个分辨率 / 换个机位就失效。

## 5. 一个可比性风险（未排除）

`NamaGoldenRun` 的后 4 个参数是 `blurType, skinDetect, smoothMode, resetSlot`
（见 `00_源码/golden_capture.cpp:11-12`）。离线跑的是 `1, 1, 0, 1`：

| 参数 | 值 | 含义（obs-beauty.cpp:579 / :589 / :596） |
|---|---|---|
| blurType | 1 | 双边滤波（**最强**·推荐，实测细节能量 2.358 最低） |
| skinDetect | 1 | 精准美肤开启（**只磨皮肤，更弱更自然**） |
| smoothMode | 0 | 人像磨皮（默认） |

真机的第三方 2.4.2 插件默认配置**未知**。若它没开"精准美肤"，
SDK 侧会更强，离线对拍的参照曲线就偏弱。**这一条未核实。**

## 6. 下一步建议

**最高优先级是换成真实摄像头帧做对拍。** 本轮已证明素材属性（分辨率、脸大小、
相机 vs 摄像头成像）是决定结论方向的关键变量 —— 继续在 `face_src`
（640×394 相机特写）上调参，本质上是在错误的素材上过拟合。

具体：抓 1 张摄像头原始帧 PNG（1920×1080，脸宽 550px 量级），
用它同时跑 SDK 与 core 的 0/50/100，出与本文同口径的表。
