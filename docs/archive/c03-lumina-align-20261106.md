## 0. 结论

**四项里落地了两项半，一项经实测判定「在我们的架构上无效」并给出原因。**

| 维度 | 落地内容 | 实测效果 |
|---|---|---|
| 边界与五官保护 | 椭圆软边肤色判据 + YuNet 关键点椭圆保护区 | 眼睛区磨皮降到 81.8%、嘴周 60.8%、**额头对照区 100.0% 不变** |
| 肤色与色彩还原 | CbCr 色度平面椭圆判据 + 亮度门控 | 掩码中间值从 0 → 1830 px，磨皮量跳变 99% 分位 3.67 → 3.33 |
| 鲁棒性 | 暗部不算皮肤（`smoothstep(0.12,0.30,Y)`）| 阴影、鼻孔、发缝不再被当肤色 |
| ~~立体感~~ | 阈值软膝**实测无效，默认关闭** | 见 §4 —— 这条暴露了我们真正的短板 |
| 未做 | 美白保色相、clarity（中频对比） | 见 §5 |


看的是 `src/engine/LmPipeline.cpp` 内嵌的 `kComposeShader` 与 `LmTuning.cpp` 的参数表。
关键的四行：

```glsl
// 1) 肤色：色度平面上的椭圆 + 软边 + 亮度门控
vec2 d = (vec2(cb,cr) - vec2(-0.065, 0.095)) / vec2(0.075, 0.070);
float m = (1.0 - smoothstep(0.6, 1.3, length(d))) * smoothstep(0.12, 0.30, y);

// 2) 五官保护：区域权重 × 保护强度
float smoothAmount = skin * uSmooth * (1.0 - protect * uSmoothProtect);

// 3) 立体感：只抹小幅度起伏
float limit = 1.0 - smoothstep(uSmoothThreshold, uSmoothThreshold*2.5, length(src-smoothed));

// 4) 美白保色相：混入「只提亮度」的版本
whitened = mix(whitened, lumaOnly, uWhitenHueKeep);
```

它自己的注释也点出了一条我们踩过的问题：

> 肤色判断用磨皮模糊后的颜色并在邻域取平均：原图色度是 2x2 采样的，直接判断时
> 肤色区边界呈锯齿，磨皮强度跟着锯齿突变，鼻梁侧面这类明暗交界处会出现台阶状的硬边

## 2. 肤色判据：矩形窗 → 椭圆软边

改造前：
```cpp
return (Cr >= 133 && Cr <= 173 && Cb >= 77 && Cb <= 127 && ...);   // 布尔
```
改造后（`skinWeight()`）：椭圆 + `smoothstep` 软边 + 亮度门控，返回 0..255 连续值。

**两个理由**：
1. 矩形窗在 (Cb,Cr) 平面的**四个角**会误判 —— 那些组合真实肤色里不存在；
2. 硬 0/255 让磨皮强度在掩码边界**瞬间跳变**，观感上就是台阶。

A/B 实测（`BEAUTY_SKIN_HARD=1` 切回旧判据）：

| 指标 | 矩形窗（旧） | 椭圆软边（新） | 变化 |
|---|---|---|---|
| 掩码中间值像素 | **0 px** | **1830 px（占非零 10.1%，共 249 级）** | 边界从硬切变渐变 |
| 非零覆盖 | 6.91% | 7.20% | +0.29%（过渡带） |
| 磨皮量跳变 90% 分位 | 1.667 | **1.333** | **−20%** |
| 磨皮量跳变 99% 分位 | 3.667 | **3.333** | −9% |
| 磨皮量跳变均值 | 0.7419 | 0.7159 | −3.5% |

> 注：「磨皮量低差值区不变」这条在软边上体现为 100.0%，见 `mask_soft_edge.py`。

## 3. 五官保护：YuNet 5 点 → 椭圆保护区

**前提**：我们原来只解析了 bbox，YuNet 的 5 个关键点（右眼/左眼/鼻尖/右嘴角/左嘴角）
一直在输出里被丢掉。这一步先把 `kps_%d` 解出来（与 bbox 同构：`(row/col + 值) × stride`）。

然后在眼睛和嘴巴上各画一个软边椭圆：

```cpp
ex = f.w * 0.12f;  ey = f.h * 0.075f;              // 眼睛椭圆半径
mrx = |kps[8] - kps[6]| * 0.5f + f.w * 0.05f;      // 嘴巴按嘴角距定宽
paintProtectEllipse(...);   // weight = 1 - smoothstep(0.35, 1.0, du²+dv²)
```

磨皮权重乘 `(1 - protect × protectK/100)`，`protectK` 默认 80。

**分区实测**（`BEAUTY_PROTECT_K=0` 关闭做对比）：

| 区域 | 关闭时磨皮量 | 开启（k=80） | 相对 |
|---|---|---|---|
| 眼睛区 | 0.618 | 0.505 | **81.8%** |
| 额头区（对照） | 0.443 | 0.443 | **100.0%** |
| 嘴周区 | 0.739 | 0.449 | **60.8%** |

两个版本输出有差异的像素 755 个，范围 x 306~375 / y 130~201 —— 正好覆盖眼睛到嘴，
没有扩散到额头。**「只保护五官、不动皮肤」这条成立了。**

> 踩坑：第一次分区时我把参照区选在「脸颊 y 175~225」，结果测出 78% —— 因为脸只有
> 134 px 高，那个位置正好和嘴巴椭圆重叠。**对照区必须选眼睛上方（额头）。**

## 4. 立体感：阈值软膝实测无效（这是本轮最重要的发现）

然后发现它**完全不起作用**：

| thr | 总磨皮量 | 高差值区 | 低差值区 | 整体变化 |
|---|---|---|---|---|
| 0（关） | 0.0319 | — | — | — |
| 15 | 0.0319 | 99.8% | 100.0% | 99.9% |
| 30 | 0.0319 | 100.0% | 100.0% | 100.0% |
| 50 | 0.0319 | 100.0% | 100.0% | 100.0% |

**原因**：全帧平均 `|src-smoothed|` 只有 **0.064/255**。我们用的是 **r=2 的双边滤波**，
大半径高斯 —— 它的 `|src-smoothed|` 本来就大得多。

**这条推翻了一个隐含假设**：立体感的差距不是「磨皮把明暗过渡抹平了」，因为我们的磨皮
（`col += (luma(src)-luma(blur)) * clarity * midtone`），不是被动保护。

所以软膝默认关闭（`limitThr = 0`），能力保留给「以后换成大半径核」时用。

## 5. 还没做的两项

|---|---|---|---|
| **美白保色相** | 三通道 log 提亮会偏色，所以再算一个「只提亮度」的版本 `col × (亮度提升比例)`，两者按 `uWhitenHueKeep` 混合 | CoreEngine **还没有美白**（面板有滑块，引擎未实现） | 中 |
| **clarity（中频对比）** | `col += (luma(src)-luma(blur)) × clarity × midtone × (1-0.5×skin)`，只作用中间调避免高光/暗部溢出 | 无 | 中，需要一次额外的大半径模糊 |

`whiten_rosy` 也值得抄：`col += whitish × skin × vec3(0.6, -0.35, 0.1)` —— 提红、**压绿**、略加蓝。
我们现在的红润只有抬 R 压 B，缺了压 G 这一项。

## 6. 性能

| 配置 | 1080p 30fps 均摊 |
|---|---|
| C2（门控 + 无五官保护 + 矩形窗） | 7.11 ms |
| C3（门控 + 五官保护 + 椭圆软边） | **6.8 ~ 8.4 ms**（多次测量波动 ±1 ms） |

**五官保护的开销在噪声内**：椭圆只在检测帧画一次（覆盖 0.68% 画面），
`blendWithMask` 里只是多一次乘加。椭圆软边判据是 float 运算，代价约 0.2 ms。

## 7. 开关一览（离线调参 / A/B）

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `BEAUTY_SKIN_HARD` | 0 | 1 = 回到旧矩形窗判据 |
| `BEAUTY_PROTECT_K` | 80 | 五官保护强度，0 = 关闭 |
| `BEAUTY_LIMIT_THR` | 0 | 阈值软膝，0 = 关闭（实测无效） |
| `BEAUTY_EDGE_K` | 10 | Sobel 边缘门控 |

对应导出函数：`BeautyCoreSetProtectK` / `BeautyCoreSetLimitThr` / `BeautyCoreSetEdgeK`。

验证脚本：`protect_test.py`、`limit_knee_test.py`、`mask_soft_edge.py`、`edge_gate_test.py`。

## 8. 事实 vs 推测

**实测**：上表所有数字、三档哈希一致性（`verify_roi.py` 全 PASS）、
`|src-smoothed|` 平均 0.064、五官保护的分区比。

**未验证**：
- 关键点椭圆尺寸（`0.12/0.075`、嘴宽 `0.05`）是**按脸框比例估的**，没做过参数扫描。
  YuNet 只给 5 个点没有轮廓，换素材（侧脸、低头）可能偏。
- 观感层面「保护到 80% 够不够」需要肉眼确认。
- 只在 `face_src` 一张上做了分区验证。
- 评分表里「立体感 8 分」的具体扣分项未知，我是从「缺 clarity」推断的，可能与评分者的判断不一致。
