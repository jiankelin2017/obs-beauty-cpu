# C6 · 美白 / 红润（补齐面板功能）

> 2026-10-28 · 面板一直有「美白」「红润」两个滑块，但 CoreEngine 从未实现
> —— 用户在自研引擎路径上拖这两根滑块没有任何反应。这是功能缺失，不是效果调优。

## 0. 结论

| 项 | 结果 |
|---|---|
| 美白提亮 | 面板 30/60/100 → 肤色区亮度 **+12.4 / +20.7 / +28.3** |
| **色相偏移** | **0.26° ~ 0.27°**（几乎为零，保色相成功） |
| 非皮肤区 | 变化 **0**（一个字节都不动） |
| 红润 | 面板 100 → **ΔR +13.7 / ΔG −8.3 / ΔB +1.8**（提红压绿） |
| 性能（1080p） | **+1.8 ms** |

## 1. 算法

### 1.1 美白：对数曲线 + 保色相


```
beta = 1 + whiten × 2
v'   = log(v·(beta−1) + 1) / log(beta)
```

对数提亮的好处：暗部提得多、高光不过曝，两端点（0 和 255）固定不动。

**关键在保色相**：三通道各自套同一条曲线，提亮比例不同 → 会偏色。
所以再算一个「按亮度等比例缩放」的版本：

```
l       = 0.299r + 0.587g + 0.114b
newL    = lut[l]
scale   = newL / l
lumaOnly= {r·scale, g·scale, b·scale}     // 色相、饱和度都不变
结果    = mix(逐通道提亮, lumaOnly, hueKeep=0.85)
```

实测色相偏移 **0.26°**，肉眼不可辨。

### 1.2 红润：提红压绿

```
dst += whiten × rosy × skin × (0.6, −0.35, 0.1) × 0.10
```

注意**压绿**这一项 —— 我们之前只有「抬 R 压 B」，缺了压 G，所以红润做出来偏橘不发粉。
系数 0.10 是按面板 100 档时 ΔR≈+14 反推的。

### 1.3 用查表避开 log

`log()` 逐像素调用在 1080p 上是百万次，受不了。改成 256 项 LUT，每帧构建一次
（256 次 log，可忽略），逐像素只剩查表 + 乘加。

## 2. 与旧引擎实现的区别

`legacy_engine.cpp` 里有一个 `applyWhiten`（v1.4 老路径），但不是同一个东西：

| | 旧 `applyWhiten` | 本实现 |
|---|---|---|
| 曲线 | 钟形 `v + v(255−v)k` | 对数 `log(v·(β−1)+1)/log β` |
| 保色相 | ❌ 三通道独立 → 偏色 | ✅ 混入 lumaOnly |
| 掩码 | 4×4 降采样 + 3×3 羽化 | **直接用自研软边肤色掩码**（0..255 连续值） |
| 红润 | 无 | ✅ 有 |
| 提亮上限 | kMax = 0.19 | 面板 100 时约 +28 灰阶 |

旧实现的掩码要降采样再羽化，是因为它拿到的只有二值判据；我们的掩码本来就是软边，
直接当权重用，省两个 pass 且边界更准。

## 4. 处理顺序

```
磨皮（高低频） → blendWithMask → 美白/红润
```

美白放在磨皮**之后**：先提亮再磨皮的话，提亮产生的梯度会被双边再平均一遍，
效果会被削弱。

无脸（`haveMask == false`）时整帧不做美白 —— 与旧引擎「没人脸就不全局提亮」一致，
也避免把背景墙一起提亮。

## 5. 性能

| 分辨率 | 无美白 | 美白60+红润30 | 增量 |
|---|---|---|---|
| 640×394 | 9.75 ms | 9.92 ms | +0.17 |
| 720p | 14.62 ms | 15.70 ms | +1.08 |
| 1080p | 23.26 ms | 25.08 ms | **+1.82** |

（这组是含检测帧的绝对耗时；30fps 均摊口径下 1080p 约 **9.5 ms**。）

开销集中在 ROI 包围盒的遍历 + 逐像素浮点。如果以后要压，可以把 LUT 改成整数定点，
预计能砍一半。

## 6. 事实 vs 推测

**实测**：上表全部数字、`verify_roi.py` 三档 maxdiff=0。

**未验证**：
- `hueKeep = 0.85`、粉调系数 0.10、beta 斜率 2.0 都是按「面板 100 时 ΔR≈+14、
  亮度 +28」反推的，**没做主观观感调优**。
- 深肤色上的表现没测（对数曲线在暗部的提亮比例更大，可能过白）。
- 与旧引擎（SDK 路径）美白效果的观感一致性没做对比 —— 两条路径的曲线不同，
  同一个面板档位出来的亮度不一样。
