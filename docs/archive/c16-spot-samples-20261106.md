# C16 · 方案 B：合成阳性样本，定量「痘印 / 鼻翼阴影 / 唇纹」抹不抹得掉

> 日期 2026-10-29 · 脚本 `06_离线验证/spot_test.py`
> 前置：C14（画质差距定量分解）、C15（C 方案盒式低通）

---

## 1. 为什么必须合成

C14 留下一个没法回答的问题：用户实机 A/B 说「额头痘印、鼻翼阴影、嘴唇纹理全留着」，
但**离线素材里根本没有痘印**。263 张相机照片（`D:\100MSDCF`）扫过一遍也全是合影 /
舞台灯 / 侧脸，一张阳性样本都没有。

没有因变量就测不了「痘印被抹掉多少」—— 测出来 100% 保留也算通过，是**假通过**。

所以自己造因变量：在现有 `640x394.raw` 的脸上叠加**已知强度、已知尺寸**的缺陷，
再让 SDK 与 core 各跑一遍，量缺陷还剩下多少。

---

## 2. 合成参数（按真实量级取）

人脸框宽 111 px ≈ 真实 15 cm ⇒ **1 px ≈ 1.35 mm**。

| 缺陷 | 类型 | 尺寸 | 深度 | 真实尺度 |
|---|---|---|---|---|
| 额头痘印·大 | 高斯暗斑 | 直径 7 px | −22 灰阶 | ≈0.9 cm |
| 额头痘印·小 | 高斯暗斑 | 直径 4 px | −13 灰阶 | ≈0.5 cm |
| 脸颊痘印 | 高斯暗斑 | 直径 5 px | −18 灰阶 | ≈0.7 cm |
| 鼻翼阴影·左/右 | 椭圆暗带 | rx 2.2 / ry 7 px | −12 灰阶 | ≈1.9 cm 高 |
| 唇纹 | 竖直条纹 | 周期 5 px | ±8 灰阶 | 见 §3 的尺度限制 |

色偏：痘印按炎症后色沉取 **R×0.80 / G×1.00 / B×1.20**（偏红棕，不是纯灰斑）。
位置全部经人工复核，确认落在脸部皮肤上（不落在背景 / 头发 / 衣服）。

## 3. 度量口径：用差值图，不用绝对深度

**第一版踩的坑**：直接量「合成图的中心−环形亮度差」，在额头痘印·大上失真 ——
那块皮肤本来就比周围亮 20 灰阶，痘印压下去后净深度只剩 2.37，基数接近 0，残留率没法算。

改成同一档磨皮分别跑原图与合成图，取差：

```
diff = 引擎(合成图) − 引擎(原图)
```

这个 `diff` 就是「缺陷经过磨皮之后还剩多少」，原图本身的纹理被完全抵消。

- **缺陷强度** = `diff` 上中心 3×3 与环形（6~11 px）的亮度差，负值 = 仍是暗斑
- **残留%** = 磨皮后强度 / 磨皮前强度 × 100
- **残留灰阶** = |磨皮后强度|，人眼能否察觉看这个：<1 基本看不见，2~3 凑近能辨，>5 明显

### 唇纹的尺度限制（必须知道）

真实唇纹间距约 0.3~0.8 mm，**不足 1 px，这个素材的分辨率根本表达不了**。
所以唇纹是「放大版代理」：周期 5 px（≈6.7 mm）。它测的是「条状中等尺度纹理
能不能被磨掉」，不等于真实唇纹。

度量改用 `std(Y − box21)`，因为周期 5 px 的正弦在 `|Y − box3|` 细频带里会被
3×3 均值削掉八成 —— 第一版实测只增加 0.85，信噪比不够。

## 5. 结果（残留% ，越小 = 抹得越干净；倍数是 core / SDK）

### 5.1 磨皮 50 + 祛斑痘 0 ← 用户实机 A/B 的档位

| 缺陷 | SDK 残留 | core 残留 | 倍数 |
|---|---|---|---|
| 额头痘印·大 | 83.5% | 86.8% | 1.04x |
| 额头痘印·小 | 69.9% | 72.6% | 1.04x |
| 脸颊痘印 | 79.4% | 79.6% | 1.00x |
| 鼻翼阴影·左 | 85.6% | 85.5% | 1.00x |
| 鼻翼阴影·右 | 87.9% | 86.2% | 0.98x |
| 唇纹 | 78.5% | 81.7% | 1.04x |

**两者几乎完全一样（0.98~1.04x）。** 在磨皮 50 这一档，痘印与鼻翼阴影**不是**
core 与 SDK 的差距来源 —— SDK 自己也只削掉 12%~20%。

### 5.2 磨皮 50 + 祛斑痘 50

| 缺陷 | SDK 残留 | core 残留 | 倍数 |
|---|---|---|---|
| 额头痘印·大 | 87.1% | 84.1% | 0.97x |
| 额头痘印·小 | 95.1% | 69.8% | 0.73x |
| 脸颊痘印 | 99.3% | 77.2% | 0.78x |
| 鼻翼阴影·左 | 115.3% | 84.1% | 0.73x |
| 鼻翼阴影·右 | 89.1% | 83.0% | 0.93x |
| 唇纹 | 110.9% | 71.4% | 0.64x |

### 5.3 磨皮 50 + 祛斑痘 100

| 缺陷 | SDK 残留 | core 残留 | 倍数 |
|---|---|---|---|
| 额头痘印·大 | 87.1% | 82.6% | 0.95x |
| 额头痘印·小 | 95.1% | 64.4% | 0.68x |
| 脸颊痘印 | 99.3% | 73.2% | 0.74x |
| 鼻翼阴影·左 | 115.3% | 82.3% | 0.71x |
| 鼻翼阴影·右 | 89.1% | 82.0% | 0.92x |
| 唇纹 | 110.9% | 66.8% | 0.60x |

祛斑痘一开，**core 反而比 SDK 抹得多（0.60~0.97x）**，且 50 与 100 相差很小
（说明 core 的祛斑痘在 50 档已接近饱和）。

SDK 侧出现残留 >100%（鼻翼 115.3%、唇纹 110.9%），最可能的解释是：
SDK 的 delspot 修的是**原图本来就有的天然斑点**，没把我的合成痘印识别为斑点，
于是 `diff = 合成痘印未被处理 − 天然斑点被提亮`，差值反而变大。

### 5.4 磨皮 100 + 祛斑痘 0 ← 拉满

| 缺陷 | SDK 残留 | core 残留 | 倍数 |
|---|---|---|---|
| 额头痘印·大 | 56.2% | 71.2% | 1.27x |
| 额头痘印·小 | 32.8% | 49.8% | 1.52x |
| 脸颊痘印 | 37.3% | 60.9% | 1.63x |
| 鼻翼阴影·左 | 70.4% | 72.7% | 1.03x |
| 鼻翼阴影·右 | 50.3% | 73.6% | 1.47x |
| 唇纹 | 74.6% | 70.6% | 0.95x |

**拉满时 SDK 明显更强（1.27~1.63x）。** core 在高档位的中频削弱不足。

## 6. 结论

| # | 结论 | 依据 |
|---|---|---|
| 1 | **磨皮 50 档下，痘印不是差距来源** —— SDK 与 core 残留差 0.98~1.04x | §5.1 |
| 3 | **我们的祛斑痘实现有效**，开到 50 就能把痘印残留压到 SDK 的 0.73~0.78x，但**面板默认 0（关）** | §5.2 |
| 4 | **磨皮拉满时 core 的中频削弱只有 SDK 的 0.61~0.79 倍**，怀疑 C15 加的档位饱和 `t·(1−0.16t²)` 偏大 | §5.4 |
| 5 | 两个指标互相印证：C14 频带口径 SDK 中频保留 83.9%，本次实测 SDK 痘印残留 83.5%，吻合 | §5.1 |

**最重要的一条**：第 1 条意味着 C14/C15 一直在调的「磨皮算子」，
对「痘印留着」这条反馈**没有直接责任**。真正该动的是**祛斑痘的默认值**。

---

## 7. 局限（不编造）

- 合成痘印是理想高斯斑，真实痘印常伴红肿边缘、隆起与毛孔改变，本测不了。
- 唇纹是放大版代理，真实唇纹在本素材分辨率下不可表达（§3）。
- SDK 的 delspot 未识别合成痘印，§5.3 的 >100% 是**推测**解释，未做消融验证。
- 只测了 640×394 这一张脸，遵照「素材只有一张脸时禁止过拟合调参」的纪律，
  上述结论**不能**直接用来调核参数。

## 8. 建议的下一步（按收益排序）

1. **装机 3.1.12 做真机验收** —— C15 的成果（五区域×三频带 1.92 pp）还没上机，
   用户真机看到的是 3.1.11 首版。装机前任何调参都是盲调。
2. **复核祛斑痘默认值** —— 现在默认 0，等于把「干净」的另一半关掉了。
   改之前先确认副作用（SDK 侧记录：帧间闪动 +56%、资源占用高）。
3. **复核档位饱和 0.16** —— 只在磨皮 100 附近暴露，用户常用 50 档影响有限。
4. 补真实素材（方案 A 摄像头直采 / 方案 C 开源数据集）后复跑本脚本验证。
