# C15 · C 方案：低通换成盒式迭代（滤镜 3.1.12 / CoreEngine 0.8）

> 产物：`beauty_smooth.cpp` 的 `boxRgbRoi()`、`beauty_freq.h` 的 `lowPath==3`
> 版本：滤镜 3.1.11 → **3.1.12**，CoreEngine 0.7.5 → **0.8**
> 状态：**已实现、已回归、已编译；真机未验收**

---

## 1. 一句话

把磨皮的低频层从「双边迭代」换成「盒式迭代」，**让保边这件事只由幅度门控负责一次**。

---

## 2. 为什么换低通就能解决

原来的链路里有**两道保边闸门叠在一起**：

```
低通 = 双边迭代  → 边缘处几乎不平均 → high = src−low 在边缘处本来就接近 0
门控 = 幅度门控  → |high| > magHi 完全不动
```

第一道已经把边缘的 `high` 压到接近 0，第二道再判一次「幅度小 → 磨」，
于是**瑕疵和结构一起被放过**。这就是 C14 里「脸颊只削 14%、SDK 削 37%」的机理。

换成盒式低通后，低通**完全不保边**（各向同性）：

- 真边缘（眉毛、唇线、鼻梁）：`|src−low|` 幅度大 → 门控拦住 → 仍然清晰
- 痘印 / 鼻翼阴影 / 唇纹：幅度中等 → 被削掉

保边职责收敛到一处，正是高低频分离原本的设计意图。

**为什么是盒式而不是可分离高斯**：`C1` 里记的「高斯 1080p 34 ms 超预算」指的是
19-tap 可分离高斯。盒式迭代是前缀和滑动窗，O(1)/像素、**成本与半径无关**，
迭代 3 次后波形已接近高斯（中心极限定理）。实测新低通比旧双边**更快**。

## 3. 扫参过程与三条反直觉结论

### 3.1 半径越大，磨得**越少**

| 盒式 r / iters（grain=0，magHi=60） | 脸颊细纹理保留率 |
|---|---|
| r=3 it=3 | 81.8% |
| r=4 it=3 | 83.1% |
| r=6 it=3 | 89.9% |
| r=8 it=3 | **98.6%** |

低通越糊 → `|src−low|` 幅度越大 → 越容易被 `magHi` 门控判为「结构」而放过。
**不要再靠加大半径去追强度**，方向是反的。

### 3.2 颗粒回填（grain）是「细纹理保留率」的最大单一来源

| grain（r=3 it=3，magHi=60） | 额头 | 鼻翼 | 唇 | 脸颊 |
|---|---|---|---|---|
| 0.0 | 66.9 | 77.5 | 96.2 | **60.9** |
| 0.25 | 73.7 | 81.3 | 96.3 | 71.6 |
| 0.5（旧默认） | 81.0 | 85.4 | 96.9 | **80.2** |

grain 0→0.5 就把脸颊从 60.9 抬到 80.2（**+19.3 pp**）。而它原本的存在理由
是「抑制**双边迭代**的阶梯感」——换盒式后阶梯感本就不存在。0.5 → **0.10**。

### 3.3 五官保护 protectK 的取舍依据是「眼区」，不是「唇」

| protectK（r=4 it=2） | 唇 | 眼区 | （SDK：唇 89.3 / 眼区 91.3） |
|---|---|---|---|
| 80（旧） | 96.7 | 93.5 | 唇差 +7.4 |
| 60 | 95.0 | 92.6 | |
| **40（新）** | **93.7** | **91.7** | 眼区差 +0.4，与 SDK 重合 |
| 20 | 92.6 | 90.9 | 眼区开始被磨得比 SDK 狠 |
| 0 | 91.5 | 90.3 | 眼区超磨 −1.0 |

**40 是「唇追得上、眼睛不吃亏」的拐点。** 降 protectK 能继续追唇，但代价是

## 5. 两个必须知道的取舍

### 5.1 尺度是按「三频带」选的，不是按细频带

只看细频带的话 `r=4 it=2` 更贴近 SDK（脸颊 65.0 vs 63.1），但它的中频会掉到
77.4、阴影掉到 94.0，而 SDK 是 83.8 / 96.8 —— **中频削太多就是「脸塌」**。

| 尺度 | 三频带平均绝对差 |
|---|---|
| **r=2 it=2（采用）** | **1.92 pp** |
| r=2 it=3 | 1.93 pp |
| r=3 it=2 | 2.86 pp |
| r=4 it=2 | 4.49 pp |

代价：脸颊细频带 71.2 vs SDK 63.1（**弱 8.1 pp**）。脸颊是本来就平整的参照区，
而用户抱怨的额头/鼻翼分别是 70.6 / 74.5（差 +0.6 / −3.1）。

### 5.2 档位饱和 `t·(1 − 0.16·t²)` 是单素材拟合

SDK 的档位曲线在高段饱和（脸颊 50→75→100 = 63.1→48.0→35.5，增量递减），
加饱和后 100 档从差 −12.1 pp 收到 −3.5 pp。

⚠️ 这条曲线只有 face_src 一张素材支撑。`BEAUTY_BLUR_SAT=0` 一键关掉回到线性。

## 6. 修掉的 bug：ROI 与全帧差 1 个灰阶

`verify_roi` 报 `maxdiff=1`。根因**不是逻辑错，是浮点累加的相位**：

盒式用滑动窗 `s += add − rem` 一路累加，float 舍入误差会累积。我加了「每 32 像素
重算一次窗口和」来截断误差，但**重算点用的是局部坐标** —— ROI 模式的局部 x=0 对应
全帧的 x=bx0，两边的重算点落在不同的全局坐标上，累加序列不同 → 舍入差 →
最后四舍五入到 uint8 时被放大成 1 个灰阶。真机上就是掩码边缘一圈接缝。

**修法**：`boxRgbRoi` 把 ROI 起点**下对齐到 32**（`alignDown32`），两模式的重算点
就落在同一批全局坐标上。多算的 ≤31 行列成本可忽略。

中途踩的坑：先试过给 `boxPlaneH/V` 传 `originX/originY` 参数按全局坐标判断，
结果漏了「首像素必须重算」—— 第一像素输出 0，maxdiff 反而涨到 18。已回退。

> 这条也解释了为什么 `grain` 才暴露它：grain 让 `d` 更容易落在四舍五入的边界上。

## 7. 诚实记录：像素级指标没那么好看

频带指标是「相对原图削了多少」，不关心削在哪。换成像素级的改动图对比：

| 指标 | 旧 core | 新 core | 理想 |
|---|---|---|---|
| 与 SDK 改动图的**相关系数** | 0.201 | **0.520** | →1 |
| 最优缩放 k（1 = 幅度一致） | 0.15 | **0.52** | →1 |
| 改动σ（SDK = 1.11） | 0.95 | **2.00** | →1.11 |

读法：新方案「削的位置」对了约一半（相关性从 0.20 提到 0.52，是实质改进），
但**幅度是 SDK 的约 1.9 倍**。SDK 磨皮 50 的改动本身很小（脸框内 RMSE 仅 1.32
灰阶），所以这个信噪比下的像素级指标只能当参考，不能当判据。

**未解决**：为什么幅度偏大。怀疑与素材分辨率有关 —— 素材脸只有 111×141 px，
而真机是 720p/1080p，SDK 的核在大脸上可能更强。**素材到位前不要继续调**，
调了就是过拟合。

## 9. 真机若反馈过磨 / 不够磨，按这个顺序动

1. **先只调 `BEAUTY_BLUR_SAT`**：过磨调大（0.16 → 0.30），不够磨调小（→ 0）。
   它只改档位映射，不动核、不动画质结构。
2. 再调 `BEAUTY_BOX_R`（1~3）：调大是**减弱**（§3.1），别记反。
3. **不要**动 `freqMagHi` 去追强度：§3.1 的机理决定了它与强度不成单调关系。
4. 唇纹还留着 → 降 `BEAUTY_PROTECT_K`，但**必须同时看眼区**（§3.3）。
