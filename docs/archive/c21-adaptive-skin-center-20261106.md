# C21 肤色椭圆自适应中心落地（C20 方案 A + B2）

> 滤镜 **3.1.13** / CoreEngine **0.9** ｜ 2026-10-29
> 前置：`C20_皮肤掩码白平衡依赖_真机磨皮不足的真正根因.md`

## 1. 落地了什么

C20 定位的根因是**肤色判据用了一个写死的椭圆中心**（抄自 MIT 版 lumina-beauty 的常量
`cb=-0.065, cr=+0.095`）。它在标准白平衡的相机素材上成立，但摄像头不保证白平衡 ——
真机帧平均 RGB 151/118/134（**B > G**，白平衡偏冷），整张脸被推出判据，
皮肤掩码只剩 34%~41%，磨皮强度掉到 SDK 的 1/8。

### 方案 A：中心逐帧自适应（主修）

新增 `estimateSkinCenter()`（`beauty_core.cpp`），在画掩码之前跑一次：

1. 取**最大脸框的中心 40%×40%** 采样（避开背景、头发、额头镜面高光）
2. 先按亮度粗筛（`Y ∈ [0.12, 0.94]`，排除鼻孔/发缝/过曝高光）
3. 迭代 2 次「取 cb/cr 中位数 → 用新中心剔除 `d < 1.5` 的离群点 → 再取中位数」
4. 采样不足（`<64` 点，或不足采样区 30%）→ 返回失败，保持上一帧/默认中心

`skinWeight()` 从读常量改为读全局 `g_skinCb / g_skinCr`。

### 方案 B2：半径缩放兜底（副开关）

椭圆半径提为 `g_skinRu / g_skinRv`，默认仍是 0.075/0.070。
自适应万一失效（极端光照）时可放宽半径保底。

### 新增环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `BEAUTY_SKIN_ADAPT` | **1（开）** | 0 = 回到固定默认中心 |
| `BEAUTY_SKIN_RADIUS` | 1.0 | 半径缩放，1.5 = 放宽 50%（B2 兜底） |
| `BEAUTY_SKIN_EMA` | **1.0** | 中心帧间平滑，见 §3 踩坑 |
| `BEAUTY_SKIN_HARD` | 0 | 旧矩形窗 A/B（原有） |

## 2. 验证结果

### 2.1 自适应算法本身（numpy 模拟先行，再落 C++）

| 配置 | 真机帧 mask | face_src mask |
|---|---|---|
| 现状（固定中心） | **41%** | 99% |
| **A 自适应中心** | **98%** | **99%** |
| A + B2 半径×1.5 | 99% | 99% |
| 仅 B2 半径×2 | 98% | 99% |
| 仅 B2 半径×1.5 | 92% | 99% |

迭代 1 次即收敛（2/3 次结果不变），故实现取 2 次留裕量。

**关键性质**：face_src 上估计出的中心 (−0.0631, 0.0956) ≈ 默认 (−0.065, 0.095)，
所以开启自适应**不推翻此前所有基于 face_src 的离线结论**。

### 2.2 face_src 未回归（哈希 A/B，磨皮 100）

```

adapt_off  md5=26d99169639a2707884ef75febfaaf91
```

与 C17 勘误值**逐位一致**，坐实未回归。

`verify_roi.py` **ALL PASS（maxdiff=0）**，640×394 / 720p / 1080p 三档。
2026-10-29 修订复验：两次连跑哈希逐位复现（基线 `b7fb312e…` / `4fb7a20e…` /
`7e0fb6c7…`，已收进 INDEX §6.1.4），`feather_ab.py` 能量 −6.28%（720p）与
3.1.10 判据一致 —— 修订（只加日志）没碰像素路径。

**真机自查新增出口**（3.1.13 修订）：首版的 `skin=` 只在 init 打一行，永远是
`(center=default, not yet estimated)`，10:39 真机日志实锤「之后没有第二行」——
beautyCoreSkinInfo() 只有 filter create 时被调用一次，没有周期性 re-log。修订加
`beautyCoreSkinAnnounce()`：worker 首次把估计中心写进全局时置 atomic 标志，
渲染线程 process 成功后取走并**补打一行不带括注的 `skin=`**。整会话至多打这一行

① init 行带括注（正常）；② 几秒内出现 §② 不带括注的一行 = 自适应真的在跑。
一分钟都不出现 → 按 `install_core_test.bat` 结算提示用 `BEAUTY_SKIN_ADAPT=0` 做 A/B。

## 3. 踩坑两处

### 3.1 EMA 破坏确定性（必须记住）

第一版给中心加了帧间 EMA 平滑（0.15），理由是"掩码中心跳变会让磨皮强度闪"。
结果 `verify_roi.py` 在 720p/1080p **maxdiff=1 FAIL**。

**根因**：EMA 让输出变成**调用历史的函数**。同一张图被重复处理（ROI 关→ROI 开→
多线程，三次 `BeautyCoreRun`）时，每次中心朝估计值挪 15%，而起点不同 → 掩码不同。
`verify_roi` 依赖的正是「同输入必同输出」这个纯函数性质。

实测定位：

| EMA | verify_roi |
|---|---|
| 0.15（初版） | 720p/1080p FAIL（maxdiff=1） |
| 0（首帧后冻结） | ALL PASS |
| **1.0（完全跟随）** | **ALL PASS** ✅ |

**结论：EMA 默认必须是 1.0（= 纯函数无状态）。** 只有 `0` 和 `1` 不携带历史。
真机若观察到磨皮强度逐帧闪，才设 `BEAUTY_SKIN_EMA=0.2` 压抖（代价是失去确定性，
且离线对拍会失真，只在真机场景用）。

顺带说明：估计值本身是确定性的（同输入同输出），闪烁的真实来源是检测 faces 坐标抖，
而中位数对噪声鲁棒 + 掩码每 4 帧才重算，实际闪烁风险低 —— 这也是敢默认 1.0 的依据。

### 3.2 匿名 namespace 内定义外部链接不到

`beautyCoreSkinInfo()` 初版定义在 `beauty_core.cpp` 的匿名 namespace 里（32–2045 行），
`obs-beauty.cpp` 链接报 LNK2019。这与文件里既有的 `beautyCoreSetSmoothParams` 是同一条
规则：**给外部用的函数必须定义在匿名 namespace 外面**（内部的 `g_cfg` / `g_skin*` 同 TU
仍可见）。已挪到 `}  // namespace` 之后。

## 4. 遗留问题（按优先级）

| # | 问题 | 现状 | 归因 |
|---|---|---|---|
| 1 | **100 档细纹理矫枉过正** | −16.0（脸颊 −24.9、眼区 −21.4） | C15 的档位饱和 `t·(1−0.16t²)` 是在**掩码 41%** 的失真前提下调的；掩码补到 98% 后强度全开，饱和系数需重标 |
| 2 | **阴影频带仍 +19.1** | 额头 +27.2 / 鼻翼 +25.5 | 已知双尺度缺口（C17 §6）：单一高 σ 低通削不动 7~21px 大尺度明暗，需双尺度 |
| 3 | 100 档耗时 26.3 ms | 50 档 13.4 ms | 含自适应采样 pass（约 8000 采样 × 2 次 nth_element，每 4 帧一次）；真机 48ms 疑点仍未解 |

**第 1 项的应急缓解（不改核参数，符合纪律）**：真机若 100 档过磨，调
`BEAUTY_BLUR_SAT`（现为 0.16）。**不要动 `boxRadius/boxIters/freqMagHi/protectK`** ——
那些是 C15 在掩码 95% 的素材上定的，而掩码前提刚被修正。
