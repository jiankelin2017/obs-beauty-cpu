## 0. 一句话结论

**仓库根目录 `LICENSE` 的逐字内容是 GPL-2.0；但「能否商用」「是否闭源分发」在仓库内存在三种互斥的历史口径（`README.md` §0、旧入口 §1、开源清单 §4），全部待人工确认。**

当前可安全执行的事只有两件：① 守住 `.gitignore` 排除闸门与提交前自检；② 引入任何第三方件前先在本表登记许可原文与分发方式。

## 2. 三处互斥的许可口径（全部待人工确认）

| 口径 | 出处 | 原文要点 | 与谁冲突 |
|---|---|---|---|
| **A · GPL-2.0 开源** | 根 `README.md` §0 事实表；`docs/archive/readme-archive-20261106.md`（`Deprecated`） §16.1 | 「动态链接 libobs → **GPL-2.0**（`LICENSE`）」；「按 GPL 传染性条款，**本插件源码须以 GPLv2 提供**」 | 与 B 的「不得再分发」、C 的「闭源分发」均冲突 |
| **B · 仅本地自用** | `docs/archive/readme-entry-20261106.md`（`Deprecated`） §1（历史仓库入口） | 「**个人学习、研究与本地自用**，不构成对外许可，**不得商用或再分发**」 | 与 A 的再分发义务、C 的商用选型前提冲突 |
| **C · 闭源且面向商用再分发** | `docs/archive/oss-survey-20261106.md`（`Deprecated`） §4；`docs/archive/opensource-boundary-20261106.md`（`Deprecated`） §1 | 「我们的插件是**闭源分发**的（有 NSIS 安装包）」；选型判据「**每一个第三方件的许可都允许商业使用与再分发**」 | 与 A 的源码须以 GPLv2 提供、B 的禁止商用冲突 |

**三者不能同时为真。** A 与 C 直接决定「`01_源码/` 能否公开、安装包是否必须附源码」；B 与 C 决定「能否对外分发」。
在这些口径未统一前，以下动作一律不做：对外发布许可声明、公开宣称可商用、把 GPL-2.0 参考仓库的代码抄进插件、
以「已获授权」为前提替换第三方模型或权重。

> 该冲突已同步登记为根 `README.md` §8 第 1 项；本文是它的唯一参考展开，不在别处重复裁定。

## 4. 不依赖许可结论、现在就能执行的约束

1. **.gitignore 是唯一排除闸门**：`参考文件/` 下的闭源商业 SDK、对照提取物、真人面部位图与 `.raw` 帧不入库；任何新增文件默认会被上传，先加规则再 `git add`；提交前跑 `python 05_验证\check_upload.py --staged`。*(当前可核对)*
2. **MIT 声明必须随文本保留**：`07_开源参考/` 的两份文本归档不得删掉版权与许可头；如需新增 MIT 组件，同样保留许可全文。*(当前可核对 + MIT 通行要求)*
3. **新增第三方件的前置动作**：先在本表 §1 / §3 登记「许可原文位置、版本、分发方式」，再改代码或改安装包。*(本批新立的维护约定)*
4. **GPL-2.0 参考仓库只读思路、不抄代码**：该红线来自 `docs/archive/oss-survey-20261106.md`（`Deprecated`） §4 与旧入口 §9，属历史口径，**待人工确认是否仍适用**；在 §2 的口径统一前，按保守方式执行（不抄）。
5. **参考 effect 文本不得当成构建资产**：`07_开源参考/MIT_wuxiwuhen_beauty_filter.effect.txt` 只读归档，不复制进 `01_源码/`，否则与当前「纯 CPU、不引入 shader」方向冲突。*(当前可核对)*
