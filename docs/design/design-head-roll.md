## 1. 结论先行

「脸检不出来 / 美颜跑偏」在这条产品线上有**四种互不相同**的原因，症状却长得一样（`faces=0`
或掩码糊错地方），排查时必须先分清是哪一种：

| # | 场景 | 真因 | 落点 | 版本 |
|---|---|---|---|---|
| 1 | 手机竖拍 / 竖屏采集卡，美颜**完全没效果** | 源被转了 90° 的整数倍：OBS 的场景项旋转只作用于**显示合成**，滤镜拿到的仍是横躺的原始帧 | 检测前合成旋转 + 框反变换 | `1.0.3.0` |
| 2 | 身体立正、**只有头歪 45°**，美颜失效 | YuNet 的**平面内倾斜**容忍边界在 30~40° 之间；更隐蔽的是「有框但框是错的」 | 候选角度合成检测 + `FaceBox` 带 `roll/rw/rh` | `1.0.5.0` |
| 3 | 旋转源上**下巴横着出去一条磨过的带子** | 脖子通道在源坐标里用 `+y` 当「正下方」，而源要转 270° 才立正 | `1.0.6.0` 止损、`1.0.7.0` 参数化成 `(u,v)` | `1.0.6.0` / `1.0.7.0` |
| 4 | 歪过 45° 再**回正后不归位**（形变方向仍歪着） | `roll` 锁定后唯一出口是「按锁定角检不到脸」，而 YuNet 在 −45° 输入下照样给框 → 永不释放 | 周期性 0° 对照释放 | `1.0.13.9` |

另有两条**过渡期专属**的观感问题，不属于上面的几何错误，但同一批场景才会遇到：

| 现象 | 机制 | 落点 |
|---|---|---|
| 歪头过渡时**画面闪 / 跳一下** | 掩码对齐路径命中时输出「上一帧画面」，未命中输出当前帧；worker 忙闲决定走哪条 → 两帧画面来回切 | `1.0.13.8` 加帧近似判定门控 |
| 歪头过渡时**卡一下** | 接上那帧在 ±45° 各跑一次 640×640 推理 | 见 §8「未解决」 |

**顺序不可颠倒**：先保证「检测拿到的是一张正立的脸」（§2、§4），再谈掩码画在哪（§5）、
锁定后怎么退出（§6）、过渡帧怎么不闪（§7）。反过来的调参都是在错误坐标上做微调。

## 2. 判据边界：YuNet 到底能容忍多少

这一节是后面所有设计的依据。两个边界必须记住：

- **90° 的整数倍**：YuNet 对躺倒的脸召回接近 0。这是 §3 存在的理由。
- **平面内倾斜**：30~40° 之间就守不住了。这是 §4 存在的理由。

**更麻烦的是中间那一档「有框但框是错的」**：真机方向（源需转 270°）下歪头 45°，只补方向不补
倾斜时，YuNet 仍会给出一个框、`detOk` 仍为真 —— 但框被撑大且偏移，双眼间距相对框宽明显偏小，
方向兜底与倾斜探测**都不会触发**，掩码照样糊错地方。所以「检出与否」不能作为唯一判据，
必须同时看框的形状是否像人脸（§4.3 的 `rollBoxPlausible()`）。

判据的量级（各角度的检出与框形状）见取证 `05_验证/ab20261109_head_roll.md`。

## 3. 输入方向：源被转过 90°（`1.0.3.0`，从 GPU 版 3.2.0 移植）

**症状**：采集设备竖着时（手机竖拍 / 竖屏采集卡）美颜**一点效果都没有**；换默认横屏机位就正常。

**根因不在掩码，在检测**：OBS 的「场景项 → 旋转」只作用于显示合成，滤镜拿到的 `in_tex` 永远是
设备原始的那一帧 —— 例如 1920×1080 里人横躺着。YuNet 对 ±90° 的脸召回接近 0，于是 `faces=0`、
掩码为空，磨皮/美白/红润全乘 0。日志里它和「模型没加载」长得一样，都是 `faces=0 / px=-1`，
所以此前一直按「检测坏了」排查。

**宿主拿不到场景项的 transform**（滤镜只看得见 target source 的纹理），所以「源有没有被转」
只能试：连续 `BEAUTY_AUTO_ROT_MISS`（默认 20）次检测无脸时，在同一张输入图上各跑一次 90°/270°
的重采样检测；认定方向后按该方向检测，再用 `invRotateFace` 把框与五点反变换回源坐标。
旋转做进 `letterboxRgb` 的重采样（`letterboxRgbRot`），**不额外分配旋转缓冲**。

| 项 | 结论 |
|---|---|
| 几何顺序 | 反变换必须早于 `estimateSkinCenter`（它拿 faces 采 src 真实像素）与 `fboxOut`（五官/美形段要用源坐标） |
| 掩码形状 | 反变换后框的宽高互换，画出来的轴对齐椭圆仍**内接**在躺倒的脸上（长轴对得上），不需要 GPU 那套 `MASK_ROLL` |
| 方向一变 | 立即清人脸框 EMA/迟滞（`resetFaceEmaState`），否则新框会被当成「遮挡跳变」压掉最多 6 帧，而那 6 帧用的是另一方向的旧坐标 |
| 换分辨率 | 宽高变了就把方向结论作废重来（同一台摄像头的结论不能套到另一路源） |
| 与 GPU 版差异 | GPU 是「先试 90，命中就收」。实测 YuNet 对**倒立脸**也会给出接近正常脸的分数，首命中有一半概率挑到翻转方向 —— 掩码仍在脸上，但五点跑到嘴的位置，亮眼/去黑眼圈/法令纹随之错位。本版两个方向都跑、**取分数高的** |
| 代价 | 认定方向前有约 0.7 秒没有美颜（同步检测每 4 帧一次时更长）；探测只在「连续无脸 + 冷却」时发生，正常人走开不会烧推理 |
| 开关 | `BEAUTY_AUTO_ROT=0` 关闭；`BEAUTY_INPUT_ROT=90/180/270` 手工声明；`BEAUTY_AUTO_ROT_MISS` / `_COOL` 调阈值 |
| 未覆盖 | 美形三项（瘦脸/大眼/下巴）仍按画面轴施加，旋转源上方向不对 —— GPU 版同样如此 |

取证：`05_验证/rot_input_20261108.md`（台架 `05_验证/_rot_probe/`）。

## 4. 平面内倾斜：头歪 45°（`1.0.5.0`）

> 用户报：人物**身体立正**、只有**头歪 45° 左右**时，美颜整体失效。

### 4.1 为什么必须单独处理

与 §3 是两件事：那个是 90 的整数倍，这个是 0~90 之间的任意角。§2 已给出边界，
§2 末段那个「有框但框错」才是真正难处理的一档。

### 4.2 `FaceBox` 的三个新字段

反变换回源坐标时，倾斜的框只能退化成**轴对齐外接矩形**（45° 时面积约为脸的 2 倍，几何常量）。
仅此一点就足以让掩码失效 —— 椭圆半轴被外接盒撑成正方形，等于画了个大圆。所以框自己带上：

| 字段 | 含义 | 未倾斜时 |
|---|---|---|
| `roll` | 平面内倾角（度），即本次检测用的合成角 | `0` |
| `rw` | 脸自身的宽（倾斜矩形的边长，非外接盒） | `0`（下游退回 `w`） |
| `rh` | 脸自身的高 | `0`（下游退回 `h`） |

**凡是「脸有多宽」的语义，都必须用 `rw/rh`，不能用 `w/h`。** 目前四处：掩码矩形/椭圆半轴、
羽化宽度、脖子宽度与起点、五官保护椭圆尺寸。`w/h` 只剩两种用途：外接盒边界（绘制范围）
与人脸框匹配（IoU / EMA）。

### 4.3 几何定义（与 `invRotatePoint` 同一组式子）

设脸中心 `(cx, cy)`、倾角 `roll`，源像素 `(x, y)`：

```
dx = x + 0.5 - cx          dy = y + 0.5 - cy
ux =  dx*cos(roll) + dy*sin(roll)      // 脸自身坐标系
uy = -dx*sin(roll) + dy*cos(roll)
矩形：|ux| < a 且 |uy| < b     （a = rw*grow/2，b = rh*grow/2）
椭圆：(ux/a)² + (uy/b)² < 1
到边界距离 ≈ min(a-|ux|, b-|uy|)
```

`roll = 0` 时 `cos = 1.0f`、`sin = 0.0f`（精确值），故 `ux ≡ dx`、`uy ≡ dy`，与旧式**逐位相同** ——
这是「0/90/180/270 与所有正立画面逐字节不变」的根据。**任何改动都必须先保住这条退化性质**。

### 4.4 脖子通道为什么一度保持竖直

用户报的场景是「**身体立正**、只有头歪」，脖子本来没歪；跟着斜框转反而会把脖子画到肩膀上去。
所以当时只把宽度换回 `rw`、起点换回脸自身的半高，方向仍是竖直。这个决定后来在旋转源上出了
问题（§5），最终由 `1.0.7.0` 用「正下方的源坐标单位向量」正式取代。

### 4.5 探测策略与假框门槛

| 项 | 值 | 理由 |
|---|---|---|
| 触发条件 | 连续 8 次「无脸 **或** 框不像人脸」 | 头歪是突发，要立刻补；`BEAUTY_AUTO_ROLL_MISS` 2~600 |
| 候选角度 | `+45°` / `-45°`（合成到方向角上） | 覆盖「0° 已检不到」那一段；每多一个候选多一次 640×640 推理 |
| 假框门槛 | `score ≥ 0.75`、双眼间距/框长边 ∈ `[0.25, 0.62]`、眼睛在嘴上面 | 反方向候选会让倾斜累加到 ~90°，那里 YuNet 吐的是像脸的纹理（假框分数与比值见取证文件） |
| 切换条件（已有框） | 候选分数需高 `0.05` 以上 | 否则两个角度来回跳，每跳一次清 EMA → 画面抖 |
| 记错怎么办 | `BEAUTY_AUTO_ROLL=0` 关闭；一旦按带倾斜的角度检不到，**当帧**退回不带倾斜再试，命中即清 | 与方向兜底同构 |

**没有门槛会更糟**：假框一旦被锁死，之后每帧都检不到脸，而且因为一直「有框」，
方向兜底也不会来救。

### 4.6 代价

歪头时磨皮 ROI 仍是斜框的**外接盒**（面积约 2 倍）。要彻底省掉得把 ROI 裁剪改成逐行 ——
band 路径现在是一次性裁剪 + 整块处理，属于另一个优化项目。修前/修后的掩码覆盖率与耗时
见 `05_验证/ab20261109_head_roll.md`。

## 5. 脖子通道在旋转源上的方向错误（`1.0.3.0` 起，`1.0.6.0`/`1.0.7.0` 修）

**现象**：源需要转 90°/270° 才立正时（本机摄像头正是这一档），画面里从下巴横着出去一条磨过的
带子，穿过肩膀落到窗帘上；真正的脖子没被磨到。

**成因**：`buildMaskInto` 最后在**源坐标**里逐像素落笔，脸框已经过 `invRotateFace` 反变换，位置
是对的；但脖子通道从脸框下沿往下时用的是源坐标的 `+y`（`neckTop = cy + hh`、
`ny1 = neckTop + bh * neck.len`）。源要转 270° 才立正时，源坐标 `+y` 在立正画面里是**横向**，
于是整条脖子被画到侧面去。

**为什么很久没发现**：`1.0.3.0` 才第一次让这台摄像头检出脸（此前「竖屏摄像头完全没效果」），
脖子通道的坐标方向没跟着那次改动一起修；带子落在窗帘上，不盯着看不出来。

**修法分两步：**

| 版本 | 做法 | 取舍 |
|---|---|---|
| `1.0.6.0` 止损 | 旋转源（`g_effRot % 180 != 0`）上整段不画脖子；另加 `BEAUTY_NECK=0` 无条件关闭 | 那条带子严格有害（背景被磨、脖子没磨），少画它任何指标都不更差 |
| `1.0.7.0` 真修 | 把「正下方」写成源坐标里的单位向量 `(dx,dy)`，几何全部参数化成 `(u,v)`：`u` 沿正下方、`v` 为横向，三种形状分支与羽化都只跟 `u/v` 走 | 顺带修掉两个换算错误 |

`1.0.7.0` 顺带修掉的两个换算错误：

1. **旋转源的宽高是交换过的**。270° 时检测框在源坐标里是 356×259 —— `bw=356` 是脸的纵向尺寸
   （脸高）、`bh=259` 才是脸宽。旧口径一律拿 `bw` 当脸宽，脖子会按脸的长边铺开。现在按
   `(dx,dy)` / `(lx,ly)` 投影算两个半跨度。
2. **脖子起点**改用「脸框沿正下方的下沿」（倾斜时按投影算，且含 `kFaceBoxGrow`），倾斜脸的
   下巴不再和脖子之间留一条缝。

`(dx,dy)=(0,1)` 且 `roll==0` 时所有式子退化成旧式，掩码**逐字节不变**。**横向基向量必须取 `+x`**：
取反会把羽化与肤色探测一起镜像，实测整体右移若干像素 —— 这类「看起来等价」的符号选择，
必须靠逐字节对拍验证，不能靠推理。

**修后效果**：横向溢出归零，向下延伸回到正常脖子长度。三版对照的像素统计见
`05_验证/ab20261109_neck_dir.md`。

**注意**：这段缺陷与 §4 的倾斜补偿**互相独立** —— 0° 源上两个方向都对，歪头时（`rolled != 0`）
才会叠加出更大的偏移。

## 6. `roll` 锁定与释放（`1.0.13.5` 起，`1.0.13.9` 补齐出口）

§4 落地后，`roll` 一旦锁定就基本不再变 —— 这本身是对的（角度每帧跳会抖）。问题出在**出口**：
`1.0.13.5` 只写了「按当前锁定角检不到脸 → 退回 0°」，而 YuNet 对 −45° 的输入照样给得出框，
`detOk` / `plausOk` 全真，于是**永不释放**。表现是用户报的「歪过头再回正，脸仍然是歪着处理的」：
`phi` 收敛后勉强看着正常，形变方向却错着，靠视觉一时看不出来。

`1.0.13.9` 的释放门（`beauty_core.cpp`）：

| 条件 | 值 | 说明 |
|---|---|---|
| 触发 | `roll != 0 && detOk && plausOk` | 只在「锁着且看起来一切正常」时才去质疑，正常正立帧零开销 |
| 周期 | 每 `rollCheckFrames` 帧（默认 45） | 频率太低会拖长错误窗口，太高则每帧多一次推理 |
| 对照 | 同一帧再跑一次 **0°** 检测 | 与锁定的那一档比较「框有多好」 |
| 判据 | 0° 的 plausible 框最高分高出 `rollReleaseMargin`（默认 0.05）才释放 | 比较基准用 `plausBest`（只统计通过 `rollBoxPlausible()` 的框），不是 `curBest` |
| 释放动作 | `startGeoFade` + `resetFaceEmaState` | 直接跳会让掩码瞬间位移；`kGeoFadeFrames = 6`，把框从旧几何线性插值到新几何。**只在单脸一对一配对时插值**，脸数变化（有人走进画面）直接硬切 —— 硬把 A 的框拉到 B 上会得到一张不属于任何人的脸 |

**为什么用 0.05 而不是「0° 更好就放」**：两个角度的分数在歪头时本来就接近（0.90 vs 0.83 这种量级），
不设余量会在两档之间来回切，每切一次清 EMA → 画面抖。

**为什么真歪头不会被误放**：0° 检测在 45° 歪脸上拿到的框过不了 `rollBoxPlausible()`（双眼间距
相对框长边只有约 0.216，判据下界是 0.25），所以「0° 更好」这件事本身不成立。这个门槛是整套
机制成立的前提，**放宽它会直接把歪头补偿废掉**。

R/H/S 三场景台架（`05_验证/roll_lock_check.py`）：

| 场景 | 内容 | 期望 |
|---|---|---|
| R | 0° → 57° → 0° 再保持 150 帧 | 回正后释放并归位 |
| H | 固定 45° / 50° / 60° 各 150 帧 | 一次都不放 |
| S | 20° / 30° / 35° 各 120 帧 | 从不锁定 |

## 7. 过渡帧闪烁：掩码对齐的往返跳（`1.0.13.8`）

**症状**：`1.0.13.7` 之后歪头过渡**还是闪**。用户描述是「还闪」，与 §6 的「不归位」是两个问题。

**机制**：`process()` 里 `alignOn_ && maskFresh_` 命中时输出 `heldFrame_`（上一帧画面），未命中
输出当前帧。worker 忙闲决定每帧走哪条 → 画面在「晚一帧」与「当前帧」之间来回切。歪头时画面
正在变化，这一帧的差就看得见。

**修法**：`frameNearlySame()` 在 4×4 采样点上比 R/G/B 平均绝对差，超过 `alignDiff`（默认 4.0）
就不走对齐路径 —— 即「两帧几乎一样的时候才对掩码，明显变了就直出当前帧」。判定本身在 1080p 上
不到 1 ms 量级，属可接受开销。

`BEAUTY_ALIGN_DIFF=0` 退回旧行为（永远对齐），用于 A/B。**注意**：`1.0.13.10` 起发布构建加锁，
该变量在发布版无效，A/B 需用 `build_1.0.13.10_dev`。

| 分组 | 开关 | 说明 |
|---|---|---|
| 输入方向 | `BEAUTY_AUTO_ROT` · `BEAUTY_INPUT_ROT` · `BEAUTY_AUTO_ROT_MISS` · `BEAUTY_AUTO_ROT_COOL` | 自动方向兜底与手工声明 |
| 平面内倾斜 | `BEAUTY_AUTO_ROLL` · `BEAUTY_AUTO_ROLL_MISS` | 关闭倾斜补偿 / 调触发阈值（2~600） |
| roll 释放 | `BEAUTY_ROLL_CHECK` | 对照周期帧数；**`=0` 关闭这道门**，退回 `1.0.13.8` 行为 |
| 脖子 | `BEAUTY_NECK` · `BEAUTY_NECK_HALFW` · `BEAUTY_NECK_LEN` | 总开关 / 半宽 / 长度 |

**`rollReleaseMargin`（0.05）没有环境变量**，只能改 `beauty_core.cpp` 的 `g_cfg` 默认值。
这是有意的：它是「假框门槛是否成立」的配套量，随手调会连带影响误放率，不适合做成现场开关。

## 9. 坑与失效说明

- **0° 退化必须逐字节验证**。§4.3 与 §5 的式子都宣称「`roll==0` 时与旧式相同」，这条性质是
  「正立画面不变」的唯一保证。任何改动后都要拿 0° 源逐字节对拍，不能靠公式推导确认。
- **符号选择不是等价变换**。§5 的横向基向量取 `+x`；取反会镜像羽化与肤色探测。类似地
  `cos/sin` 的符号、`ux/uy` 的先后顺序，看起来对称，实际不等价。
- **状态复位必须跟着「几何量变化」走**。方向变（§3）、分辨率变（§3）、释放 roll（§6）三处都要
  清 EMA / 迟滞 / 倾斜状态，否则旧坐标系的框会被搬进新帧 —— `1.0.0.3` 那个 `0xc0000005`
  就是这么来的，见 `docs/CHANGELOG.md` §2。
- **`kMaskHold` 是「丢检次数」不是帧数**。歪头时检测周期变长，6 次丢检可能等于十几帧，
  撑不住「检不出 → 探测接手」那段空窗（`1.0.13.6` 记录）。
- **美形三项不跟随**。瘦脸/大眼/下巴仍按画面轴施加，旋转源与倾斜源上方向都不对（GPU 版同样）。
- **多人脸各自歪不同方向**不覆盖：`g_effRoll` 是全局一个值，只能照顾一个方向。
- **倾斜在 45° 附近来回摆**有 8 帧左右滞后，期间靠掩码保持。
- **发布版（`1.0.13.10`）读不到上述任何 `BEAUTY_*`** —— 发布构建加锁，开关全部失效。
  排查与 A/B 必须换 `build_1.0.13.10_dev`。
