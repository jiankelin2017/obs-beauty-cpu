## 一、项目定义

### 1.1 是什么

给 **OBS Studio 32.1.1** 写的**美颜滤镜插件**，用自研纯 CPU 引擎（**CoreEngine**）完全替代第三方商业 SDK
（某商业美颜 SDK 2.4.2），实现观感对齐的本地离线美颜。

| 项 | 值 |
|---|---|
| 滤镜 id | **`obs_beauty_filter`** |
| 显示名 | 「OBS美颜」 |
| 引擎 | CoreEngine 1.4.1（源码最新；线上定稿为 1.4.0），纯 CPU，**运行时不加载任何第三方 SDK** |
| 面板 | 由滤镜属性**动态生成**（`build_form()` 枚举 `obs_properties`），不硬编码参数表 |
| 开发周期 | 2026-10-14 ~ 2026-10-30（16 天，3.0.14 → 3.1.39 共 40+ 次版本迭代） |
| 性质 | 个人学习 / 本地使用。第三方 SDK 二进制**仅作对照真值与参考材料**，不随包分发 |

### 1.2 两个入口

1. **滤镜**：OBS 源 →「滤镜」→ 加「OBS美颜」，id `obs_beauty_filter`。
2. **面板**：OBS 顶层菜单栏右侧「美颜(&A)」→ 打开参数面板（Dock 形式、可拖动、尺寸可记忆）。

### 1.3 关键路径

| 角色 | 路径 |
|---|---|
| 滤镜 DLL | `C:\Program Files\obs-studio\obs-plugins\64bit\obs-beauty.dll` |
| 面板 DLL | `C:\ProgramData\obs-studio\plugins\obs-beauty-ui\bin\64bit\obs-beauty-ui.dll` |
| 面板几何记忆 | `%APPDATA%\obs-studio\plugin_config\obs-beauty-ui\ui.ini` |
| OBS 日志 | `%APPDATA%\obs-studio\logs\*.txt` |

> ⚠️ ProgramData 插件目录的**目录名必须与 DLL 名完全一致**（`obs-beauty-ui/…/obs-beauty-ui.dll`）。
> OBS 扫描规则是 `<目录名>/bin/64bit/<目录名>.dll`，名字对不上会**静默跳过且不写日志** —— 表现就是「像没装」。

### 1.4 技术栈

C++17 / MSVC 14.51 / Qt 6（OBS 自带）/ ONNX Runtime（YuNet 人脸检测 + PP-HumanSeg 人像分割）/
OBS 32.1.1 libobs API / Python 3.12（离线验证台架）。

## 三、系统架构

### 3.1 三层结构

```
┌──────────────── OBS Studio ────────────────┐
│  视频源（摄像头/采集卡）                     │
│      ↓ 滤镜链                              │
│  obs-beauty.dll  ── obs_beauty_filter ──┐  │
│      ↓                                  │  │
│  CoreEngine 1.4.0（纯 CPU 美颜引擎）      │  │
│      ├─ YuNet 人脸检测（ONNX）           │  │
│      ├─ 肤色掩码 / 区域椭圆 / 关键点      │  │
│      ├─ 保边平滑 + 高低频 + 细节回填      │  │
│      ├─ 色调变换（美白/红润/清晰）         │  │
│      └─ 位移场（瘦脸/大眼/下巴）          │  │
│                                         │  │
│  obs-beauty-ui.dll ── 顶层菜单「美颜」    │  │
│      └─ 参数面板（动态生成 + 几何记忆）    │  │
└─────────────────────────────────────────┘  │
              ↘ 读滤镜属性 ←───────────────┘
```

## 五、画质复刻：对齐目标与评分

### 5.1 对齐目标

对齐对象是**某商业美颜 SDK 2.4.2**（闭源，**不在本仓库、也不随安装包分发**）：
以它在固定场景下的输出作为画质基线，基线帧由本机离线生成，仓库里只保留数值结论。

参照跑法有严格要求（**这是最容易搞错的一点**）：
- 基线由本工程的 `ref_golden` 包装层生成，其中美白/红润/锐化/清晰/全局锐化被 CPU 顶替过。
- 因此这三项另用 `05_验证\全项对齐_20261030\sdk_native.py`，通过 `LEGACY_EXTRA_PARAMS_FILE` **只注入被测参数**，绕开包装层。
- **任何「与基线对齐」的结论都必须写明参照是「原生」还是「包装层」**，否则数字没有意义。

### 5.2 评分公式

**严格式**（有 `corr` + `RMSE` 的项）：

```
S = 40 × min(r, 1/r)                    r = 我方改动量 / SDK 改动量
  + 35 × corr                           空间相关（逐像素，越高越同位置）
  + 25 × max(0, 1 − RMSE / (2·max(chg, chg_ref)))
```

**色调式**（清晰 / 美白 / 红润 —— 单参数另测，无逐像素对齐图，算不出 corr/RMSE）：

```
C_tone = max(0, 1 − hypot(Δluma差, ΔRG差) / 2)     偏差 2 灰阶记 0 分
S = (40 × min(r,1/r) + 35 × C_tone) / 75 × 100      归一到 100
```

打分脚本：`05_验证\全项对齐_20261030\score_replica.py`（**改口径只改这一个文件**）。
数据源：同目录 `acc_summary_3.1.34.json`（11 项 × 100 档 × 3 帧，**每帧独立进程**）。

### 5.5 三个必须说清的坑

**① 「磨皮 86 分」不存在 —— 86 是纹理保留率百分比，不是分数。**
全项目出现的 86 / 87 全部指「磨皮 50 档时脸颊还剩多少细纹理」：我方 86.0%，SDK 63.1%。
**这个数越小越接近 SDK**（磨得越到位），拿它当分数会读反。
磨皮百分制得分历史只有三个值：80.6 / 82.5 / 82.7。要上 86 分需 corr 从 0.803 提到 **0.90**
（或 RMSE 从 1.57 压到 1.00），属换肤色掩码的结构性改造，不是调参能到。

**② 黑眼圈 65.7 / 法令纹 65.0 不是「做坏了一半」。**
改动量已与 SDK 差 1.8% / 4.7%，位置也对齐（corr 0.75+）。但公式第三段要求 `RMSE < 2×改动量`，
而小信号项 `0.70 > 2×0.170`、`1.39 > 2×0.338` ⇒ 第三段恒为 0。
改动量只有 0.17 灰阶时，±0.7 的 RMSE 已接近 8bit 量化噪声。真实含义是「改得一样多、分布略有不同」。

**③ 旧的 77 分作废 —— 其中 3 个数字是错的，不是「分数变好了」。**

| 项 | 旧 | 新 | 原因 |
|---|---|---|---|
| 去黑眼圈 | 62.5 | 65.7 | 旧 corr 0.289 是**多帧共进程的脏数据**，逐帧独立进程实测 0.753 |
| 去法令纹 | 63.9 | 65.0 | 同上，旧 0.636 → 实测 0.768 |
| 全局锐化 | ≈70 | 91.3 | 旧值是**估的、不可复算**（代入脏 corr 也得 86.6） |
| 美白 | 83.7 | 75.1 | 新口径把 Δ亮度差 0.91 灰阶计入一致度 |
| 红润 | 85.2 | 79.8 | 新口径把 Δ(R−G) 差 0.54 计入 |
| 清晰 | 89.3 | 93.1 | Δ亮度差仅 0.007 灰阶，几乎完全重合 |

**脸内锐化不计分**：我方做的是「回填磨皮削掉的细节」（磨皮 = 0 时改动量 0.000），
SDK 是独立锐化器（1.012）。属**语义选择**，不是精度问题；要真正复刻需再叠一层稀疏加锐。

### 7.3 三个真 BUG（不是审美问题）

**① 底部两个按钮从来就没显示过（3.1.32 ~ 3.1.35）。**
构造函数把「恢复默认 / 关闭」`addWidget` 进 `mode_grid_`，随后 `reload()` → `build_form()` → `clear_form()`
→ `purge_layout(mode_grid_)` 把 grid 内所有控件（含这两个按钮）`deleteLater()`，之后再没造回来。
**修法**：按钮改建在 `build_form()` 内，与档位下拉同生命周期。
**红线：凡需跨 rebuild 存活的控件，不能放进会被 purge 的 layout。**

**② 「固定尺寸」不是一次调用，是三处。**
构造函数 `apply_adaptive_size()`、`event()` 的 `QEvent::Show`、`build_form()` 末尾三处都在强制改尺寸 ——
只删 `setFixedSize` 会导致「失焦回来 / 拖滑块」时尺寸回弹。

**③ 控件高度对不齐，根因在 OBS 主题不在代码。**
`Yami.obt` 给每类控件各算一套高度：

```css
QComboBox   { height: var(--input_height); }
QSpinBox    { height + max-height: var(--input_height); }
QPushButton { height + max-height + padding + margin-top/bottom; }
```

面板旧 QSS 只覆盖 `padding`，height/margin 全放给主题。代码里还有第二套数字（`setFixedHeight(32)`、
`setFixedSize(108,44)`），但 **QSS 的 height 优先级高于 `setFixedHeight()`** ⇒ 同一句 `setFixedSize`
**只生效一半**（宽 74 生效、高 32 不生效，实测 28.6）—— 这才是「怎么调都对不齐」的真相。
**修法**：`kCtrlH = 26`（内容盒）+ 1px 边框 ×2 = 总高 **28**；QSS 写全
`height/min-height/max-height/margin:0/padding:0 8px`；**代码里高度数字全部删除，只留宽度**。
复选框无边框用 `kCtrlH+2`；`QTabBar::tab` 不认 `min-height`，只能靠 padding（实测 27，属物理下限）。

## 十二、经验教训（20 条雷区，按类归并）

### 12.1 OBS / 插件 API

1. `obs_get_source_defaults()` **只含 default 条目**，`obs_data_apply` 只拷实际值 ⇒ 拿它喂 `obs_source_update` 是 **no-op**。
   必须 `obs_data_get_defaults()` 转实际值。
2. ProgramData 插件目录名必须与 DLL 名完全一致，否则**静默跳过、不写日志**。
3. 读日志的「源-滤镜树」：`- filter:` 行缩进在**它所属的源**下面，不是上一行的源。
   任何「某滤镜挂在某源上」的判断必须用 `render#N target=` 那行交叉验证。
4. 场景配置用 `%APPDATA%\obs-studio\basic\scenes\*.json` 的 `sources[].filters` 为准；
   日志（运行中）与 JSON（上次保存）可能不一致。

### 12.2 Qt / QSS / 面板

5. **QSS 的 `height`/`min-height` 盖过 `setFixedHeight()`** —— 高度只在 QSS 定义一次，代码里别写高度。
6. **跨 rebuild 存活的控件不能放进被 `purge_layout()` 清的 layout**（按钮消失 BUG 的根因）。
7. `QGroupBox` 的标题抬不出框（`margin-top` 移动的是整个组框）；要独立标题用卡片 + `QLabel`。
8. 面板 UI 改动**必须过离屏探针**再看真机，否则 QSS 优先级这类问题肉眼定不了。
9. `setMinimumContentsLength` 是猜，不是量 —— 文字截断要按实际 `fontMetrics` 算。

### 12.3 数值与算法

10. **`(int)` 是截断不是四舍五入** —— 负增益写回会系统性少 1（已改 `lroundf`，两处）。修之前所有压暗类效果都偏暗一档。
11. **不要回到拟合路线。** 等效参数对得上平均值，对不上结构。
12. **不要用固定阈值做「平坦区磨、纹理区保」**，原理上做不到，必须 `Δg²·yFactor` 抛物线权重。
13. `r1 < r2` 会削穿中频（半径不对称很危险）。
14. `boxRgbRoi` 内部只外扩 `r×iters+2`，大半径时调用方必须再外扩 `max(r×it)`。
15. **ROI 起点下对齐到 32**，否则浮点累加相位不同会差出灰阶。
16. **EMA 默认必须 = 1.0**，改了会拖影。
17. **ORT 自旋必须关**（`allow_spinning=0`）—— 默认 1 让推理线程忙等，白烧 1.4 核。CPU 对不上先查这条。
18. 同步/异步提交周期不能合并（异步 `maskEveryAsync=0` 生产、同步 `kMaskEverySync=4` 离线台架）；改了同步，全部基线作废。

### 12.4 流程与环境

19. **不能只读文本就下结论**：`render#0 target=… 1280x720` 是横屏；竖屏缓冲会让磨皮核变成 3.16× 竖椭圆。
20. **预览冻结 ≠ 我们卡了**：全内存 dump（2.77 GB）显示 189 条线程**无一条**在 `obs-beauty.dll`，
    图形线程 median 0.586 ms 健康，根因是**两条 win-dshow 争同一台摄像头**（CH1 / CH2 同设备）。
    → 两个源不要指向同一台相机。
21. **`self-check` 里的 `sdk=` 是误标**：`engine=core` 时它返回的是 `CoreEngine::lastMs_`，不是 SDK 耗时；
    且那是 frame#0 的数（含 YuNet 首帧建 session），**不能当稳态性能**。稳态看 `BEAUTY_PROFILE=1` 的 180 帧统计。
22. **参照要分清「原生」与「包装层」**（§5.1）。
23. **md5 不可复现**（§2.2）—— 判源码一致性用 `src_fingerprint.py`，不要用 md5，也不要用 `/Brepro` 重编定稿。
24. **PowerShell 处理中文路径会乱码**，`ConvertFrom-Json` 会被中文区域名打断 —— 用 Python `os.listdir` 或 `[regex]::Match`。
