## 0. 一句话结论

**纯 CPU 实现的 OBS 美颜滤镜插件，独立产品线 `1.0.14.0`；不引入自定义 shader / GPU 计算管线，美颜算法全部在 CPU buffer 上完成。**

## 1. 版本轴

CPU 线自 `1.0.0.0` 起立，四段式 **主.功能.修订.构建**，唯一出处是 `beauty_params.h` 的 `BEAUTY_BUILD_STR`。

| 档位 | 触发条件 | 动作 |
|---|---|---|
| 构建位 | 注释 / 文档 / 重打包等不影响行为 | `+1` |
| 修订位 | 修 bug / 调默认值 / 优化速度 | `+1`，后两位归零 |
| 功能位 | 用户可见新功能 | `+1`，后两位归零 |
| 主版位 | 不兼容变更 | `+1`，后三位归零 |

低位不进位，跨档取高。`1.0.2.0` → `1.0.14.0` 几乎全是修订位 `+1`，只有 `1.0.5.0` 走功能位（头歪 45° 自动补偿）；`1.0.13.10` → `.11` → `.12` 经裁定走构建位，`1.0.13.12` → `1.0.14.0` 于 2026-11-10 按字面执行。`CoreEngine::version()` 已并入单轴，不再维护独立 `core 1.4.x`。

版本号同步链：

`beauty_params.h` → `obs-beauty.cpp` / `obs-beauty-ui.cpp` → `build_setup.ps1` / `obs-beauty.nsi` / `e2e_test.ps1` → `docs/CHANGELOG.md`

> `docs/archive/` 是历史原件（2026-11-10 重建）。根 README 与 `04_文档` 里的 `3.1.39` / `3.1.40` / `core 1.4.x` 只代表当时状态。

## 2. 快速开始

### 2.1 构建

| 脚本（`02_构建\`） | 作用 |
|---|---|
| `build_manual.bat` | 编译滤镜 / CoreEngine |
| `build-ui_320.bat` | 编译面板 |

产物落到独立目录 `02_构建\build_<版本>\`（`set BEAUTY_OUTDIR=...` 指定），**不要覆盖** `build_output\` 里的历史定稿。

工具链：MSVC 14.51.36231 + Windows SDK 10.0.26100.0 + `C:\Qt` + NSIS 3。受限环境 `vcvars64.bat` 不可用，脚本内已硬编码 `INCLUDE` / `LIB` / `PATH` 探测，依赖目录按内容探测定位。构建后跑 `verify-ui-imports.py <dll>` 自检。

### 2.2 打包

`build_setup.ps1` 从 `BEAUTY_BUILD_STR` 读版本 → 定位 `build_<版本>\` 取件 → 版本串自检 → 传 `/DPKGVER` 给 `obs-beauty.nsi` → 产出 `06_安装包\OBS美颜_CPU_v<版本>.exe`。可用 `-Version` / `-BuildOut` / `BEAUTY_BUILD_OUT` 覆盖；**缺 `/DPKGVER` 直接编译失败，没有写死兜底**。

| 版本 | 产物大小 | MD5 |
|---|---|---|
| `1.0.14.0`（当前发布） | 3,643,349 B | `8df84db986a36bca0f20f7e1b9d578a0` |
| `1.0.13.0` | 3,652,694 B | `409721014032b3e95f611ed8bc0e0269` |

### 2.3 装机

装卸回归 **2026-11-07 16:56 实测通过**：`40/40 PASS`、`0 FAIL`，终态四件 MD5 逐一相同。

装机口径按 C-1 统一到 `C:\ProgramData\obs-studio\plugins\`（见 §8 第 9 项），`install_<版本>.bat` 拒绝覆盖已存在文件。复跑：关掉 OBS（含托盘），以管理员进程执行 `e2e_test.ps1`，结果写在 `%TEMP%\obsbeauty_test\log.txt`；当前机状态以 `05_验证/e2e_install_20261109_1312.md` §5 为准。

四条硬约束：手动提权 · 先关 OBS · `C:\ProgramData` 可写 · **面板插件目录名必须与 DLL 名一致**（否则 OBS 静默跳过且不写日志）。

### 2.4 上传前自检

两道闸门，都要过：

| 脚本 | 检查内容 |
|---|---|
| `check_upload.py` | 索引一致性 · 闭源商业资产 · 体积红线（单文件 > 1 MB 走 Release 附件）；支持 `--staged` / `--fix` |
| `check_docs.py` | 九条断言：Active 头六字段、归档件 `ARCHIVED` 头与替代指向、`INDEX.md` 双向登记、`docs/` 零断链、命名规范、当前版数字表格（只告警）、版本轴一致性、`05_验证/` 零断链、总表「适用版本」列 |

`check_docs.py` 只读、纯标准库、失败退出码 `1`。第 7 / 8 / 9 条允许登记**带理由的例外**并每次打印清单（设计取证快照记「最后一次内容复核版本」，归档件可能指向已清理的取证文件）；例外不等于放行 —— 未登记的落后版本或新断链仍阻断。

## 3. 架构与帧管线

### 3.1 模块与算法链

```
OBS 32.1.1
└─ obs-beauty.dll · obs_beauty_filter
   └─ CoreEngine（纯 CPU）
      ├─ 人脸检测
      ├─ 肤色掩码 / 区域椭圆 / 5 关键点
      ├─ 保边平滑 + 高低频分离 + 细节回填
      ├─ 色调（美白 / 红润 / 清晰 / 全局锐化 / 脸内锐化）
      ├─ 五官局部（去法令纹 / 去黑眼圈 / 亮眼 / 祛斑痘 / 五官立体）
      └─ 位移场（瘦脸 / 大眼 / 下巴）

obs-beauty-ui.dll · 菜单「美颜·CPU(&A)」（仅 CPU 宏开启）
└─ 参数面板：遍历滤镜 obs_properties 动态生成，不持有副本
```

### 3.2 帧管线

`检测 → 肤色掩码 → 磨皮 → 色调 → 锐化 → 五官局部 → 美形 → 输出`

全 0 参数逐字节透传、不进引擎；14 项功能分五页（美颜 / 锐化 / 五官 / 美形 / 高级）。

### 3.3 关键口径

**色调整帧**（`1.0.2.0` 起）：清晰 / 美白 / 红润整帧施加、不乘皮肤掩码（`BEAUTY_TONE_GLOBAL=1`，与 GPU 版同口径）；磨皮 / 锐化 / 五官仍只在皮肤掩码内。

**性能**（`1.0.13.0` 真机同会话配对）：1080p30、ROI≈480×305，下载 2.07 + 检测掩码 0.67 + 磨皮 2.72 + 色调 0.46 + 细节 0.77 + 美形/alpha 0.86 + 上传 0.62 ≈ **8.34 ms/帧**（24 个干净窗口中位），占 30 fps 预算 25%、60 fps 预算 50%。

优化五步：

| 版本 | 做法 | 效果 |
|---|---|---|
| `1.0.8.0` | 磨皮盒式并行粒度 / ROI 外拷贝并行 / A 通道搬进引擎 | 磨皮 −2.5 ms |
| `1.0.11.0` | 色调整数复合表 | 色调 4.56 → 0.84，全链 −4.88（−27%） |
| `1.0.12.0` | A 通道并进色调写、`detailRefill` 跳过中频盒式 | 台架 −1.69（−10.5%） |
| `1.0.13.0` | 磨皮盒式三通道融合 + 垂直趟 SSE | 台架全开 −2.83（−18.7%）；真机磨皮 −0.40（−12.8%）、引擎 −0.37 |

`BEAUTY_ZERO_COPY=1` **已证伪**：下载省 0.58 ms，但引擎 `+0.41`、上传 `+0.19`，净慢 0.28 —— 映射内存写合并 / 非缓存，而引擎反复读同一片输入。默认关，代码留作开关。

**统计三坑**：① 按 ROI 面积对齐（ROI 297×270 → 561×291 时磨皮 5.63 → 9.77）；② 只统计「无脸跳过 = 0」的窗口（`1.0.7.0` 的 10.41 ms 旧基线作废，`1.0.10.0` H 组实测 19.02 ms）；③ 防抢核 —— 跨会话绝对值不可比，后台抢核能让多线程段齐降 1.8 倍而单线程的人脸检测不变。真机只认「同一坐姿、同一会话、交替跑」的配对数据（`live_matrix.py` 跑 S/F 两组），早期 `13.25` / `12.07` / `−1.40` 不再引用。详见 `design-cpu-performance.md` §2.7~§2.10 / §3.0 / §3.0b。

**功能开关**：

- **脖子**（`1.0.7.0`）几何参数化到「立正方向」（`u` 沿画面正下方、`v` 横向，由 `BEAUTY_INPUT_ROT` / `g_effRot` 决定）。≤`1.0.5.0` 按源 `+y` 画，旋转源上真脖子漏磨；`1.0.6.0` 旋转源整段不画止血。开关 `BEAUTY_NECK=0`，取证 `05_验证/ab20261109_neck_dir.md`。
- **头歪**（`1.0.5.0`）检测召回边界 30~40°，45° 歪头常无框或敷衍框；连续 8 次「无脸或框不像人脸」后试 ±45°，命中记住倾角（`FaceBox.roll`），掩码按倾斜矩形画（45° 外接盒面积是脸 2.8 倍）。开关 `BEAUTY_AUTO_ROLL=0`（逐字节回 `1.0.4.0`），阈值 `BEAUTY_AUTO_ROLL_MISS`（2~600）。真机已验证（2026-11-09，`UGREEN 35867`）：第 17.6 s 命中 +45°（score 0.871），之后无脸跳过全程 0，150 s 零丢帧。
- **输入方向**（`1.0.3.0`）OBS 场景旋转只作用于显示合成；连续检不到脸时自动试探 90°/270°，按该方向检测后反变换回源坐标。开关 `BEAUTY_AUTO_ROT` 默认开，已知方向可用 `BEAUTY_INPUT_ROT=90/270`。

**「纯 CPU」的准确口径**（2026-11-06 确认）：`gs_texrender` / `gs_texture_*` / `gs_draw_sprite` 是 OBS 滤镜框架唯一的帧 I/O 通道（源帧 → map 到 CPU `buf_in` → CPU 计算 → 回写 `buf_out` → 画回），不是 GPU 计算。验收标准是「不引入自定义 shader / hlsl / GPU 计算管线，美颜算法全部在 CPU buffer 上完成」：`01_源码` 无 `gs_effect_create*`、无 hlsl / effect 资产，唯一相关的是 OBS 内置 `OBS_EFFECT_DEFAULT`。

总表是 `docs/INDEX.md`（主题｜路径｜类型｜状态｜适用版本｜维护人｜最后核对｜替代/归档）。固定分类 `README` / `design` / `guides` / `reference` / `CHANGELOG` / `adr` / `archive`：主目录每类只留当前版，同一主题不允许两份并存；命名 `类型-主题.md`，归档件用 `主题-YYYYMMDD.md` 并在文首标「已废弃，见 xxx」及原因。

**可信度顺序**：逐字源码 > 动态实测 > 推断 > 拟合（`01_源码\` > `README` > `docs\` > `_quarantine\`）。

**防腐化**：`INDEX.md` §0 有头模板与校验规则、§4 有九条维护约定；`check_docs.py`（`0.3.0`）拦截漏登记 / 缺替代指向 / 断链 / 命名跑偏 / 漏改头表 / 失效引用。脚本版本 `0.3.0` 与产品版本 `1.0.14.0` 是两条互不相干的轴。
