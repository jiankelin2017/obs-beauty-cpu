# 真机多帧验收 · 2026-10-30 03:1x（v3.1.17 装机后首次）

## 为什么做

`00_先读我.md` §0.3d 的画质结论只有 **1 张**真机帧（C24 要求 5–8 张），且真机稳态耗时从未测过。
本轮把 OBS 里的自研滤镜当被测件（v3.1.17 / core 1.1.0 / blur=100），一次补齐这两项。

## 环境（可复核）

| 项 | 值 |
|---|---|
| OBS | 32.1.1（obs-websocket 5.7.3，端口 4455） |
| 场景 | `美颜测试`（配置文件 `beauty_test.json`） |
| 源 | `视频采集设备` dshow_input，采集 1280×720 |
| 画布 | 1920×1080 / 30 fps |
| 滤镜 | `obs_beauty_filter` v3.1.17，core 1.1.0，blur_level=100，color_level=0 |
| 日志证据 | `init OK (v3.1.17, engine=core/1.1.0)`、`self-check … faces=1`、`frame#1 drawn 1280x720 faces=1` |

## 方法（两个坑，写下来免得重踩）

1. **不能直接抓源**：`GetSourceScreenshot("视频采集设备")` 对 async 的 dshow 源返回**全黑**（实测 6 张 mean=0.0）。
   必须抓**场景**：`GetSourceScreenshot("美颜测试")`。
2. **要抓「关掉滤镜」的帧**：先用 `SetSourceFilterEnabled false` → 间隔 0.55 s 连拍 8 张 `1920×1080` PNG → 再 `SetSourceFilterEnabled true` 复原。
   `grab_raw.py` 全自动，末尾会回读 `filterEnabled` 确认已恢复。
3. 画布 1920×1080 是把 720p 源放大了 1.5 倍（`real_frame_eval.py` 头注释已说明）：两边引擎吃同一张图，相对关系不变，但绝对 RMSE 会偏低。
   要更严就把 OBS 画布设成 1280×720 再抓一遍（本轮没做）。

## 指标口径

- **金标**：`nama_golden.dll` + **加密** bundle（`C:\btwork\engine`，md5 与产品 `common/assets/model/` 一致），`blur=100`、**`blur_type=-1`**（不下发 = 产品真实行为 = bt2）。
- **掩码**：`mk_mask.py` + **明文** bundle（`C:\btwork_plain\engine`）——`BeautyDumpMask` 只认明文 ZIP；两 bundle 渲染逐字节等价，故不影响结论。
- **被测**：`beauty_core_test.dll`（2026-10-29 17:38 构建）+ `BEAUTY_SMOOTH_MODEL=surface3`、`BEAUTY_S3_BAND=1`、`BEAUTY_S3_BT=8.3`。
  ⚠ 这三个环境变量必须在 `beauty_core` 首次 `ensureReady` **之前**设好（`g_cfg` 只读一次），否则拿到的是 DLL 内建默认（legacy / band=0 / T=14）——`flattex_eval.py` 首跑就踩了这个坑，数字完全反了。
- **平坦 / 纹理**：在肤色掩码内对**源图**灰度算 5×5 局部标准差 σ：`flat = σ<2.0`、`tex = σ>6.0`，中间带不计。

## 性能（真机稳态，首次实测）

`GetStats` 的 `renderTotalFrames / renderSkippedFrames` 4 s 差值：

| 状态 | 渲染帧率 | 跳帧 |
|---|---|---|
| 滤镜开 | 30.0 fps | 0 |
| 滤镜关 | 30.0 fps | 0 |
| 滤镜开（复测） | 30.0 fps | 0 |

→ **720p 下滤镜不吃帧**（预算 33.3 ms，实测无跳帧）。OBS 状态栏那次 `18.39 / 30.00 FPS`
是启动瞬时的累计值，不是稳态，**不要据此判断性能**。
更细的分项（下载/引擎/上传）仍需 `BEAUTY_PROFILE=1` 重启 OBS 才出 180 帧性能行，本轮没做。

## 结论

1. 主验收线 **通过**：8/8 帧 RMSE **1.606** < 2.0。
2. 总改动量只差 **+3.4%**，但**分布错了**：平坦欠磨 11%、纹理过磨 18%；
   产品的「平坦/纹理」选择比是 **1.39**，我们只有 **1.05** → 我们磨得"不分结构"。
   这就是视觉上"脸颊/鼻唇沟比产品更糊"的量化来源（见 `ab_m00_zoom.png`）。
3. 空间相关 **0.803**，略低于 0.82 门槛（0.79–0.84 波动）→ 位置基本对，但没到判据。
4. 下一步应改**选择性**（保结构、加平坦），而不是继续整体加/减强度。
