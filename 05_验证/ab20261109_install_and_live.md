# 真机验证：1.0.5.0 装到 ProgramData 之后（2026-11-09 上午）

这一轮把「1.0.5.0 只做了离线验证」这个缺口补上：**装进装机目录、用真摄像头、真场景、
真录制**跑一遍。顺带在验证过程中挖出一个从 `1.0.3.0` 起就在、但一直没人注意的缺陷
（见 §5）。

- 摄像头：`UGREEN 35867 CH1`（1920×1080，画面相对正立被转 270°）
- 场景：`视频` / 源 `视频采集设备` / 滤镜 `OBS美颜`
- 装机路径：`C:\ProgramData\obs-studio\plugins\obs-beauty\bin\64bit\obs-beauty.dll`
- 录像：`D:/c/2026-11-09 11-30-18.mp4`（1920×1080，30 fps，150 s，4499 帧）

---

## 1. 装机：非提升进程改不了 ProgramData，必须过一次 UAC

`obs-beauty\bin\64bit` 目录的 ACL 是

```
BUILTIN\<user>s:(I)(OI)(CI)(F)
BUILTIN\Users:(I)(OI)(CI)(RX)
BUILTIN\Users:(I)(CI)(WD,AD,WEA,WA)
```

`WD,AD` 只允许**新建**文件，改已有文件要 `FILE_WRITE_DATA` / `DELETE` —— 非提升进程
没有。所以：

- 先把两个 DLL 拷到纯 ASCII 的临时目录（`%TEMP%\obs-install\`），
  批处理里**不能出现中文路径**（GBK/UTF-8 一错就找不到文件）；
- 再用 `Start-Process -Verb RunAs` 弹一次 UAC 跑安装脚本，脚本里先备份旧 DLL 再覆盖。

结果（`install_log.txt`）：备份 2/2 成功、安装 2/2 成功。

| 文件 | 字节 | sha256 前 16 位 | 与构建产物 |
|---|---|---|---|
| `obs-beauty.dll` | 465920 | `91949c86fd7cbeba` | 一致 |
| `obs-beauty-ui.dll` | 218624 | `a7587afb48a8748c` | 一致 |

装前是 `1.0.3.0`（456704 B，二进制里 `band_roi` / `倾斜探测` 都是 0 处），
旧 DLL 备份在 `%TEMP%\obs-install\bak\`。

```
11:30:35.646 [美颜] 倾斜探测命中 +45°（score=0.871）：本帧人脸在画面内倾斜了约 45°
```

录制从 `11:30:18` 开始，所以倾斜探测落在**第 17.6 秒**——正是用户按脚本把头顶到
45° 的那一段。补上之后 `无脸跳过` 一路是 0：

| 时间窗 | 引擎 ms | 无脸跳过 |
|---|---|---|
| 11:30:42 – 11:32:30（歪头段 + 回正段） | 10.4 – 13.3 | 0 |
| 全程下载 + 上传 | 2.0 + 1.5 | — |

150 秒录制期间日志里**没有任何** `skipped` / `lagged` 行（这两行只在非零时打印），
结束时只有一行 `Recording Stop`，即**零丢帧**。

## 4. 逐帧复核：同一批帧上，270° 检不到、315° 检得到

把录像抽帧（每秒 1 帧）丢回探针，按「270 优先，不行试 315 / 225」检测：

| 时间 | 检出角度 | score | 脸颊 `lapMean` |
|---|---|---|---|
| 8–15 s（正立） | 270 | 0.87–0.89 | 5.6 – 7.3 |
| 16–17 s（开始歪） | 270 | 0.80–0.81 | 3.7 |
| **18–27 s（歪 45°）** | **315 = 270+45** | **0.876 – 0.891** | **2.9 – 3.3** |
| 29–33 s（回正） | 270 | 0.900 – 0.904 | 5.0 – 5.4 |

两件事同时成立：

- 探测锁定的 `+45°` 就是**唯一能出脸**的那个角（270 在该段 `faces=0`），
  而且探测报的 `score 0.871` 与离线逐帧量的 `0.876~0.891` 对得上；
- 歪头那 10 秒脸颊的高频能量（Laplacian 平均绝对值）**比正立还低**（3.0 vs 5.3）——
  皮肤不是「没磨」，而是磨到了，且没有因为补偿而抖成碎片。

回正也是自动的：`g_effRoll≠0` 时一旦按带倾斜的角度检不到，当帧就退回不带倾斜再试，
命中即清掉 roll（`beauty_core.cpp` 里那段 immediate fallback）。所以 28 秒那次回正
没有丢帧、也没有第二条日志。

## 5. 【新发现】源被转 90°/270° 时，脖子通道画错了方向（`1.0.3.0` 起）

这一条与头歪无关，是**正立时就已经存在**的缺陷。

掩码最后是在**源坐标**里逐像素画的，而脖子通道从脸框下沿接着往下时用的是源坐标
的 `+y`。源需要转 270° 才立正时，源坐标的 `+y` 在立正画面里是**横向**的，于是：

| | 掩码总量 | 落在脸框（放大 35%）外 |
|---|---|---|
| 正立、270° 源 | 145010 px | 40444 px（**27.9%**） |
| 歪 45°、270° 源 | 104250 px | 24416 px（**23.4%**） |
| 正立、**0° 源**（对照） | 303927 px | 脖子竖直往下，无横向溢出 |

看图更直接：`05_验证/_live1509/mask_ab.png`（左正立、右歪头，红/蓝区是掩码）
—— 两张图里都有一条带子从下巴横着穿到右肩和窗帘上；对照
`05_验证/_live1509/rot0_ov.png`（0° 源）脖子是正常竖着往下的。

后果两条，都不致命但看得见：

1. 真正的脖子**没被磨**（脖子只在下巴正下方那一小块被脸框蹭到）；
2. 背景窗帘、右肩被当成皮肤一起磨了 —— 也就是「背景糊了一片」。

为什么一直没被发现：这台摄像头 `1.0.3.0` 才第一次能检出脸（之前「竖屏摄像头完全
没效果」），而脖子通道的坐标方向没跟着那次改动一起修；日常看画面时那条带子落在
窗帘上，不盯着看不出来。

## 6. 复现命令

```bash
# 装机（会弹 UAC）
powershell -c "Start-Process cmd -ArgumentList '/c','%TEMP%\obs-install\install_105.bat' -Verb RunAs -Wait"

# 拉起 OBS（后台常驻，BEAUTY_PROFILE=1 打开 180 帧性能窗口）
cd "C:\Program Files\obs-studio\bin\64bit"
BEAUTY_PROFILE=1 ./obs64.exe --disable-shutdown-check --minimize-to-tray &

# 状态 / 开关滤镜 / 录制 / 正常关闭
python 05_验证/obs_ctl.py status
python 05_验证/obs_ctl.py filter off        # 抓原始帧用
python 05_验证/obs_ctl.py record 150
python 05_验证/obs_ctl.py quit              # 发 WM_CLOSE，日志与 mp4 都正常收尾
```

`obs_ctl.py` 是这一轮新增的：obs-websocket 5.x（端口 4455，密码在
`plugin_config/obs-websocket/config.json`）驱动，用来代替手点 GUI。
注意两条：连接前必须清掉 `HTTP_PROXY`；OBS 必须以后台常驻方式启动。
