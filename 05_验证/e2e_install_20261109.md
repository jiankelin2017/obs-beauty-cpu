## 1. 首次运行的 6 项失败（已定性，非产品缺陷）

```
FAIL  A3 filter dll removed
FAIL  A3 onnxruntime removed
FAIL  A3 model removed
FAIL  A3 panel dll removed
FAIL  A3 models dir removed (was ours)
FAIL  A3 ProgramData ui chain removed
```

同一个 A3 里 `install dir removed`、两个注册表键、开始菜单全部 PASS —— 说明卸载器跑完了。
`obs-beauty.nsi` 的步骤顺序是「1~4b 删文件 → 7 删注册表」，注册表既然没了，删除动作确实执行过。

### 定性证据（三条，互相独立）

1. **`models` 目录的创建时间是 `17:14:50`**，正是 A1 安装的那一刻。若卸载器删过它，此刻不会还在。
2. **注册表路径正确**：复跑时打印 `reg ObsDir = C:\ProgramData\obs-studio\plugins\obs-beauty\bin\64bit`，
   与断言用的路径一致 → 排除「卸载器算错 `$OBSDIR`、删到空地方」这个假设。
3. **放宽窗口后全部消失**：`gone after wait: filter=True ort=True models=True ui=True`。

结论：**卸载器的文件删除有 1~2 秒延迟**（`Delete` 静默失败不重试，NSIS 卸载器自身也在收尾）。
旧判据在「注册表键消失」之后硬睡 1.2 秒就断言，卡在边界上。

## 5. 这次暴露的判据问题（写给下次）

- **卸载断言不能用固定 sleep**。卸载器删文件与删注册表不是同一时刻，且 `Delete` 失败不报错。
  凡「卸载后应消失」的断言，一律轮询 + 超时，不用固定等待。
- **`B2 … RESTORED from backup` 这组断言有盲区**：`$safetyMap` 记录的是测试前机上文件的 MD5，
  当机上装的就是待测版本时，「文件根本没被删」和「从备份还原成功」得到同一个 MD5，两者无法区分。
  本轮 B2 的 PASS 因此只证明「终态正确」，**不证明「还原逻辑被执行」**。要真正验证还原，
  得先装一个不同版本再覆盖安装。
