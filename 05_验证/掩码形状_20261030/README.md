# 掩码形状与「残影」定位（2026-10-30 03:56）

现场：OBS 32.1.1 / 场景 `美颜测试` / 源 `视频采集设备` 1280×720 / 滤镜 v3.1.19 + core 1.3.0，
`blur_level=64`。用户反馈「脸部快速移动时遮罩追不上，能看到遮罩残影」，并截图标记了
**脖子左右两侧**。

## 一、做了什么

1. 用 `probe_mask.py` 通过 obs-websocket 抓「滤镜开 / 关」两帧（不改任何面板参数，事后复原）。
2. 用 `mask_dump.py`（ctypes 调 `beauty_core_test.dll` 的 `BeautyCoreMask`）把
   **自研 CoreEngine 在那一帧上真正算出来的掩码**落盘（8 字节头 + w×h 字节）。
3. 把掩码叠加回画面：**红 = 强掩码（>128）**、**黄 = 羽化带（8~200）**、**青线 = 边界**。
4. 对 `goldens/real/m00_in.raw`（1920×1080 真机帧）重复同样流程，看脖子段。

## 二、结论

**不是整块遮罩偏移，是「掩码是矩形，边界是直线」。**

- 掩码 = `人脸框矩形（YuNet 框 ×1.15）∩ 肤色权重`，边缘羽化 = 脸宽 8%；
  下面再接一条 **脖子矩形通道**：宽 `0.90 × 脸宽`、长 `0.65 × 脸高`
  （`beauty_core.cpp:539-540`、`:1589-1666`）。
- 因此边界不是脸/脖子轮廓，而是**两条竖直直边**。`m00_neck.png` 里可以清楚看到
  左边那条青线**直接切在脖子皮肤上**，线外侧的脖子没被磨 → 脖子上出现一条
  「半磨 / 不磨」的竖直分界。
- 快速移动（尤其歪头、转头）时，脖子相对人脸框的位置在变，这两条直边就在脖子上
  **来回扫**。观感就是「遮罩追不上、有残影」——实际是直边在扫，而不是掩码整块漂移。

## 三、排除掉的一条

「运动模糊导致检不出脸 → 沿用旧掩码 6 帧（`kMaskHold=6`）」这条**已排除**：
把 `m00` 做 8 / 15 / 25 / 40 px 的水平运动模糊后仍 `faces=1`，
掩码面积 16.52% → 16.49% / 16.58% / 16.75% / 17.06%（变化 <3%）。
YuNet 对运动模糊很稳，不会走到「保持旧掩码」那条路。

## 四、还没量化的一条（时序）

链路本身把「掩码 + 它描述的那一帧」当成整体处理（3.1.10 对齐），稳态下掩码与画面
**同源**，理论上不该有错位。但 worker 掉一帧时会**静默退回**「新帧 + 旧掩码」——
那一帧就是 1~2 帧错位，正好落在快速移动时。

这件事目前**没有日志**：对齐率只在 `BEAUTY_PROFILE=1` 时每 180 帧打印一次
（`obs-beauty.cpp:975`，格式 `对齐 used/total（xx%）`）。要确认得带这个环境变量重启 OBS。

## 十一、形状实验：椭圆 / 肤色跟随都被数据否掉（2026-10-30 04:10）

用户批准「A（对齐率）+ C（脸框换椭圆距离场）」后，我在 `beauty_core.cpp` 实现了
`BEAUTY_MASK_SHAPE` 位掩码（0=旧矩形，1=脸椭圆，2=脖子椭圆，4=脖子逐行跟随肤色），
默认仍是 0（生产行为零变化），然后用 fuai 掩码在 S1 的 8 个有效场景上量化：

| 形状 | mean IoU | 精确率 | 召回率 |
|---|---|---|---|
| 0 矩形（旧，基线） | **0.8416** | 0.954 | 0.878 |
| 1 脸椭圆 | 0.7694 | 0.960 | 0.82 |
| 2 脖子椭圆 | 0.8062 | 0.953 | 0.85 |
| 3 脸+脖子椭圆 | 0.7637 | 0.966 | 0.81 |
| 4 脖子跟随肤色 | 0.7665 | 0.928 | 0.83 |

**全部低于基线的 0.8416**：精确率微升、召回率掉 5~7 个点 —— 掩码被几何形状削掉一块。

另外两项也试过并否掉：

| 尝试 | 结果 |
|---|---|
| 脖子加宽（半宽 0.45→0.55/0.65/0.75 脸宽） | 召回率封顶 0.905，精确率从 0.954 掉到 0.72 → IoU 0.842→0.667。加宽等于把背景框进来 |
| 羽化加宽（16→24/32/48 px） | IoU 0.842→0.755/0.705/0.560。软边是靠牺牲覆盖换来的 |

**关键观察（决定后续方向）**：把 fuai 真值掩码叠回画面（`cmp_face_src.png` 左图）可以看到，
**第三方的掩码脖子也是直边**，形状就是「脸框 + 一条矩形脖子柱」。所以「直边」本身
不是缺陷，跟真值一致；用户看到的残影来自直边**在皮肤上移动**，而移动的原因是掩码与
画面不同源（检测滞后），不是形状。

→ 形状这条路（C）到此为止，默认值保持 0。下一步应转向 A：先量出对齐率，
再决定「worker 掉帧时该不该跳过美颜」。
