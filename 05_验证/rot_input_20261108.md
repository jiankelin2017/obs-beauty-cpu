# OBS美颜 CPU `1.0.3.0` · 输入方向自动补偿取证记录

> 本文件是 `05_验证/` 下的取证副本，**不是 Active 文档**，`docs/INDEX.md` 不登记它。
> 台架源码与可执行文件在同目录 `_rot_probe/`；`.raw` 帧与 `.exe` 按 `.gitignore` 不入库。
> 本轮**没有**在 OBS 里出图（本机摄像头报 `data.GetDevice failed`），真机观感仍待人工确认。

| 字段 | 值 |
|---|---|
| 症状 | 摄像头/采集卡是**竖着**的时候（手机竖拍、竖屏采集卡），美颜完全没效果；同一台机器换成横屏机位就正常 |
| 根因 | OBS 场景项旋转只作用于**显示合成**，滤镜拿到的 `in_tex` 仍是躺着的原始帧。YuNet 在 ±90° 的脸上检不出框 → 掩码为空 → 磨皮/美白/红润全乘 0 |
| 改动 | `01_源码/beauty_face.*`：`detect()` 增加 `rotateDeg`，旋转做进 letterbox 重采样（零额外帧缓冲）；`01_源码/beauty_core.cpp`：连续无脸时自动试探 90°/270°，命中后按该方向检测并用 `invRotateFace` 反变换回源坐标 |
| 开关 | `BEAUTY_AUTO_ROT=0` 关闭（逐字节回到 `1.0.2.0`）；`BEAUTY_INPUT_ROT=90/180/270` 手工声明方向；`BEAUTY_AUTO_ROT_MISS` / `_COOL` 调阈值 |
| 结论 | 四个方向判据全部符合预期：正立照旧出掩码；旋转源**自动**恢复（第 21 次检测起）；`AUTO_ROT=0` 永远不出（等于修复前）；手工方向立即生效 |

## 1. 台架与做法

`beauty_core_test.dll`（`05_验证/build_core_test.bat` 同一套源文件）→ `BeautyCoreMask()` 每次调用
跑一次检测并回一份 8-bit 掩码；`rot_probe.py` 逐 case 起独立进程（环境变量与引擎静态状态都要干净）：

| case | 输入 | 环境 |
|---|---|---|
| `upright` | `probe_in.raw` 640×394（人正立） | 默认 |
| `auto` | 同帧**逆时针转 90°** → 394×640 | 默认（自动探测开） |
| `auto_cw` | 同帧**顺时针转 90°** → 394×640 | 默认（自动探测开） |
| `auto_off` | 逆时针 90° 帧 | `BEAUTY_AUTO_ROT=0` |
| `manual90` / `manual270` | 逆时针 90° 帧 | `BEAUTY_INPUT_ROT=90` / `=270` |

## 3. 判据 D：正立路径逐字节不变

本轮改动只在「方向 ≠ 0」时才走新代码（`letterboxRgbRot` / `invRotateFace`），但为了证明
**没有夹带其它变化**，用同一台架做了一次前后对比：把 `01_源码` 临时退回到 `1.0.1.0`
（`git stash`）编一份 baseline DLL，与当前 DLL 各跑一次正立帧，比较掩码缓冲区：

```
old ret= 0 px= 18126 OK mask=640x394 px=18126 (7.19%) faces=1
new ret= 0 px= 18126 OK mask=640x394 px=18126 (7.19%) faces=1
identical bytes: True len 252168 252168
maxdiff= 0 ndiff= 0
```

`maxdiff=0` = 正立（未旋转）源的掩码与改动前**逐字节相同**。旋转/竖屏是唯一新增的行为。

## 4. 为什么不是「首个命中就收」

`det_probe.exe` 把同一帧按四个方向各检一次（分数是解码出来的框分数）：

| 帧 | rot=0 | rot=90 | rot=180 | rot=270 |
|---|---|---|---|---|
| 正立 640×394 | **0.920**（1 张脸） | 0.379（无） | 0.820（1 张脸） | 0.338（无） |
| 逆时针 90° 394×640 | 0.338（无） | **0.920**（1 张脸） | 0.379（无） | 0.820（1 张脸） |
| 顺时针 90° 394×640 | 0.379（无） | 0.820（1 张脸） | 0.338（无） | **0.920**（1 张脸） |

**倒立脸也能检出（0.820）**。GPU 版的探测是「先试 90，命中就收」，在顺时针那一档会先撞上 0.820
的翻转框 —— 掩码仍落在脸上，但五位关键点跑到嘴的位置，亮眼/去黑眼圈/法令纹随之错位。
本版两个方向都跑、**取分数高的**，代价是探测帧多一次 640×640 推理（只在连续无脸且有冷却时发生）。

## 6. 本记录不覆盖什么

1. **真机出图**：没在 OBS 里看到画面（本机摄像头 `data.GetDevice failed`）。
2. **代价**：认定方向要等 `BEAUTY_AUTO_ROT_MISS` 次检测（默认 20 ≈ 0.7 秒 @30fps，同步检测
   每 4 帧一次时为 4 倍）；这 0.7 秒内没有美颜。
3. **美形三项**（瘦脸/大眼/下巴）仍按画面轴施加，源被转过 90° 时方向不对 —— GPU 版同样如此，
   本轮未改（见 `docs/CHANGELOG.md` 的「已知边界」）。
4. **动态换向**：机位从横屏拧到竖屏时，靠「方向检不到 → 试 0°」与「尺寸变了就重来」两条路恢复，
   未做长时真机稳定性验证。

> 补正（2026-11-08 17:36）：以上第 1 条描述的是本轮台架取证当时的状态，保留原貌。之后 16:51–17:22 的真机运行已在 OBS 内实际出图，且日志明确记到「连续 20 次检不到脸，自动方向探测命中 270°（score=0.926）」（"2026-11-08 16-51-40.txt" l. 274），补上了本轮「真机出图」与「方向补偿真机生效」两项空白；片内 A/B 性能对照见 `05_验证/ab_perf_20261108.md`。**第 4 条动态换向的长时稳定性仍未验证**，两版 40 项装卸回归也仍未复跑。
