# 脖子通道方向错误：止血（1.0.6.0）与真修（1.0.7.0）

日期：2026-11-09
状态：**离线已验证；真机验证见 §5**（2026-11-09 11:58，`1.0.7.0` 装机路径，零丢帧）
相关：`docs/design/design-face-mask.md` §15、`05_验证/ab20261109_install_and_live.md`

---

## 1. 问题

源需要转 90°/270° 才立正时（本机摄像头正是 270° 这一档），掩码里出现一条**横穿肩膀
落到窗帘上**的带子，而真正的脖子一点没磨。

成因：`buildMaskInto` 的脖子通道全部在**源坐标**里做，从脸框下沿按 `+y` 往下推进。
源要转 270° 才立正时，源坐标的 `+y` 在立正画面里是**横向**的。

`1.0.3.0`（第一次让这台摄像头检出脸的那版）起就一直错着；带子落在窗帘上，不盯着
看不出来，直到 2026-11-09 上午的真机验证对着掩码叠加图才发现。

## 2. 1.0.6.0（止血）：旋转源上整段不画

改动：脖子段加一道方向门槛。`g_effRot % 180 != 0` 时整段跳过，另加 `BEAUTY_NECK=0`
无条件关闭。

为什么选「不画」而不是别的：旋转源上那条带子**严格有害**（背景被磨、脖子没磨），
而脖子本来也没被磨到 —— 少画一条错带子在任何指标上都不更差。

实测（源 1920×1080，`BEAUTY_INPUT_ROT=270` 强制方向）：

| 帧 | ≤1.0.5.0 掩码 | 1.0.6.0 掩码 | 落在脸框（放大 35%）外 |
|---|---|---|---|
| `up10.raw`（正立，录像 10 s） | 145010 px | 101142 px | 40444 px（27.9%）→ **0 px** |
| `tilt22.raw`（歪 45°，录像 22 s） | — | 76822 px | — |

`BEAUTY_NECK=0` 与 1.0.6.0 默认输出**逐字节相同** —— 证明旋转源上脖子确实一点没画。

0° 源（`t5_a0.raw`，1080×1920）掩码与 1.0.5.0 **逐字节相同**（303927 px）。

## 3. 1.0.7.0（真修）：几何参数化到「立正方向」

### 做法

把「正下方」写成源坐标里的单位向量，全部几何改成 `(u, v)` 参数：

```
g_effRot  0   →  d = ( 0, 1)   横 = (+1, 0)
g_effRot  90  →  d = (+1, 0)   横 = ( 0, +1)
g_effRot 180  →  d = ( 0,-1)   横 = (+1, 0)
g_effRot 270  →  d = (-1, 0)   横 = ( 0,-1)

u = 沿 d 离开脸框下沿的距离      v = 横向偏移
X = oxI + u·dx + v·lx            Y = oyI + u·dy + v·ly
```

三种形状（跟随肤色 / 椭圆 / 矩形）与脖子羽化全部只跟 `u`、`v` 走，与源朝向无关。

### 顺带修掉的两个换算错误

1. **旋转源的宽高是交换过的**。`g_effRot=270` 时检测框在源坐标里是 356×259，
   其中 `bw=356` 是脸的**纵向**尺寸（脸高）、`bh=259` 才是横向（脸宽）。
   旧口径一律拿 `bw` 当脸宽 → 脖子按脸的长边铺开，实测宽度多 1.4 倍。
   现在用投影算两个半跨度：

   ```
   halfAlong  = 0.5·(bw·|cos·dx + sin·dy| + bh·|−sin·dx + cos·dy|)
   halfAcross = 0.5·(bw·|cos·lx + sin·ly| + bh·|−sin·lx + cos·ly|)
   ```

   `roll==0` 时它们退化成 `bh/2`、`bw/2`（`ndx≠0` 时互换），与旧式逐位相同。

2. **脖子起点用「脸框沿正下方的下沿」**，倾斜时按上面的投影算，不再固定用外接盒
   底边。倾斜脸的下巴不再和脖子之间留一条 7.5% 的缝（旧口径没乘 `kFaceBoxGrow`）。

### 0° 源为什么能逐字节不变

`(dx,dy)=(0,1)`、`(lx,ly)=(1,0)` 时：

* 横向基向量取 `+x` 而不是 `−y` 那一支 —— 旧实现从 `nx0` 往右递增、羽化按「离左右
  边界的距离」算，取反会把羽化和肤色探测一起镜像（实测差 4012 px，整体右移 2 px）。
* 原点取整沿用旧口径：`oxI = (int)cx`、`oyI = y1`（已 clamp 的 int），`uLen = ny1 - y1`。
* `extU = 0.5·(bw·0 + bh·1)·grow` 与旧 `hh` 是同一个表达式，逐位相同。

实测 `t5_a0.raw` 掩码 = 303927 px，与 1.0.5.0 / 1.0.6.0 的 PGM **逐字节相同**。

### 实测（立正坐标系下统计）

`up10.raw`，源 1920×1080，270°；脸框换算到立正画面后 259×356、下巴在 y=809。

| 版本 | 掩码总量 | 横向远于 0.85 脸宽 | 向下延伸到 |
|---|---|---|---|
| 1.0.5.0 | 145010 px | **26154 px（18.0%）** ← 那条带子 | y=834（下巴下 25 px） |
| 1.0.6.0（止血） | 101142 px | 0 px | y=834（脖子没磨） |
| **1.0.7.0** | 114684 px | **0 px** | **y=901（下巴下 92 px）** |

即：横向溢出归零的同时，掩码第一次真的往下覆盖到脖子。

叠加图：`_live1509/a_up10_ov.png`（正立）、`_live1509/a_tilt22_ov.png`（歪 45°）。

### 回归（全部通过）

| 场景 | 帧 | 结果 |
|---|---|---|
| 0° 正立 | `t5_a0.raw` 1080×1920 | 掩码 303927 px = 14.66%，**逐字节不变** |
| 0° + 歪 45° | `t5_a45.raw` | `倾斜探测命中 +45°（score=0.901）`，掩码 19.25% |
| 真机方向 | `cam270.raw` 1920×1080 | 方向探测命中 270°，掩码 14.73% |
| 真机方向 + 歪 45° | `cam315.raw` 2122×2122 | 先命中 270°（0.759），再命中 −45°（0.906），掩码 7.77% |

性能（`cpu_bench`，`up10.raw` 1920×1080 40 帧）：

```
只开磨皮 26  全帧 (修前)      = 24.07 ms
只开磨皮 26  掩码 ROI(修后)   =  7.38 ms   ratio 0.307  省 69%
全开(掩码 ROI) = 22.18 ms     全开(强制全帧) = 38.55 ms  ratio 0.575
```

脖子通道多出来的面积没有把 ROI 拖回去 —— 它沿立正方向走，落在脸框正下方，
而旧版把它甩到侧面，ROI 反而更宽。

`_live1509\v103` 里的是历史副本；改完源码忘了分发，测出来的还是旧版本的结果。

## 6. 仍未做 / 已知残留

* **脖子矩形会落到浅色衣服上**：`g_maskShape=0`（生产默认）是矩形 + 肤色权重，
  上衣若是浅灰/米色会通过 `skinWeight`。人前倾时「下巴下 0.65 脸高」就到胸口了，
  于是胸口被磨一块（`_live1158/t030_full.png` 左下）。这是 **0° 源同样存在**的
  老行为，不是这次引入的；要收住得把默认形状换成 `&4`（逐行跟随肤色轮廓）或
  缩短 `kNeckLen`，另立项。
* `1.0.6.0` / `1.0.7.0` 都还没重打装机包（`06_安装包\` 仍停在 `1.0.3.0`）。**2026-11-09 补记：现已重打 `OBS美颜_CPU_v1.0.13.0.exe`，本条只描述当时的状态。**
