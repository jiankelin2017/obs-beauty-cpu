| 字段 | 值 |

| 日期 | 2026-11-09 |
| 版本 | `1.0.7.0` → `1.0.8.0` |
| 目的 | 只提速，不改任何像素。验证「改了之后画面逐字节相同」+「真的变快」 |

## 0. 结论

| 项 | 结果 |
|---|---|
| 画面是否变 | **没变**。三份素材、两种分辨率、走 ROI 与走全帧兜底，`dumpOut` 全部逐字节相同 |
| 磨皮 ROI 是否变快 | **是**。`f1.raw` 1080p：10.64 → **7.04 ms（−34%）**（3 轮交替取中位数） |
| 全开是否变快 | 是但幅度小：25.45 → 23.92 ms（−6%），因为清晰/全局锐化/五官没动 |
| 进程 CPU 占用 | 3.36 → **4.53 核**（同一份 150 帧窗口），即「活真的摊到多核上了」 |

## 1. 改了什么

三处，全部在 `01_源码/`：

| # | 文件 | 改动 |
|---|---|---|
| A1 | `beauty_smooth.cpp` | `boxPlaneV` / `bandBoxV` 的列块宽 32 → 8；`surface3RgbBand` 的 `bt` 阈值 150000 → 8192 像素 |
| A2 | `beauty_smooth.cpp` | `surface3RgbBand` 里 ROI 外整帧拷贝（1080p 约 6~7 MB）由单线程 `for+memcpy` 改 `runRange` 按行并行 |
| A4 | `beauty_core.cpp` / `obs-beauty.cpp` | 新增 `forceOpaque()`（SSE2），在 `process()` 四个返回点调用；删除插件层那段 207 万次 32 位读改写 |

A1 的根因值得单独记：`runRange` 的并行度只由「任务数 = 块数」决定，且内部有
「每线程至少 16 行」，所以半分辨率 ROI（平面宽 ≈384）用 32 列块只有 12 个任务 →
`12 < 32` → 整个垂直 pass 被判成单线程。垂直 pass 是磨皮里最重的一段
（13 平面 × 3 趟 × 3 组），从双尺度带通上线起一直只占一个核。详见
`docs/design/design-cpu-performance.md` §2.5。

## 2. 逐字节验证（先证明「没改画面」，再看快多少）

两件二进制：`v107base`（把 A1/A2 反向改回的 `beauty_smooth.cpp` + 其余同当前源码）、
`v108`（当前源码）。同一素材、同一参数、`BEAUTY_SKIN_EMA=0`、异步检测由台架默认关闭。

| 素材 | 尺寸 | faces | 走的路径 | `dumpOut` 比对 |
|---|---|---|---|---|
| `f1.raw` | 1920×1080 | 1 | ROI（磨皮/清晰/五官都按掩码） | **完全相同**（8,294,400 B） |
| `probe_in.raw` | 640×394 | 1 | ROI（小画幅，`bt` 两版都单线程） | **完全相同** |
| `up10.raw` | 1920×1080 | 0 | 全帧兜底 + 色调整帧 | **完全相同**（含 A 通道） |

命令（工作目录 `%TEMP%\bb108`，ASCII 路径，`models\yunet.onnx` 需在同目录）：

```
BEAUTY_SKIN_EMA=0 bench_base.exe f1.raw 1920 1080 20 f1_base.raw
BEAUTY_SKIN_EMA=0 bench_new.exe  f1.raw 1920 1080 20 f1_new.raw
```

三条都 `identical: True`。`up10.raw` 的 faces=0 是素材本身（人不在画面里），
正因为它走的是「全帧 + 整帧色调」这条另一条路径，才拿出来单独验一遍。

## 3. 耗时（`f1.raw` 1920×1080，faces=1，各跑 3 轮交替取中位数）

| 项 | `1.0.7.0`（v107base） | `1.0.8.0`（v108） | 变化 |
|---|---|---|---|
| 只开磨皮 26 · 掩码 ROI | 10.64 ms | **7.04 ms** | −34% |
| 只开磨皮 26 · 强制全帧 | 22.87 ms（单次） | 15.14 ms（单次） | 全帧路径本不该变；两次读数差这么多说明本机台架噪声大，不作结论 |
| 全开 · 掩码 ROI | 25.45 ms | 23.92 ms | −6% |
| 全开 · 强制全帧 | 39.39 ms | 30.12 ms | 噪声大，不作结论 |
| 进程 CPU 占用（150 帧窗口） | 3.36 核 | 4.53 核 | +35% |

原始三轮读数：

```
base blur [10.06, 10.64, 10.81] median 10.64
base all  [25.34, 25.45, 42.89] median 25.45
new  blur [ 6.86,  7.04, 12.27] median  7.04
new  all  [23.25, 23.92, 38.48] median 23.92
```

> ⚠️ 台架噪声不小（同一份 exe 的第三轮会跳到 12.27 / 42.89），所以一律取中位数，
> 不取平均；`全开 强制全帧` 那一行两版差异是噪声，不作为「全帧路径也变快」的证据。

## 4. 真机验证

**待补**：装机需要管理员令牌（`C:\ProgramData\obs-studio\plugins\...\obs-beauty.dll`
对 `BUILTIN\Users` 只有 `(I)(RX)`），本轮会话的 `Start-Process -Verb RunAs` 被
工具安全策略拦截，改为用户手动运行 `03_装机/install_1.0.8.0.bat`。

装机后要看的四件事：

1. init 行必须是 `init OK (CPU v1.0.8.0, ...)`；
2. `BEAUTY_PROFILE=1` 的分项应从「下载 2.25 + 引擎 10.0 + 上传 1.44」变成
   「引擎 ↓约 2.5~3 ms、上传 ↓约 0.3~0.4 ms」（引擎与上传的界线会移动：A 通道置位
   从上传段挪进了引擎段）；
3. `self-check: out_tex mean` 必须仍在 140 左右 —— 若变成 0.0，说明 A 通道置位漏了；
4. 一段 60 s 录制零丢帧，画面与 `1.0.7.0` 逐帧目视无差。
