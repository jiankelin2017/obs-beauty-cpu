# 头歪 45° 美颜失效 · 根因与修复验证（1.0.5.0）

| 字段 | 值 |
|---|---|
| 日期 | 2026-11-09 |
| 版本 | `1.0.5.0`（`1.0.4.0` → 功能位 +1） |
| 触发 | 用户报：人物**身体立正**、只有**头歪 45° 左右**时，美颜明显失效 |
| 场景约束 | 摄像头已关闭，全程离线复现（用户去睡觉） |
| 结论 | **已修**。根因两层，都已消除；`roll==0` 的画面逐字节不变 |

---

## 1. 复现

素材：`2026-11-09 01-35-26.mp4` 抽帧 → 得到正立帧 `t5_a0.raw`（1080×1920 RGBA），
再用 PIL 机械旋转出 `t5_a30.raw` / `t5_a45.raw`。

用 `05_验证/det_bench.exe`（单帧检测探针）直接看 `detect()` 的原始输出：

```
+0.0°   faces=0        ← 45° 歪头，一个框都没有
+30.0°  score 0.886
+45.0°  score 0.901    ← 反向补 45° 就检得到
-45.0°  faces=0
```

**第一层根因**：YuNet 对平面内倾斜的召回边界在 30~40° 之间。30° 还有 `score 0.773`，
45° 直接归零 → 掩码为空 → 磨皮 / 美白 / 红润全乘 0，日志 `faces=0`。

### 1.1 第二层：真机上更常见的不是「检不到」，而是「框是错的」

真机这条路的源需要转 270° 才正立。把正立帧转 -90° 造出「真机方向」，再叠 45° 歪头，
得到 `cam315.raw`，在补偿角上扫：

```
+315.0°  faces=0                          ← 方向 + 正倾斜：失败
+225.0°  score 0.906  eye/max 0.337       ← 真正的补偿角
+270.0°  score 0.759  eye/max 0.216       ← 只补方向、不补倾斜
```

`+270°` 那一行就是要命的地方：**框在那儿、分数也过阈值（0.759 > 0.6）**，但双眼间距
只有框宽的 28%（正立脸 43~47%），说明框被撑大且位置偏移 —— 掩码照样糊错地方。
这种帧 `detOk` 为真，既不会触发 90/270 方向兜底，也永远轮不到倾斜探测。
用户看到的「美颜失效」，一半来自这一档。

**修前实测**（`mask_dump.exe`，40 帧）：

```
cam270（正立，仅方向）      faces=1  掩码 18.11%
cam315（真机方向 + 45° 歪头）faces=1  掩码  6.76%   ← 锁在 270° 的敷衍框上
```

## 2. 修法

### 2.1 检测侧：±45° 倾斜探测 + 假框门槛

- 连续 `BEAUTY_AUTO_ROLL_MISS`（默认 8）次「检不到脸 **或** 框明显不像人脸」后，
  在合成角（方向 + 倾斜）上各试一次 `+45° / -45°`，命中就记下来。
- **必须配质量门槛**，这不是保险：反向候选会把倾斜累加到接近 90°（侧躺），
  YuNet 在那里的输出是「画面里某块像脸的纹理」。实测三档分得很开：

  | 类别 | score | 双眼间距 / 框长边 |
  |---|---|---|
  | 真框 | 0.886 ~ 0.920 | 0.332 ~ 0.370 |
  | 敷衍框（只补方向） | 0.759 | 0.216 |
  | 假框（反向补偿） | 0.661 ~ 0.690 | 0.078 ~ 0.103 |

  门槛取 `score ≥ 0.75` + 比值 ∈ `[0.25, 0.62]` + 眼睛在嘴上面，两侧各留 25% 余量。
  没有门槛时「取分数最高的那个」会把假框**锁死**：之后每帧都检不到脸，而且因为
  一直「有框」，方向兜底也不会来救 —— 比不修更糟。

- 已经有框只是敷衍时，要求候选**明显更好**（`+0.05`）才换角度。否则会在两个角度
  之间来回跳，而每跳一次都要清人脸框的 EMA，画面会抖。

### 2.2 掩码侧：按「倾斜矩形」画，不按「外接盒」画

反变换回源坐标时，倾斜的框只能退化成轴对齐外接矩形：45° 时外接盒面积是脸本身的
**2.8 倍**（723×723 vs 439×584）。照外接盒画掩码的后果：

- 磨皮糊到脸外面（椭圆半轴被撑成正方形 → 画成一个大圆）；
- ROI 白涨一倍，`只开磨皮` 从 10.5 → 19.5 ms，而脸一点没变大。

于是 `FaceBox` 多带三个字段：`roll`（倾角）、`rw/rh`（脸自身宽高，即倾斜矩形的边长）。
掩码逐像素先把坐标转进**脸自己的坐标系**，再按 `(rw, rh)` 画：

- 矩形路径（默认，`g_maskShape=0`）：新增一个「倾斜矩形距离场」分支；
- 椭圆路径（`g_maskShape&1`）：半轴改用 `rw/rh`，坐标先旋转；
- 脖子通道：**保持竖直**（用户报的是「身体立正、只有头歪」，脖子本来没歪），
  只把宽度换回 `rw`、起点换回脸自身的半高；
- 五官保护椭圆：尺寸改用 `rw/rh`。

### 2.3 `roll == 0` 的逐字节保证

所有新分支都以 `rolled != 0` 或 `bw/bh` 的形式进入，而未倾斜时：

- `f.rw` 恒为 0 → `bw = f.w`、`bh = f.h`；
- `cosf(0) = 1.0f`、`sinf(0) = 0.0f`（精确值），故 `ux = dx*1 + dy*0 = dx`、
  `uy = dy*1 - dx*0 = dy`，与旧式**逐位相同**；
- `hw = 0.5f*(bw*1 + bh*0)*grow` 与旧式 `f.w*grow*0.5f` 只是乘法顺序不同，
  两次乘除都是精确的 2 的幂缩放，结果逐位相同；
- 默认矩形路径（`else` 分支）的源码**一行未改**。

## 3. 修后实测

### 3.1 检测

```
t5_a45   +45°  score 0.901  eye/max 0.351   ← 命中，勾上闸门
t5_a30   -30°  score 0.690  eye/max 0.095   ← 假框，被闸门挡掉（修前会被选中）
cam315   -45°  score 0.906  eye/max 0.337   ← 先命中 270°，再命中 -45°
```

`cam315` 的日志链（`mask_dump.exe`，300 帧）：

```
[美颜] 连续 20 次检不到脸，自动方向探测命中 270°（score=0.759）
[美颜] 倾斜探测命中 -45°（score=0.906）：本帧人脸在画面内倾斜了约 45°，已自动补偿
computeMask=ok  faces=1
```

注意第二行：方向探测先给了 0.759 的敷衍框，质量判定不通过，倾斜探测才接上，
把它换成了 0.906。这正是 §1.1 那一档的闭环。

### 3.2 掩码形状

`_probe_run/_m_a45_geo.png` / `_m_cam315_geo.png`（绿色线是理论倾斜矩形）：

- 掩码**正好填满**绿色斜框，四边都是斜的，没有溢出到外接盒的四个角；
- 脖子通道是一条竖直的淡带，起点在脸下方，不跟着脸转。

### 3.3 覆盖率与成本（1080×1920，真机档位）

| 场景 | 掩码覆盖 | 只开磨皮（ROI） |
|---|---|---|
| 正立（对照） | 14.66% | 10.6 ms |
| 45° 歪头 修前 | **0%（完全失效）** | — |
| 45° 歪头 只修检测 | 25.2%（外接盒） | 19.5 ms |
| 45° 歪头 修后 | 18.35% | 17.6 ms |

正立那行的 `14.66%` 与修前**完全相同** —— 这是 §2.3 逐字节承诺的实测证据。

### 3.4 剩余代价（已知，接受）

歪头时 ROI 仍是斜框的**外接盒**（面积约 2×），所以磨皮 10.6 → 17.6 ms。要彻底省掉
得把 ROI 裁剪改成逐行（band 路径现在是一次性裁剪 + 整块处理），属于另一个优化项目。
考虑到「头歪着」是瞬时状态，且修前是**完全没效果**，这个代价明确可接受。

```bat
rem 性能
05_验证\_probe_run\v103\cpu_bench.exe <frame.raw> <w> <h> 40

05_验证\build_cpu_bench_v103.bat

```

环境变量：`BEAUTY_FACE_MODEL=yunet.onnx`（放在 exe 同目录），`BEAUTY_AUTO_ROLL=0` 关掉
整个头歪补偿，`BEAUTY_AUTO_ROLL_MISS=8` 调触发阈值（2~600）。

测试帧：`05_验证/_probe_run/` 下 `t5_a0/a30/a45.raw`（正立 + 机械旋转）、
`cam270.raw` / `cam315.raw`（真机方向 + 歪头，由 `t5_a0` 用 PIL 转出来）。
