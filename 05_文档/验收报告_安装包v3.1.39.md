## 三、方法

两轮，都在同一台真机上：

**Phase A —— 模拟全新机器**
1. 把 4 个已装文件复制到安全目录（md5 存档）
2. 从装机位置删掉这 4 个文件、删掉 `models\` 目录、删掉 ProgramData 面板目录
3. `OBS美颜_Setup_v3.1.39.exe /S`
4. 核对：4 个文件 md5 是否与包内逐位相同；卸载器 / README / md5 清单；两处注册表；开始菜单
5. `Uninstall_OBS美颜.exe /S`（轮询注册表键消失确认卸完，最多 120 s）
6. 核对：4 个文件、`models` 空目录、ProgramData 目录链、安装目录、两处注册表、开始菜单 是否全部消失

**Phase B —— 覆盖装 + 备份还原**
1. 把原文件放回装机位置
2. `setup /S`（此时应触发「装前有文件 → 先备份」分支）
3. 核对：文件正确；`backup\obs-beauty.dll.bak` 存在；`ModelsCreated=0`（目录装前就有）
4. `Uninstall /S`
5. 核对：4 个文件**逐位还原**；`models` 目录保留；安装目录与注册表清空

**判据**：`Start-Process -Wait` 取安装器退出码；卸载器会把自己复制到 `%TEMP%` 再运行，
所以用「注册表键消失」当完成信号，再等 1.2 s 给删目录留时间。

## 五、测试打出来的两个真 BUG

测试不是走过场，第一版就挂了两次：

**BUG 1 — 包内自检写错时机，安装直接退出码 2（什么都没装）**

`.onInit` 里加了「源文件自检」，检查 `${SRCDIR}\filter\obs-beauty.dll` 是否存在。
`File` 是**编译期**把内容写进 exe 的，安装时根本不需要暂存目录，而 `build_setup.ps1`
编完就把 `%TEMP%\obsbeauty_pkg` 清了 → 自检恒假 → `Abort` → 退出码 2。

第一次测试之所以「通过」，是因为那轮用了 `-KeepStage`（暂存目录还在）——**测试恰好掩盖了 bug**。
改成不带 `-KeepStage` 再测才暴露。

修法：自检移到编译期 `!if ! /FileExists … !error`，并做了反向验证
（`/DSRCDIR=C:\__nope__` 编译必须失败，实测报 `!error: source missing: …` 并退出 1）。

**BUG 2 — `/DOUTFILE` 带中文，产物名变乱码**

makensis 按控制台代码页解析命令行，`OBS美颜_Setup_v3.1.39.exe` 被写成 `OBS????_Setup_v3.1.39.exe`。
修法：先以 ASCII 名编译，再用 PowerShell 改名为中文。

> 教训与 C13 坑 #3 同源：**NSIS 只在 ASCII 路径上可靠**。源路径、输出路径都要过一手。

## 六、没验证的部分（明确边界）

1. **安装向导每页的截图核对**。静默模式跳过了所有页面，只验证了落地行为。
   字符串编码按 UTF-16LE 抽查过（`OBS美颜` / `安装程序` / `参数面板` / `滤镜` 均在 exe 内），
   但「界面排版有没有串位/截断」需要人眼。
2. **OBS 启动后能不能真的加载**。这次没启动 OBS —— 装进去的 4 个文件与测试前逐位相同，
   而测试前那份已被 `2026-10-30 20-11-01.txt` 日志证明可 `init OK (v3.1.39, engine=core/1.4.0)`。
   若换了新构建，仍需按 `09_安装包\README_打包说明.md` §「装完怎么确认」看日志。
3. **绿色版 / 非默认路径 OBS**。检测只认注册表 `HKLM\SOFTWARE\OBS Studio` 的(默认)值
   （缺失时退回 `%ProgramFiles%\obs-studio`）。ProgramData 走环境变量，没测过被重定向的情形。
4. **升级跨越多个大版本**（比如从 3.0.20 直接装到 3.1.39）。APPID 与安装目录沿用旧包，
   理论上算覆盖升级；但没造过 3.0.20 的装机现场来实测。
