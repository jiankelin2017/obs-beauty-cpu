# 3.0.17 优化报告：磨皮模式（结构自适应细节回填）

日期 2026-10-26 · 目标：把磨皮干净度与纹理立体感推向第三方「美颜 2.4.2」的 90~95%
上一版 3.0.16（`clarity` 下发 + 祛斑痘滑块）

---

## 0. 结论先行

这一版做了两件事，一件是**否证**，一件是**实现**：

1. **否证：NamaSDK 里没有隐藏的"磨皮质感"开关。** 我把 166 个候选参数名逐个注入实测，
   只有 12 个真正改变输出，全部是已知项或美型项。第三方面板上那四档「磨皮模式」
   **不是 SDK 参数**，是它自己的后处理 —— 这条路到此为止，不必再找。
2. **实现：自己写了一套"按局部结构分配细节"的回填算法**，做成同样的四档下拉框。
   在磨皮 50 这档上，它让**四个指标同时变好**：皮肤更干净、边缘更立体、总细节更多、
   帧间更稳。这是本项目第一次出现"细节↑ 而闪动↓"同时成立（以前两者必然互斥）。

| 指标（磨皮50/锐化50，10 帧，1074×604，脸内） | 人像磨皮（旧行为） | 清晰磨皮 | 变化 |
|---|---|---|---|
| 平坦区残留高频（↓ = 更干净） | 1.767 | **1.470** | **−16.8%** |
| 边缘/轮廓对比幅度（↑ = 更立体） | 11.964 | **13.932** | **+16.5%** |
| 脸内总细节 std（↑ = 纹理更多） | 5.691 | **6.435** | **+13.1%** |
| 脸内帧间闪动（↓ = 更稳） | 1.650 | **1.587** | **−3.8%** |
| 背景改动（应≈0） | 0.0041 | 0.0038 | ≈0 |

叠上「清晰」滑块 60 后：边缘对比 **+22.8%**、总细节 **+19.3%**，闪动仍 −3.3%。

3. **泛化：算法抗噪，但救不了错位的掩码。** 在主素材上把噪声从 ±5 加到 ±15，收益
   反而更大（平坦 **−25.0%**、闪动 **−11.5%**）；加到 ±30 才失效（平坦 +13.9%）。
   而换到另一段真实素材时出现"符号相反"，逐帧核对后查明是 **fuai 给出的肤色掩码
   在该画面上错位并漂移**（有掩码叠加图），四档因此全部打空 —— 问题在上游分割，
   不在本算法。详见 **§6**。

> 一句话给决策用：**「人像磨皮」是安全档**；「清晰磨皮」在掩码正常的画面上是净增益
> （噪声越大越明显），但如果画面里脸很小 / 带黑边导致分割错位，四档都等于没有。
> 下一版最值钱的一刀是给掩码加自检兜底，而不是继续调阈值。

## 2. 实现：按局部结构分配细节回填

### 2.1 问题

细频带（1~2px）里混着两种完全不同的东西：

- **平坦皮肤上的毛孔、相机噪点** → 该抹掉（这就是"干净度"）
- **睫毛、鼻翼、镜框外沿、唇线** → 该保留甚至加强（这就是"立体感"）

3.0.0~3.0.16 只有一个全局 alpha，两者一视同仁：想干净就整体压（边缘一起糊），
想立体就整体推（皮肤上全是颗粒、帧间还闪）。

### 2.2 做法

结构强度直接复用循环里已经算好的中频带 `|h_mid|`（`box3 − box7`，3~7px 差分量，
1/64 级定点），**不额外扫一遍图**，代价只有每通道一次比较：

```
t = clamp((|h_mid| − 0.75级) / (4.0级 − 0.75级), 0, 1)     // 0=平坦 1=结构
a0 = am × base
a0 -= a0 × flat × (1 − t)                                  // 平坦区衰减
a0 += a0 × edge × t                                        // 结构区增强
```

阈值不是拍脑袋定的：实测该帧脸内 88811 像素的 `|h_mid|` 分布为
**P50 0.74 级 / P75 1.47 / P90 4.13 / P95 10.2**，所以取 0.75 级以下为"平坦"
（约六成皮肤像素）、4 级以上为"结构"（约一成，全是五官边缘）。

只调**脸内**那一份（`am`），脸外的「全局锐化」（`amG`）保持原样，否则全局锐化的
含义会被模式污染。

### 2.3 四档（`nama_engine.cpp` 的 `kTexModes[]`）

| 档 | base | flat | edge | 用途 |
|---|---|---|---|---|
| 0 人像磨皮（默认） | 256 | 0 | 0 | 3.0.16 行为，不做任何调制 |
| 1 清晰磨皮 | 256 | 256 | 300 | 平坦区完全不接细频 + 结构区 +17% |
| 2 精细磨皮 | 200 | 200 | 180 | 整体收一档，平坦再压、结构略提 |
| 3 朦胧磨皮 | 140 | 0 | 0 | 整体压细频，结构区也不加（柔光镜观感） |

`edge` 之所以取 300 不取 512：512 能让边缘对比到 +27%，但 4 倍放大后镜框白边发"脆"，
300 已经够立体且自然（`out/mode_cmp/zoom4x.png` 是这组对比）。

### 2.4 一个必须补的坑：基准回填

回填是否执行原先完全由「锐化」/「清晰」两个滑块决定。**最常见的用法是只开磨皮、
这两项都是 0** —— 那时根本没有回填可调，新下拉框会静默失效。
所以「清晰磨皮」和「精细磨皮」在两项都为 0 时**自动按「锐化 50」做基准回填**
（实测：只开磨皮时切到清晰磨皮，总细节 3.507 → 6.435，边缘对比 6.865 → 13.932）。
「人像磨皮」不做这件事，保持旧行为。

## 4. 与第三方的距离（诚实评估）

- **能确定兑现的**：立体感与干净度这两个**可量化维度**同时改善（边缘 +16.5%、
  平坦 −16.8%）。叠「清晰」60 后边缘 +22.8%。
- **不能确定的**：这能否等于对方的观感。对方的四档模式是自研后处理，算法未知，
  没有它的输出就做不了逐像素对标。离线指标只能证明"朝正确方向走、且没有副作用"。
- **如果还差一截**，剩下的方向按性价比排序：
  1. 对方的"清晰磨皮"可能同时降低 SDK `blur_level` 并加强自研平滑 —— 可以试
     「磨皮 50 + 内部按 35 下发 + 更狠的结构权重」，属于同一套框架内调参。
  2. 接美型三件套（`cheek_small` / `intensity_eye_lid` / `intensity_lip_thick` 已实测可用），
     但那是"变好看"，不是"磨皮质感"。
  3. 上真算法（引导滤波 / 频域分离 + 边缘保持平滑）替换 SDK 磨皮 —— 工作量大一个量级。

## 6. 泛化验证：噪声鲁棒、换素材失败（原因已查明是掩码，不是算法）

这一节是本版本最容易被误读的部分，按"做了什么、看到什么、怎么解释"写清楚。

### 6.1 素材

| | 素材 A（主素材） | 素材 B（换素材测试） |
|---|---|---|
| 来源 | `out/frame_0.png` 1074×604 + 均匀噪声 ±5/帧 | `face_src.png` 640×394，另一人 / 另一光线 / 门店背景 |
| 脸内 1~2px 细频本底（磨皮50/锐化50 基线） | 1.77 | 6.43~6.82 |

### 6.2 第一步：直接把算法搬到素材 B —— 失败

| 素材 | 平坦高频 | 边缘对比 | 总细节 | 闪动 | 脸内被改动的像素 |
|---|---|---|---|---|---|
| A 1074×604 | **−16.81%** | **+16.45%** | +13.09% | −3.81% | **91.2%** |
| B 640×394 | **+10.97%** | +6.78% | +0.76% | +2.09% | 19.3% |
| B 1280×788（2× 放大） | **+8.00%** | +3.40% | +0.25% | +0.73% | 7.6% |

A 的数字在改代码重编后**逐位复现**（`recheck_big.py`：1.767→1.470），不是测量漂移。
B 的两档都符号相反，而且"只改动 19% 的脸内像素"本身就不对劲 —— 如果 `am` 真被推到 0，
整脸都该变。

（这一步之前还踩了一个夹具 bug，见 §6.5。）

### 6.3 第二步：把掩码叠回画面看 —— B 的掩码是错的

用 B 自己的掩码（`mask_bx_m0.raw`，md5 `301d27dc…`，已确认是本轮转储）叠到画面上：
绿线是一条**窄竖条**，只压住右半张脸一直拖到头发和胸口；换第 10 帧再看，这条带子
又飘到了左侧、盖在头发和背景上。而 A 的掩码（`chk_mask_A.png`）严丝合缝地贴着
额头→脸颊→下颌→颈部，停在下巴领口。

⇒ **素材 B 上 fuai 的肤色掩码本身错位且漂移**。掩码错位时 `mv≈0`，`am` 也就≈0，
于是"四档下拉框几乎什么都不改"——这正好解释了 19% 那个怪数字，也说明
B 的负面结果**不能用来判定算法好坏**。图：`06_离线验证/3.0.17_泛化验证/`。

### 6.4 第三步：在 A 上只加噪声（掩码保持对齐）—— 鲁棒到 ±15，±30 失效

把 A 的同一张底图分别加均匀噪声 ±15 / ±30（各 10 帧），重跑模式 0/1：

| 噪声 | 平坦高频 | 边缘对比 | 总细节 | 闪动 |
|---|---|---|---|---|
| ±5（原素材 A） | 1.767 → 1.470（**−16.8%**） | +16.5% | +13.1% | −3.8% |
| ±15 | 6.187 → 4.639（**−25.0%**） | +17.1% | +0.8% | **−11.5%** |
| ±30 | 12.475 → 14.211（**+13.9%**） | +16.4% | +2.2% | +11.6% |

关键：**±15 的平坦本底（6.187）与素材 B（6.43~6.82）几乎相同，而这一档的效果是所有
档里最好的**（平坦 −25%、闪动 −11.5%）。所以"素材噪声大"不是 B 失败的原因，
B 失败纯粹是掩码错位。

±30 才是真失效：此时脸内 1~2px 本底已到 12.5 级，"结构"判据被噪声整体占满
（flat 集合从 23041 px 掉到 13023 px），平坦抑制无从下手，只剩 `texEdge` 的增强，
于是平坦区反而更毛（+13.9%）、闪动也升（+11.6%）。

### 6.5 顺手修掉的夹具 bug（会影响所有复用该探针的脚本）

`nz_probe_dlldir.run()` 原来取掩码用 `sorted(mask_dump_*)[-1]`，而 `clear_dump()`
早前被改成空操作（避开沙箱删除计数），目录里会残留上一次 60 帧运行的
`mask_dump_059.raw`。于是第一次跑 B 时拿到的是**素材 A 的掩码**（两份 md5 都是
`c4bf880d…`），flat/edge 划分全错，得出过一个假的"+4.01%"。
已改为按 mtime 取本次 run 写出的最后一个转储。**任何复用这个探针的脚本都要检查这一点。**

### 6.6 结论与产品决策

- 算法本身**对噪声是鲁棒的**：噪声越大（±5→±15），平坦抑制和降闪动的收益反而更明显；
  到 ±30 这种极端档才会失效并轻微反向。
- 真正的风险不在算法，而在**上游掩码**：某些画面（小脸 / 带黑边 / 噪声形式不同）
  fuai 的分割会错位甚至漂移，此时磨皮只作用在错的地方，四档全部形同虚设。
  这个问题影响的是整个"只磨皮肤"的设定，不只是 3.0.17 的新档。
- **默认档保持 0（人像磨皮）**，这一条不变；模式 1 在干净源和中等噪声源上都是增益，
  可以放心试。
- 下一步（v3.0.18 候选，按优先级）：
  1. 给掩码加**自检**：用覆盖率 + 与上一帧的重合度做一个廉价健全性检查，明显异常时
     退回"整脸/整帧"兜底，而不是拿一张错位的掩码硬磨。这是比调阈值更值钱的一刀。
  2. `kTexLo` / `kTexHi` 仍是绝对阈值，±30 那档的失效说明可以做成噪声自适应
     （用脸内 `|h_mid|` 中位数当噪声底）。
