## 3. 逻辑：SDK 磨皮的完整管线（已验证）

### 3.1 档位映射（动态实测，非推断）

```
面板 t (0–100)
  └─ OBS 层恒等透传，不做 ÷100
  └─ SDK 内部 ÷100 → blur_amount ∈ [0,1]
  └─ blur_intensity = 0.75 × blur_amount      （精确成立）
```

`< 0.001` 时直接返回原图。

### 3.2 强度重映射与 evenfactor（逐字源码）

```glsl
intensity = mix(intensity * 1.4286, 1.0, step(0.7, intensity));
lowp float evenfactor = mix(0.3, intensity - 0.3, step(0.6, intensity));
```

注意：第二行的 `intensity` 是**第一行重映射之后**的值。

展开：

| 原始 `I` | `I₁` | `evenfactor` |
|---|---|---|
| `I < 0.42` | `1.4286·I < 0.6` | **0.3**（常数） |
| `0.42 ≤ I < 0.7` | `[0.6, 1.0)` | **1.4286·I − 0.3** |
| `I ≥ 0.7` | `1.0` | **0.7**（常数） |

**关键推论**：`I ≥ 0.7` 之后，`I₁` 和 `evenfactor` 都不再变化 → **第二级在 70 档以上完全饱和**。75→100 的差异**全部来自第一级预模糊**（`blur_intensity` 0.5625 → 0.75）。

### 3.3 两级结构

```
原图
  ├─ 第一级（prog 64）：预模糊 + LUT 提亮
  │    blur_intensity = 0.75 × t
  │    LUT: 8×8×64（512×512 图集）
  │
  └─ 第二级（prog 70）：
       tex_surfaceblur1 / tex_surfaceblur2（由 prog 67 生成）
       even = clamp(C − blur1 + blur2, 0, 1)
       even = mix(even, blur2, skin · evenfactor)     ← 位置待确认
       res  = C + (even − C) · I
       out  = C + (res − C) · (1 − eye)
       out  = mix(C, out, skin)                        ← nonskin_blur_scale = 0
```

### 3.4 表面模糊核（prog 67，逐字数学式）

**同一核串行两趟**，不是两种模糊：

| | blur1 | blur2 |
|---|---|---|
| 趟次 | pass 1 | pass 2 |
| 输入 | 原图 | **blur1 本身** |
| `yFactor` | 40 | 20 |
| 色差容限 | 0.1581 | 0.2236 |
| 输出 | 540×960 | 540×960 |

权重公式：

```
Δgk = Ck.g − C0.g
wk  = 1 − min(Δgk² · yFactor, 1)        ∈ [0,1]
out = (Σ wk·Ck + C0) / (Σ wk + 1)
```

必须照抄的四个细节：

1. **空间权重恒为 1**（盒式核，不是高斯）
2. **值域权重是二次抛物线截断**（不是指数，不是 L1）
3. **只测绿通道**（不是亮度，不是 HSV 的 V）
4. **25 tap**：8 方向 × 3 环（`lens = 1,2,5`，比例 1:2:5）+ 1 个中心点

### 3.5 采样几何（实测）

UV 空间半轴固定：`sx = 0.002640845`、`sy = 0.0046875`（比值 1.775）。

像素步长随处理分辨率变化：

| 输入 | 处理分辨率 | 环1 | 环2 | 环3 | 形状 |
|---|---|---|---|---|---|
| 1920×1080（横屏） | 960×540 | 2.53 / 2.53 | 5.07 / 5.07 | 12.67 / 12.67 | **圆** |
| 1080×1920（竖屏） | 540×960 | 1.43 / 4.50 | 2.85 / 9.00 | 7.13 / 22.50 | **椭圆 3.16:1** |

**结论**：核按 `1136×640` 横屏参考分辨率生成，**没有随画幅自适应**。横屏下是圆核，竖屏下竖向拉长 3.16 倍。

上采样回 1080p 后，竖屏最大环步长为 **14.26 / 45.0 px**。我们之前拟合出的 `r=14` 正好等于这个水平步长——数字对得上，但形状是圆的，所以观感不对。

### 3.6 肤色判定（硬阈值，0–1 归一化）

```
r > 0.371 && g > 0.156 && b > 0.078
&& r > b && r > g
&& |r − g| > 0.059
&& (max − min) > 0.059
```

`nonskin_blur_scale = 0` → **非肤区域一点都不磨**，输出原图，没有渐变带。

### 3.7 眼保护

只有 `eye`，**没有 mouth**。公式：

```
out = C + (res − C) · (1 − eye)
```

**我们的实现多画了一个嘴巴椭圆**（`beauty_core.cpp:1453-1458`），而 SDK 把嘴唇当皮肤磨。这是 100 档唇区 +25.5 残差的最可能根因。

### 3.8 LUT（8×8×64）

```
dim = 64, raw = 8, col = 8
blueColor = b × 63
quad.y = floor(floor(blueColor) / 8)
quad.x = floor(blueColor) − quad.y × 8
```

一张 512×512 纹理，64³ 三维查找表摊平。**内容未取到**，只影响颜色/通透感，不影响磨皮几何。

### 3.9 已知的无效项

- `use_stf2 = 1` 在当前 build 里**等于没开**：`stf2 = (st1 − st3) × intensity`，而 `real_main` 是恒等函数 → `st1 == st3` → `stf2 ≡ 0`。可以完全忽略。
- `blur2` 永远取 `tex_surfaceblur2`，与 `use_stf2` 无关。

## 8. 坑（踩过的，别再踩）

1. **不要再回到拟合路线**。等效参数能对上平均值，对不上结构。
2. **不要用 `BEAUTY_BLUR_SAT` 追 100 档**。那是 legacy 的补偿手段，天花板已经撞到。
3. **`r1 < r2` 会把中频削穿**（旧结构下的结论，新结构不适用，但说明半径不对称很危险）。
4. **固定阈值在原理上做不到「平坦区磨、纹理区保」**。必须用 `Δg²·yFactor` 的抛物线权重。
5. **`boxRgbRoi` 内部只外扩 `r×iters+2`**，大半径时调用方必须再外扩 `max(r×it)`。
6. **ROI 起点下对齐到 32**，否则浮点累加相位不同，会差出灰阶。
7. **EMA 默认必须 = 1.0**，改了会拖影。
8. **PowerShell 的 `ConvertFrom-Json` 会被中文区域名打断**，解析 `s3_eval.py` 输出用 `[regex]::Match`。
9. **PowerShell 处理中文路径会乱码**，用 `read` 工具或 Python `os.listdir`。
10. **第三方「OBS美颜摄像头」源不能删**。
11. **版本纪律**：面板/滤镜同号，改动同步 CHANGELOG / INDEX / C 文档 / HANDOVER。
12. **`installer-stage` 仍是 3.1.7**，打包前必须同步。
