## 一、本周结论

1. **预览冻结不是我们的滤镜卡死**，是两路 dshow 抢同一个摄像头导致采集断粮。证据链完整（dump + PDB + 时间线），已排除图形线程分支。
2. **3.1.13 修订版三条遗留全部关闭**：收效行、面板/滤镜同号、装机清单自查。
3. **磨皮核按第三方源码结构重写完成（surface3，P0）**，默认关闭，只走 `BEAUTY_SMOOTH_MODEL=surface3`。
4. **真机 1080p 拟合达标**：50/100 档四区域×三频带加权分 **1.55**（旧核 10.48），100 档过磨问题基本消除。
5. **face_src 640×394 曲线反而退步**（RMSE 4.01 vs 旧核 2.39），根因是小脸归一化后半径被压到 1~3、档位区分度不足。**这是 surface3 不能翻默认的直接原因**。

## 四、磨皮对齐：surface3 三层模型（P0）

### 4.1 结构（来自第三方 GLSL 反编译）

```
I    = min(1, 1.4286·t)
e    = (I < 0.6) ? 0.3 : (I − 0.3)
even = C − b1 + b2
even = mix(even, b2, skin·e)
res  = C + (even − C)·I
out  = C + (res − C)·(1 − eye)
```

`b1/b2` 是**表面模糊**（带颜色阈值），不是普通盒式。阈值负责保高对比细纹理——这正是旧两层模型在 100 档过磨的根因。

### 4.2 本轮拟合出的五条硬结论

| # | 结论 | 反例/依据 |
|---|---|---|
| 1 | `b1/b2` 必须**同尺度**（`r1 ≈ r2`） | `r1=2/r2=8` 时 50 档中频 63.2 vs SDK 80.7，中频被削穿 |
| 2 | 半径必须**按人脸宽度归一化** | 参考脸宽 532 px；face_src 脸 111 px → 等效半径 1/4.8 |
| 3 | 表面模糊阈值默认 **thr = 0（纯盒式）** | thr=1 就让 50 档细纹理 78%→105%；真机 thr=2 直接 99.3%（等于关掉磨皮） |
| 4 | `e` 实测近似随档位**线性**（0.45→0.60） | SDK 原分段式仅保留为对照开关（`s3EOff>0`） |
| 5 | 半径随档位**线性增长**（`r0=2 → r100=14`） | 固定半径两头不可兼得 |

### 4.3 当前默认参数（已落代码，未翻默认）

```
s3R0=2, s3R1=s3R2=14, s3It1=s3It2=1
s3Thr1=s3Thr2=0
s3K=1.4286, s3ELo=0.45, s3EHi=0.60, s3EOff=0
scale = fw / 532   （fw = 本帧最大脸宽，夹在 0.20~2.50）
```

## 五、风险与遗留

| 级别 | 事项 | 影响 |
|---|---|---|
| **P0** | face_src 曲线 RMSE 4.01 > legacy 2.39 | surface3 不能翻默认 |
| **P0** | 参考脸宽 532 是 **cv2 YuNet** 读数，我们引擎自己读 ~505 | 真机 r100 实际落到 13 而非 14，系统偏差约 5% |
| **P0** | 缺 `tex_surfaceblur1/2` 的**生成 shader** | 100 档能否保住细纹理无法确认，只能近似 |
| **P0** | 缺面板 0/25/50/75/100 → uniform 值表 | 档位映射只能反解，无法验证 |
| P1 | 缺 SDK 掩码/关键点导出 | per-region 残差（100 档唇 +25.5 / 脸颊 −19.8 / 眼区 −14.6）无法判断是算法差还是掩码覆盖差 |
| P1 | 缺真实 PNG 无损素材 | 真机帧是 JPEG 截图，8×8 块效应污染细频带，数字只能作参考 |
| P1 | 100 档唇区过磨 | 可能要给 surface3 单独做「只护眼不护嘴」的 protect 缓冲（涉及 async swap 5 处） |
| P2 | 真机 45~50 ms / 19.4 fps 反常 | 疑热降频，未复查；`BEAUTY_PROFILE=1` 可拆三段 |
| P2 | 面板角标修复未装机；`installer-stage` 仍是 3.1.7 | 打包会带错版本 |
