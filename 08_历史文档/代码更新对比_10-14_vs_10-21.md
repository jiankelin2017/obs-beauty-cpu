## 一、插件本体（进安装包的两个 DLL）

### 1. `obs-plugin-build\src\obs-nama-beauty.cpp`  +41 / −17

**(a) 日志降噪：热路径从 LOG_INFO 降到 LOG_DEBUG**

新增统一入口 `nama_tracef(int level, const char *step)`，拆成两个包装：

- `nama_reset_trace()` → `LOG_INFO`，只留给两个「恢复默认」按钮（低频、用户主动触发）
- `nama_reset_trace_dbg()` → `LOG_DEBUG`，给 update / 渲染刷新这类热路径

5 处热路径调用全部改为 `_dbg`：
`update: enter`、`update: settings read`、`update: return`、`render: applying params to SDK`、`render: applied`

> 代码注释给的理由：滤镜属性页拖一次滑块会触发多次 `obs_source_update`，每次 update 又产生一次渲染线程 flush；若按 INFO 落盘，正常录制时日志会被刷屏，UI 线程和渲染线程都要多做无谓的写盘 I/O。

**(b) 暂存面回读优化（`memcpy` 整块拷贝）**

```cpp
if (linesize == row) {
    memcpy(f->buf_in, ptr, row * cy);   // 紧凑行距，一次拷完
} else {
    for (uint32_t y = 0; y < cy; y++)   // 非紧凑才逐行
        memcpy(f->buf_in + (size_t)y * row, ptr + (size_t)y * linesize, row);
}
```
D3D11 暂存面通常是紧凑行距，逐行循环是多余的函数调用开销。

**(c) 回读失败判断前移（画面正确性修复）**

`if (!got) { obs_source_skip_video_filter(f->context); return; }` 从「SDK 渲染之后、上传纹理之前」**挪到 SDK 调用之前**。

> 原位置意味着：本帧 CPU 回读失败时，仍会拿**上一帧的旧 `buf_in`** 喂给 SDK —— 既有画面问题（SDK 会照着旧帧做人脸跟踪），又白跑一次 SDK 渲染。

### 2. `obs-plugin-build\src\obs-nama-beauty-ui.cpp`  +23 / −0（纯新增）

**(a) `build_form` 空指针防护**

- `obs_source_properties()` 返回 `NULL`（滤镜插件未加载/被停用）时直接 `return`，不再 `obs_properties_first(NULL)` 崩溃
- `obs_source_get_settings()` 返回 `NULL` 时 `obs_properties_destroy(props)` 后 `return`

**(b) `ensure_menu()` 轮询兜底**

新增 `static int g_menu_attempts`；超过 240 次（250 ms × 240 = 60 s）就 `g_timer->stop()` 并打一条 `LOG_WARNING`「主窗口 60 秒内未就绪，停止轮询」，不再永远每 250 ms 唤醒一次。

> 对应 DLL 层证据：UI DLL 体积 193,024 → 193,536 B，正是这段新增代码；两个 DLL 的字符串表**完全一致**（没有新增/删除任何文案），说明改动全在逻辑层。

## 二、校验脚本（跟进参数表删减）

### 3. `verify_param_parity.py`  +11 / −1

- `CPP_ROW` 正则分组补上 `FILTER`：`NAMA_G_(BEAUTY|SHAPE|FILTER)`
  > 原来只写 `BEAUTY|SHAPE`，`filter_level` 被静默跳过 —— 滤镜与面板即使不一致也判「通过」，恰好漏掉最该校验的一项。
- 解析面板 `DEFAULTS` 时，若 `filter_level` 不在 `BEAUTY/SHAPE` 数组里，就单独补一条 `{key: filter_level, group: FILTER, dflt: ...}`，否则这一项又会绕过校验。

### 4. `beauty_panel\index.html`  +6 / −3

自检期望值对齐当前参数表：条目数 `31 → 26`、美颜 `11 → 9`、美型 `20 → 17`。
> 旧值是删除 `tooth_whiten`、`delspot_level` 以及三项弱美型参数之前的，会让面板自检恒为失败。

### 5. `beauty_panel\test_panel.js`  +4 / −3

同上：`11/20/31 → 9/17/26`。

## 结论

这 7 天的改动属于**收口加固**，没有新增功能：

1. **稳定性**：修 2 个隐患 —— properties/settings 为 NULL 时崩溃、顶层菜单轮询无限跑
2. **画面正确性**：修 1 个隐患 —— 回读失败时用旧帧喂 SDK
3. **性能/日志**：热路径日志降噪（INFO→DEBUG）+ 一处整块拷贝优化
4. **校验闭环**：`filter_level` 之前没被一致性校验覆盖，现已补上；面板自检期望值与实际参数表对齐
