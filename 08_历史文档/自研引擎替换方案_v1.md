# 自研美颜引擎替换方案 v1

> 目标：把 `CNamaSDK.dll` / `fuai.dll` / `auth_package.bin` / `*.bundle` 全部移出运行时，
> 换成一套**代码、着色器、模型、LUT 全部自写**的美颜核心。
>
> 编写日期 2026-10-27 · 对应现状：滤镜 3.0.19 / UI 3.0.20
>
> 本文是**规划**，不含实现代码。第 9 节列了三件需要拍板的事。

---

## 0. 「全自研」的边界定义

先把边界钉死，否则后面每个评审都会吵一次。

| 分类 | 内容 | 处置 |
|---|---|---|
| **必须清除** | `CNamaSDK.dll`、`fuai.dll`、`auth_package.bin`、`face_beautification.bundle`、`ai_face_processor_pc.bundle` | 运行时目录里一个字节都不许出现 |
| **必须清除** | 从 bundle 里解出来的 GLSL 文本、LUT 贴图、`face_mask*.png/dat`、`face_warp.json`、`*.tflite` | 不得随包分发；只作算法参考，重写实现 |
| **必须替换** | `NamaEngine`（SDK 驱动层）、`NamaRegion`（fuai 掩码）、`applySharpen`（CPU 锐化） | 新写 |
| **保留** | OBS 插件框架、`obs-nama-beauty-ui.dll` 面板、参数表、构建/打包脚本 | 复用，接口对齐 |
| **允许依赖** | OBS 自身的 `gs_*` 图形 API、libobs、Qt（UI 侧）、Win32、CRT | 宿主 API，不算第三方引擎 |
| **允许的离线工具** | PyTorch / numpy 用于**训练**（产物是权重，不进运行时） | 训练工具链，不是运行时依赖 |

**判据一句话**：发布出去的 `obs-nama-beauty.dll` + 数据目录里，跑起来的每一行代码、每一个字节的权重和贴图，都是我们自己产出的。

关于「算法能不能抄」：数学与算法思路（双边滤波、guided filter、UNet 结构）不受版权保护；**具体写法的代码、着色器文本、贴图、模型权重**受保护。所以做法是「读思路、重写实现、重训权重」，不是「改个变量名搬过来」。这是工程判断，不是法律意见，真要对外发行请让法务过一遍。

## 1. 现状盘点：我们要甩掉什么

| 现状 | 数字 | 换成自研后的预期 |
|---|---|---|
| 运行时体积 | 64 MB（两个 bundle 28 MB + 两个 DLL + 依赖） | **≤ 6 MB**（模型 2–3 MB，其余是代码） |
| 首次初始化 | 1.7–2.0 s（`fuSetup` + 人脸模型 + 美颜道具） | **≤ 100 ms**（只加载 3 个小模型） |
| 1080p 单帧 | 62.9 ms（全开）/ 20.9 ms（全关） | **≤ 8 ms / ≤ 1 ms** |
| 主链路 | GPU → CPU 回读 8.3 MB → SDK → 回传 GPU | **全程 GPU，零全帧回读** |
| 稳定性风险 | 隐藏 GL 窗口 + `wglMakeCurrent` 跨线程互踩 + 全调用 SEH 兜底 + `poisoned_` 状态机 | 这四类风险**整体消失** |
| 参数表达力 | `blur_level` 在 66%→78% 之间饱和，等于开关 | 强度连续可调，50 档就是 50 档 |
| 已知 P0 | 掩码错位时磨皮静默打空；`faces=0` 仍改 8.44% 像素 | 掩码自检 + 硬门控，`faces=0` 零改动 |

顺带说明为什么值得做：现版本 `blur_level` 之所以像开关，是因为 SDK 的核只有 12 个采样点、`lowp` 精度、单通道 G 引导（见 `surfaceblur.fs.glsl` 的 `yFactor` 权重）。这个上限不是调参能突破的 —— 换成自研的可分离保边滤波后，强度曲线是设计出来的，不是被核大小卡住的。

### 2.2 渲染 pass 图

```
上游帧 tex_in (RGBA)
  │
  ├─[V0 缩略]──► 192×256 RGBA ──► 回读 196 KB ──► vision 推理
  │                                                    │
  │                                             皮肤掩码 192×256
  │                                                    │
  │                                            [V1 时序稳定]
  │                                            EMA + 位移补偿 + 自检
  │                                                    ▼
  ├─[R1 掩码投射]◄──────────────────────────── mask tex (R8, 全分辨率)
  │        五官保护由关键点生成的眼/眉/唇多边形叠乘
  │                │
  ├─[R2 保边平滑] 半分辨率 H/V 两趟（joint bilateral / guided）
  │        引导来自全分辨率 luma，避免半分辨率台阶
  │                │
  ├─[R3 磨皮合成] mix(tex_in, blur, m·strength)
  │        + 高频回填（detail 曲线）+ 中频带回升
  │                │
  ├─[R4 美白/红润] 肤色感知提亮（不碰非肤色，硬门控）
  ├─[R5 3D LUT]    滤镜（自有 Hald CLUT，R8G8B8A8 采样）
  ├─[R6 清晰/锐化] unsharp（含全局锐化，0 = 脸外逐字节不变）
  ├─[R7 形变]      网格位移（M3，需要关键点）
  └───────────────────────────────► 输出
```

关键点：**V0 那一趟回读是唯一的 CPU 接触点**。192×256×4 = 196 KB，按 15 fps 算 2.9 MB/s；现在是每帧 8.3 MB × 60 fps = 500 MB/s。这一项就吃掉 62.9 ms 里的大头。

### 2.3 推理运行时（自研）

不引入 ONNX / TFLite / NCNN / OpenCV。自己写一个**只覆盖本工程所需算子**的极小运行时：

| 项 | 设计 |
|---|---|
| 权重格式 | 自有 `.bmn` 容器：magic + version + 张量表 + 权重块 + 量化参数，小端定长，加载即校验 |
| 算子集 | `conv3x3`(dw/pw)、`conv1x1`、`concat`、`add`、`relu/relu6`、`sigmoid`、`bilinear_upsample`、`maxpool`、`softmax`(小图) |
| 核 | 先用 AVX2 fp32，带边界特化；int8 留作 M2 后期的加速项 |
| 线程 | 2–3 个 worker（`std::thread` + 自旋屏障），按 batch 内并行 |
| 内存 | 全部预分配，运行期零 malloc；每实例一份 arena |
| 兜底 | 任一算子越界/校验失败 → 整帧透传 + 记日志，不崩 |

模型规模预算（这是能跑进 3 ms 的关键）：

| 模型 | 输入 | 输出 | 参数量 | 单帧开销 |
|---|---|---|---|---|
| 皮肤分割 | 192×256 | 192×256×1 | ~150 K | 1.5–2.5 ms |
| 关键点 | 112×112 | 106×2 | ~800 K | 2–3 ms |
| 人脸检测 | 256×256 | 框 + 5 点 | ~300 K | 2–3 ms，每 30 帧一次 |

不是每帧都跑检测；分割和关键点按 15 fps 跑、中间帧用位移补偿插值。摊到 60 fps，视觉层 **< 1.5 ms/帧**。

## 3. 五个必须先定的设计点

### 3.1 推理跑在 CPU 还是 GPU

| | CPU + AVX2 | D3D11 Compute Shader |
|---|---|---|
| 工作量 | 基准 | ×2.5（要写 conv 的 HLSL、处理 barrier、调 group 大小） |
| 延迟 | 1.5 ms/帧（摊薄后） | 0.6 ms/帧 |
| 兼容性风险 | 无 | 老核显 / ANGLE 后端要单独测 |
| 调试难度 | 低（可逐层对拍） | 高 |

**建议 CPU 先行**，把 `vision::Backend` 做成接口，M5 之后再决定要不要补 CS 后端。理由：延迟预算够（OBS 60 fps 有 16.6 ms），而调试成本差一个量级。

### 3.2 掩码时序稳定 = 直接修掉 P0

现版本的 P0 是「掩码错位 → `mv≈0` → 磨皮四档全部打空，且没有任何报错」。新设计里把它做成三层：

1. **合理性自检**：掩码覆盖率 / 外接框面积比 / 与上一帧的 IoU 三条同时越界 → 判定失效。
2. **失效即透传**：失效帧整帧不处理并记一次计数，**绝不静默输出半成品**。
3. **位移补偿**：用上一帧人脸框到本帧的平移量 warp 历史掩码，再做 EMA（α 按帧间差自适应，静止人脸 α 大、快速移动 α 小）。

这条做完，「磨皮突然没效果」这类问题从"用户报障"变成"日志里一行 `mask invalid, passthrough`"。

### 3.3 参数与场景兼容（不能破的接口）

现有 11 个滑块的名字和范围**必须原样保留**，否则老场景集合加载后全部归零：

```
blur_level / clarity / color_level / red_level / sharpen /
global_sharp / face_threed / eye_bright / remove_pouch_strength /
remove_nasolabial_folds_strength / delspot_level
+ blur_type / skin_detect / smooth_mode
```

语义映射表（新引擎内部换算，面板刻度不变）：

| 面板项 | 新引擎对应 | 备注 |
|---|---|---|
| `blur_level` 0–100 | 平滑强度 `s` 与半径 `r` 双曲线 | 50 档 = 设计基准，不再是 SDK 饱和点 |
| `blur_type` | 0 高斯 / 1 保边 / 2 弱平滑 | 保真保留三档语义 |
| `skin_detect` | 1 = 只动掩码内；0 = 全帧 | 保持默认 1 |
| `smooth_mode` | 保留/边缘/收敛/朦胧 四条 detail 曲线 | 直接把现有四档推导搬进 GPU |
| `clarity` | 中频带增益 | 现版本实测唯一立体感来源，不要削 |
| `global_sharp` | 掩码外锐化开关 | 0 时脸外逐字节不变，这条是硬指标 |

### 3.4 色彩与精度

- OBS 可能给 sRGB 或 Rec.709、8bit 或 10bit、带 alpha。所有 pass 走 `gs_effect` 并在入口统一按 `gs_get_color_space` 建纹理，避免出现 3.0.x 早期那种偏色。
- 平滑在**线性光**下做（先解 gamma），合成回原空间。SDK 一直是在 gamma 空间做的，这会让新旧观感有系统性差异，需要在 M0 基线里明确记录，别在 M5 才发现。
- 中间纹理一律 `GS_RGBA16F`（半分辨率平滑图可以 `RGBA8`），消掉 `lowp` 量化台阶。

### 3.5 模型与资源分发

```
obs-plugins/64bit/obs-nama-beauty/
├── obs-nama-beauty.dll
└── models/
    ├── skin_seg_v1.bmn        (~0.8 MB)
    ├── landmark_v1.bmn        (~1.9 MB)
    ├── detect_v1.bmn          (~0.7 MB)
    └── manifest.json          版本 + sha256 + 输入尺寸
```

资源外置而不是编进 DLL：模型迭代不用重编二进制，也便于灰度时 A/B 两份模型。`manifest.json` 里带 sha256，加载时校验，防止半截安装。

## 4. 里程碑

单人全职口径。日历按「1 人 + 可并行做数据的助手」估。

### M0 · 基线冻结（3 人日）— **唯一有时效性的一步**

SDK 还在手上的时候，把它的输出固化成回归集。这一步不做，后面所有"对齐/超车"都只能靠肉眼。

```
goldens/
├── flat/     静态帧：不同肤色 / 光照 / 眼镜 / 刘海 / 口罩 / 白衣服 / 木桌背景
├── motion/   运动帧序列：转头、快速进出画、低头、遮脸（含 faces=0 段）
└── params.json   每组的 14 个参数全量快照
```

每组存 `输入.png / SDK 输出.png / 参数.json`。覆盖：磨皮 0/1/25/50/75/100 × `blur_type` 0/1/2，美白/红润/锐化各 3 档，`faces=0` 对照组。

**产出**：`06_离线验证/goldens/` + 一份 `baseline.md`（记录每个组合的细节保留率、闪动、掩码覆盖率）。

### M1 · GPU 渲染层（12–15 人日）

目标：**在还不碰 AI 的前提下**，把磨皮/美白/红润/滤镜/锐化全部搬到 GPU，掩码先用现有的颜色启发式占位。

- 换掉手工 `gs_texrender` + `gs_stagesurface_map` + `gs_texture_set_image`，改用 `obs_source_process_filter_begin` / `_tech_end`。
- 写 R2–R6 五个 pass 的 HLSL + GLSL（`gs_effect` 一份源码编译两个后端）。
- `beauty/gpu/texture_pool`：按尺寸分级复用，运行期零创建。
- `beauty/core/pipeline`：pass 图声明式描述，按开关裁剪不需要的 pass（"全 0 直接透传"要真的零 GPU 工作）。
- 把 `applySharpen` 的双频带策略移植成 `R3/R6` 的 detail 曲线，保持四档 `smooth_mode` 的观感。

**验收**：1080p 全开 ≤ 8 ms；全 0 ≤ 1 ms；背景逐字节不变；M0 基线的"细节保留率"误差在 ±5 个点内。

**风险点**：线性光 vs gamma 空间的合成差异。M1 结束必须给出结论（改还是不改）。

### M2 · 视觉层（25–35 人日，含训练）

分三步，每步独立可验收：

1. **数据与训练脚本**（8–10 d）：分割/关键点的训练与评测脚本进 `tools/train/`（不进运行时）。数据来源：公开人脸数据集 + 自己的采集（合规要过一遍）。
2. **推理运行时**（8–10 d）：`.bmn` 格式、AVX2 算子、逐层对拍工具（`bmn_dump` 与参考实现比对，阈值 1e-5）。
3. **接入与收敛**（8–12 d）：替换占位掩码，调时序稳定，跑 `flicker_probe.py` 对齐闪动指标。

**验收**：皮肤分割在自建测试集 IoU ≥ 0.90；关键点 NME ≤ 0.05（按眼距归一）；掩码闪动 ≤ 3.0.19 的 60%；`faces=0` 变化像素 **= 0**。

**这是整个项目唯一的高风险里程碑**。若分割质量卡住，退路是「自研小模型 + 肤色先验 + 时域投票」的混合方案，仍属自研。

### M3 · 形变与立体（10–15 人日）

- `R7` 网格形变：瘦脸、大眼、鼻梁。需要关键点 + 网格插值，onset 用关键点三角化。
- `face_threed`：用深度先验做提亮/阴影，替代 SDK 的 `face_threed`。
- 这三项现有版本已接、效果可用，属"不能回退"项。

**验收**：与 M0 基线同参数下的视觉对照，形变不产生脸部撕裂/背景位移。

### M4 · 切割与灰度（4–6 人日）

- 运行时目录删除 SDK 全部文件；`NamaEngine` / `NamaRegion` 整体移入 `07_历史文档/sdk-retired/`（留档，不编译）。
- 双插件并存：新插件用独立 filter id `nama_beauty_filter_v2`，面板提供「一键迁移」把老场景的参数抄过去。
- 灰度：整合包内保留 3.0.20 回滚件，`ROLLBACK.bat` 可用。

**验收**：干净机器装包 → 启动 → 加滤镜 → 全功能可用；进程模块列表里搜不到 `CNamaSDK` / `fuai`。

### M5 · 收敛与交付（8–10 人日）

- 跑全量指标 + 主观盲测（≥ 5 人，AB 双盲，记录偏好率）。
- 性能矩阵：720p/1080p/4K × 集显/独显。
- 打包、文档、验收报告。

### 合计

| | 人日 | 累积 |
|---|---|---|
| M0 | 3 | 3 |
| M1 | 12–15 | 15–18 |
| M2 | 25–35 | 40–53 |
| M3 | 10–15 | 50–68 |
| M4 | 4–6 | 54–74 |
| M5 | 8–10 | 62–84 |

**约 3–4 个月**（单人）。若 M2 的模型训练能并行找人做，可压到 2.5 个月。

## 8. 与现有问题的对应关系

这次替换顺带清掉待办里的四条：

| 现待办 | 在新架构里怎么消失 |
|---|---|
| P0 性能悬崖（磨皮+锐化 69 ms） | 全部在 GPU，且 `applySharpen` 的整帧无条件双频带不再存在 |
| P0 肤色掩码无自检兜底 | §3.2 的三层设计 + 硬门控 |
| P2 `kTexLo/kTexHi` 噪声自适应失效 | detail 曲线改成按局部方差自适应，不再依赖固定阈值 |
| P3 语义区域偶发失败（37/60） | 自研运行时无外部依赖，失败率由我们自己的错误处理决定，且失败=透传 |

## 9. 需要拍板的三件事

**① 推理层跑在哪？**
建议 CPU + AVX2 先行（工作量最小、可逐层对拍），留 `vision::Backend` 接口给后续 CS 后端。若你要求"必须 GPU 才算自研"，M1/M2 工作量各加约 40%。

**② 训练工具算不算"第三方"？**
建议允许离线用 PyTorch 训练，产物只有 `.bmn` 权重。若连训练也必须自写，那需要自研反向传播框架，加 4–6 周且没有质量收益 —— 不建议。

**③ 老的观感要不要保？**
新引擎的磨皮曲线是重新设计的，默认肯定和 3.0.19 不一样（会更好，但用户会觉得"变了"）。建议同时提供「经典」预设，用 M0 基线拟合旧参数，默认走新版。
